# 产品需求

## 定位

旅行助手是使用虚构供给、虚构订单和模拟价格的求职演示项目。网站对知道链接的人开放登录页，但只允许管理员预先授权的账号进入；不开放自助注册，不接入真实出票、付款、酒店库存、租车库存或退款。页面和接口应清楚表明模拟属性。

## 旅客能力

- 登录后查看本人行程、会话、历史动作和模拟平台政策；跨账号数据不可读取或修改。
- 查询虚构航班、酒店和租车候选；航班两端显示当地日期、时间和时区偏移。
- 用多轮对话提出旅行需求，获得有数据库依据的回答与可核查的经典地点推荐。实时联网检索无法核实时说明边界，不编造时效信息。
- 支持九类模拟交易：机票预订／改签／取消，酒店预订／改期／取消，租车预订／改期／取消。
- 每笔交易先生成一张独立待确认卡。卡片展示对象、变更前后、模拟金额、当地时间、规则及有效期；只有所属旅客逐张确认后，服务端才修改对应订单。拒绝、过期、重复确认或仅在对话中说“同意”均不写订单。
- 刷新和切换会话后可恢复已保存的对话与卡片；未完成或失败的轮次可核对状态，不应产生重复订单。

## 管理和运行要求

- 管理员通过受控命令创建、轮换、停用授权账号。初始样本账号在公网环境停用；密码和第三方密钥只放私有配置。
- 公网只开放 HTTPS／HTTP 代理与必要的 SSH；应用和 PostgreSQL 不直接映射公网端口。
- 模型和搜索调用有频率、并发与用量记录；服务商余额、限流或故障时明确提示，不能声称已完成实时查询。
- 迁移与虚构批次导入仅在新空库中显式运行。重启或部署代码不得重建批次，也不得修改既有订单。
- 正式数据库每日加密后异地备份；恢复私钥独立保管，定期核对备份状态，并通过全新隔离卷演练恢复。

已知限制：一句话同时询问“机票、酒店和租车”时，现有对话筛选可能只回答机票；独立“我的行程”页面仍可列出三类订单。虚构航班和报价不能用于实际出行决策。
