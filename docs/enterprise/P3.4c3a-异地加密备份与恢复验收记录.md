## 原始环境和备份

- 开工复核 `travel-cloud`：数据库健康，应用与公网代理已停止；数据库、备份、批次清单和两份证书相关卷标签与项目一致，数据库和应用没有宿主机端口映射。2026-10-27 批次、14 版迁移、33,121 条虚构航班、4 个旅客、4 个会话、12 条服务商用量事件均可读取。恢复演练项目及数据卷原先不存在。现有两份同机 PostgreSQL 备份的格式、权限和 SHA256 均通过检查。
- 使用 PostgreSQL 17 `pg_dump -Fc` 新建一份**不覆盖旧文件**的备份；`pg_restore -l`、`PGDMP` 头、文件权限和哈希通过。数据库归档 705,873 字节，SHA256 `c73ba12e81201f1010fead3603aed1d3f2e4449b2744c71a8f79558deee95d38`。归档、批次清单与不含凭证的源库摘要装成 716,800 字节备份包，SHA256 `17665b3410bc7405020d268e870dcd3562e8c39a51f7a85f1ec8783bc9466b16`。备份前后源库摘要一致。
- 本机从 [age 官方 v1.3.2 发布页](https://github.com/FiloSottile/age/releases/tag/v1.3.2)下载 Windows 工具，并用 GitHub 官方发布接口给出的 SHA256 `f48d8f8f9ebe903ab5027ed067652f2cc1db94bc206976430133b905dcd8e8c7` 核对。生成单独恢复密钥对；私钥原件保存在旅客本机受限、Git 忽略的目录，公开接收密钥用于加密。旅客已回复确认将私钥的第二份副本存入自己的密码管理器；本轮未读取密码管理器内容，也未做该副本的独立解密测试。
- 经已核验主机身份的 SSH 通道，将服务器备份包**直接加密写入本机**，没有本机明文备份文件。密文为 717,160 字节，SHA256 `f2866bc1a5ec926d9c8689c1171d10722852bba4ebbda572788d576a89b19165`；传输流的明文字节数和 SHA256 与服务器源包相同。私钥和密文仅对本机当前用户及工作台运行身份授权读取；文件位于 Git 忽略目录。

## 从本机密文恢复

- 使用**该本机密文**与本机私钥实际解密，在内存核对备份包、数据库归档、批次清单和元数据哈希；之后将核对后的内容送到云端新建的私有暂存目录。没有使用原服务器备份卷直接充当恢复输入。
- 在新的 `travel-cloud-restore-p34c3a` 项目创建**全新数据库卷和批次清单卷**；数据库恢复前公共表数为 0。恢复网络标记为 Docker 内部网络，不发布宿主机端口。使用同主版本 PostgreSQL，一次 `pg_restore --exit-on-error --no-owner --no-privileges` 成功；恢复的批次日、14 版迁移、供给、订单、旅客、会话、轮次、待确认动作、审计和服务商用量摘要与源备份逐项一致。批次清单 SHA256 同样一致。
- 隔离环境使用**新数据库密码和新 JWT 密钥**，模型与搜索只配置不可调用的恢复专用占位值，且内部网络无公网出口。只启动私有应用并核对 `/ready` 为 200；两名已授权账号可登录、读取本人资料和行程，跨账号会话读取为 404。演练账户验证在恢复后的副本中产生一条新测试会话，发生于源库摘要比较之后；原云端库没有这些写入。
- 收尾前再次比较原云端数据库及清单，与快照时完全一致。隔离应用和数据库均已停止，**新恢复卷保留**；临时解密文件及云端暂存目录已清理。本机加密副本和原服务器私有备份均保留。原公网应用和代理仍关闭，仅原数据库健康运行。隔离容器 `OOMKilled=false`，本次启动以来内核 OOM 事件为 0。备份、加密传输、解密转送和隔离恢复命令分别约用 10、2、4、21 秒；这只是本轮命令耗时，不是任何灾难场景的恢复时间承诺。

## 结论和后续边界

**通过一次手动服务器外恢复演练**：旅客本机有一份可实际解密、可在新卷恢复的加密数据库与批次清单副本；私钥第二份副本按旅客反馈已存入密码管理器。恢复时原数据卷未重置或覆盖，公网未重新开启，未调用 DeepSeek 或联网搜索，也未合并或推送 Git。

这还不等于持续灾难恢复：每日自动备份、不同地域私有 OSS 留存、七份日保留和密码管理器副本的独立恢复仍未验收，留待 P3.4c3c。九类交易与多轮隔离验收留待 P3.4c3b；真实展示网络与云控制台防火墙复核也未完成。
