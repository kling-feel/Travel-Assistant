现行导入命令 `--apply --reset-demo --backup` 只验证备份是 PostgreSQL 自定义格式的文件头，并拒绝非默认账号或待确认动作；它仍会清空旧库业务历史。因此**不在旧库执行该命令**。日期不能只改 `demo_state`，也不能在每次 API 启动时平移已确认订单。

## 新旧批次隔离设计

1. **旧批次**：保留原 Compose 项目和数据卷，不修改其 `demo_state`、订单、会话、动作或审计。正式切换前另存数据库自定义格式备份，检查目录可读，并在独立临时库演练恢复。不能仅凭备份文件存在判断可恢复，也不能运行 `down -v` 删除旧卷。
2. **新批次**：建议 Compose 项目名 `travel-date-next`，候选数据库端口 5436、隔离 API 端口 8015；Compose 命名卷预期为 `travel-date-next_travel_pgdata`。这些端口在 P3.3a 核对时未监听，但 P3.3b 开工前须再次查占用，并以 Compose 项目标签和实际挂载信息确认卷名，不能靠字符串推断。新库仅从可交付虚构样本迁移、导入和生成初始订单，不复制旧批次旅客记录。
3. **应用连接**：P3.3b 在启动独立 API 前明确设置新库连接端口和 API 端口，并只打印目标主机类别、端口与数据库名称，不打印连接串密码。若 `DATABASE_URL` 有值，它优先于 `POSTGRES_PORT`，必须核对最终有效配置，避免误连旧库。
4. **登录隔离**：两个批次会复用默认旅客 ID。若共用 `JWT_SECRET_KEY`，旧批次令牌可能在新批次仍有效；新批次须使用独立的随机签名密钥和批次专属演示密码，保存在 Git 忽略的本机配置中。切换时清除旧标签页登录态并要求重新登录；旧会话 ID 在新库不能恢复。新批次 API 必须对旧令牌返回 401。
5. **切换与回退**：P3.3b 只在 8015 验收，不接管 8000。P3.3c 经旅客确认后才安排停止当前演示、核对旧库备份与卷、切换 8000 指向新批次，再做登录、行程、候选和确认卡验收；失败时停止新 API 并把 8000 恢复到旧库配置。保留新旧两套卷，任何清理另行确认。

## P3.3b 操作手册草案与检查点

1. **启动前只读核对**：在可运行 Docker 的 PowerShell 中确认 Docker 引擎、当前 Compose 项目、旧卷实际名称及挂载、新项目名是否未占用，5433／5436 和 8000／8015 的实际监听状态。读取旧库状态时使用只读事务，记录演示日、订单状态计数、待确认动作、额外账号、会话、审计与 13 个迁移版本；不显示密码、旅客消息正文或令牌。
2. **旧数据保存**：在任何新批次写入或后续切换之前，给旧库生成带时间标记的自定义格式备份，保存在 Git 忽略的 `data/generated/`，检查 `PGDMP` 文件头和 `pg_restore -l` 目录；在临时隔离库完成恢复演练并比对关键计数。旧容器和卷保持原样。
3. **建立新库**：以独立 Compose 项目和实际确认的端口创建新卷，只对新库运行 13 个迁移与图检查点初始化。新库导入前也保留可恢复的空库备份；导入预览必须显示目标库标识、目标日期、预计账号和业务记录变化，再执行显式写入。
4. **数据核验**：比较样本哈希、115 座机场、33,121 班航班、618 条可售航线、窗口内报价数量、跨时区当地到达日、酒店两晚覆盖、租车产品日期、初始订单与政策版本；相同源样本和目标日期两次构建应得到相同业务数据。新旧库关键计数与旧库备份前后哈希分别记录；不把新批次记录合并进旧库。
5. **隔离 API 验收**：使用独立令牌密钥和演示密码启动 8015 服务，验证旧令牌 401、新账号登录、查询及九类提案确认边界；API／数据库重启后会话与确认卡恢复。只有完整验收通过才起草 P3.3c 正式切换计划。

## 风险与停止条件

| 风险 | 拦截方式 |
| --- | --- |
| 连接串覆盖端口导致误写旧库 | 写入前由进程打印脱敏后的有效目标标识，并与独立 Compose 标签、端口和空库状态三方核对；不一致立即停止 |
| 两批次共用 JWT 密钥造成旧令牌跨库有效 | 独立签名密钥、旧令牌 401 测试和切换时清除浏览器登录态 |
| 卷名或端口冲突 | 使用显式项目名，执行前核对实际卷标签、挂载及端口；冲突时重新选择，不覆盖旧卷 |
| 备份不可恢复 | 检查自定义格式目录并在独立临时库实际恢复、核对关键计数；失败不得切换 |
| 虚构时间窗或订单错位 | 以目标日重复构建和两日期离线样本、产品覆盖、真实对话交易卡验收；任何不一致停止 |
| 切换期间仍有用户操作 | 事先安排停止窗口、保留旧 API／卷回退路径；未经旅客确认不切换 8000 |

P3.3a 未执行数据库迁移、导入、备份、恢复或服务启停。旧库实际状态、卷名及目标端口的运行态可用性留给 P3.3b 开工时核对，不作为已通过的验收结论。
