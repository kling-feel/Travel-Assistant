## 启动门槛与备份

- 开工时 `travel-cloud` 只有健康数据库；批次日 2026-10-27、数据库项目标签与独立数据卷相符。初始化后备份仍可列目录，SHA256 与 P3.4c2e 记录一致。
- 在开放网站前另建一份**不覆盖旧文件**的数据库备份：PostgreSQL 自定义格式，`pg_restore -l` 可读，权限 `0600`，689,053 字节，SHA256 `729f65c2525864de9c5c1aac2813fa6d393012d11970a5be4184bd9895d5dd8a`。数据库重启前又复核一次格式、权限和哈希。两份备份目前都在同一台服务器；异地恢复尚未验收。
- 先只启内部应用：`/health`、`/ready`、`/app` 与页面脚本返回 200；内部 `/docs` 为 404，匿名 `/me` 为 401。应用与数据库均无宿主机端口映射。此时数据库约 93 MiB、应用约 137 MiB；可用内存约 950 MiB，未见 OOM。

## 授权、订单边界与公网

- 停用的演示账号与不存在的账号均返回相同 401；`portfolio_owner` 和 `interviewer` 均可登录并读取本人 `/me`、行程。跨账号读取会话及另一账号的待确认卡均为 404。生成过一张酒店待确认卡，确认前订单未变，随后放弃，订单仍未变。对不存在账号连续八次错误登录为 401，第九次为 429，另一授权账号仍可正常登录。
- 根域与 `www` 的 DNS 解析分别经服务器默认解析器、Google 和 Cloudflare 公共解析器核对，均指向已购实例。代理只发布宿主机 80／443；主机监听记录为 22／80／443，应用 8000 和数据库 5432 没有宿主机监听或 Docker 发布映射。主机 `ufw` 未启用，阿里云控制台防火墙规则本轮未直接读取；公网 80／443 的证书挑战与页面访问实际成功。
- Caddy 为根域和 `www` 成功取得受信证书；根域证书检查时有效至 2027-01-24。`https://adzyforever.com/app` 与页面脚本返回 200，`http://` 跳转 HTTPS 为 308，`https://www` 跳转根域为 301；主页面具备 HSTS、CSP 等响应头。公网 `/docs`、`/redoc`、`/openapi.json`、`/health`、`/ready` 均为 404，匿名 `/me` 为 401。
- 工作台网络对原始 TCP 探测使用 `198.18.0.1` 代理，导致“8000 可以建立 TCP 连接”的初次判断是假阳性：对该端口的实际 HTTP 请求未收到响应，云主机也没有 8000／5432 监听或映射。发现时已先停止公网代理、核对原因后才恢复测试。**本轮没有获得独立于工作台代理的公网 TCP 端口扫描结果**；后续可在面试实际网络或阿里云防火墙控制台复核。

## 页面、真实服务与重启

- 真实浏览器在受信 HTTPS 下用专用授权账号登录成功；能读取本人对话与行程页面，刷新后自动恢复登录及同一条会话答复，退出后回到登录页。本机仅为这次浏览器验收临时复制账号文件到 Git 忽略目录，退出后已删除；没有将密码放入终端输出、聊天或跟踪文件。375 和 338 像素宽度下，登录页与授权工作台无横向溢出，导航和行程信息可读。该账号没有有效初始订单，因此本轮页面**没有重新目视验证已取消订单样式**；此前的独立页面验收仍为该功能依据。
- 通过受信 HTTPS 做四轮真实云端对话：有效行程、虚构机票取消政策、上海至伦敦最近航班日期、伦敦文化地点。四轮均返回 200，未生成交易动作；这四轮的用量接口记录模型成功事件 **增加 5 次**、阿里云搜索成功事件 **增加 1 次**。伦敦搜索未找到可核实的新地点资料，答复明确回退人工核查目录。随后追加上海、北京两轮定向推荐：上海博物馆得到联网检索支持；北京未能核实新资料，明确回退。数据库最终只读汇总为**模型成功 9 次、搜索成功 3 次、待确认卡 0 张**；不能把阿里云“调用成功”解释成每个城市都已被实时来源证实。实际费用以服务商账单为准。
- 最近容器日志未发现已知账号密码、模型／搜索密钥、数据库／JWT 密钥或 Bearer 头。分别重启应用、代理和数据库后，三服务恢复健康，原受信证书继续可用，授权登录、2026-10-27 批次和已保存答复均保持一致。最终运行测量为可用内存约 945 MiB、根盘可用约 33 GiB，数据库约 22 MiB、应用约 119 MiB、代理约 12 MiB；三个容器 `OOMKilled=false`、内核 OOM 事件 0。该数据说明**本轮短时负载**可运行，不代表长期并发容量已经证明。
