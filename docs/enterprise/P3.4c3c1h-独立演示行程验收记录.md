## 执行与隔离证据

1. 云端只读供给核对显示，在演示窗口内有三班可连贯搭配伦敦酒店和租车的上海→伦敦直达航班；旅客选最近的 11 月 1 日组合。确认前，机票、酒店、租车模拟报价分别为 ¥6,585、两晚 ¥330、两天 ¥190。
2. 写入前创建新的 PostgreSQL 自定义格式备份，校验归档目录，再将备份加密保存到旅客本机 Git 忽略目录；本机使用恢复身份实际解密并验证归档内部哈希。恢复身份的独立副本由旅客保存在密码管理器中。创建独立授权展示账号后，公网页面登录成功、行程为空、读取其他账号会话返回 404。
3. 第一张机票卡未及时操作而自然过期，订单未变；重新查询当前候选、报价和版本后，选定同班次生成新卡。旅客亲自确认新机票卡，服务端核对为 1 笔已确认机票、酒店和租车仍为 0。
4. 同会话先只读查询盖特威克机场附近酒店，零卡；选定两晚标准间生成单张酒店卡，未确认前订单未变。旅客亲自确认后，服务端核对机票／酒店／租车为 1／1／0。
5. 同会话先只读查询机场车辆，零卡；选定经济型车与明确的取还车钟点生成单张租车卡，未确认前订单未变。旅客亲自确认后，三类订单各 1 笔、状态均为已确认，订单标识互不重复。API 交叉核对两端航班当地时间、酒店日期、租车两天计费和三笔金额。
6. “现在有什么已确认的有效行程？请按时间列出全部”正常对话返回三笔及三条归属正确的订单依据，零新卡、订单不变。行程页面和 API 均列出三笔。
7. 写入后再次做在线 PostgreSQL 自定义格式备份、归档目录校验、服务器外加密和本机实际解密／内部哈希核对。从前后两份归档分别抽取原机票与酒店订单的数据行，原有 2 笔机票及 2 笔酒店记录逐行一致；新增订单各 1 笔。云端总数为机票／酒店／租车 3／3／1，供给仍为 33,121 班航班、原五个卷及 2026-10-27 演示批次。
