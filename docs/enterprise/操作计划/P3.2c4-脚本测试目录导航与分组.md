# P3.2c4：脚本与测试目录导航、分组操作计划

> 2026-10-24 制定｜状态：已获确认并执行。承接已完成的 [P3.2c3b 助手与旅客 API 归位](P3.2c3b-助手与旅客API归位.md)；结果写入[当前进度](../当前进度.md)。

## 1. 目标与取舍

当前 `scripts/` 有 23 个 Python 入口和现行用途索引，`tests/` 有 38 个 `test_*.py` 与 1 个页面验收辅助文件。根目录的应用代码已归入 `travel_assistant/`，但测试仍按阶段编号平铺。把测试按职责分组，并让脚本和测试的日常入口在 README 中一眼可见。

`scripts/` 中多项命令已写入项目 README，且有些会迁移、重置数据库或产生模型费用。本步**保留这 23 个脚本的现有文件位置和调用命令**，只改导航和准确性说明；不为了目录整齐给危险命令新增别名。`tests/` 按功能移动测试文件，不改变测试断言、固定模型、内存数据库或运行时业务代码。

## 2. 计划分组与执行顺序

1. 重读《产品需求》《软件架构》《当前进度》与本计划，核对 `64e1990` 所在功能分支、干净工作区。列出 38 项测试文件、跨测试文件的 8 处导入、页面辅助文件的 1 处导入，以及 README 中公开的 17 个脚本路径；记录完整测试 **230 项**、31 条路由、18 张表和 13 个迁移版本的基线。
2. 在 `tests/` 下建立 `business/`、`dialogue/`、`recommendations/`、`interface/` 四组，并加入必要的包标记以维持 `python -m unittest discover -s tests -p 'test_*.py'` 递归发现。拟把 10 个订单／产品／数据测试放入 `business/`，17 个对话／提案／记忆／流式测试放入 `dialogue/`，7 个地点／推荐测试放入 `recommendations/`，4 个页面／展示／计量测试放入 `interface/`。移动前逐项核对文件清单，不凭文件名前缀机械分类。
3. 将只为页面验收提供替身应用的 `tests/p31_preview_server.py` 放到 `tests/support/`；更新跨测试文件的导入。只修正包路径，不移动测试类、共享替身或测试方法；逐文件对比移动前后，防止把测试发现数的变化误认为成功。
4. 新增 `tests/README.md`，用职责、常用发现命令和数据边界解释四组测试；更新 `scripts/README.md` 的日常／数据库写入／可能付费导航，以及根 README 的当前目录图。历史计划、验收与进度文档全文保留，旧阶段命令作为历史记录；当前可执行命令必须指向实际文件。
5. 运行每组测试及完整发现命令，核对测试数量、身份隔离、九类交易确认、推荐、流式交互和页面覆盖没有减少；再查项目根外导入、页面入口、两日期离线样本、Python 编译、页面脚本语法、依赖、README 的脚本路径及本地 Markdown 链接。审查暂存文件、凭证形态和公开文字后，仅提交当前本地功能分支，结果同步《当前进度》。

## 3. 停止条件与边界

- 若分组后测试发现少于 230 项、出现重复执行、跨文件导入失效或需要改业务代码，先在本步修复；不得以减少测试换取通过。若必须扩大范围，修订计划并重新确认。
- 不执行数据库迁移／导入／重置，不运行会写数据库的专项脚本，不调用付费模型或搜索，不操作 8000 页面。`.env`、本机配置、备份和原始 SQLite 不进入 Git。
- `main` 合并与 GitHub 同步仍属 G-17，需另行计划和确认。P3.2d 再整理历史文档导航，本步不删除历史内容。
