# P3.2a：旧实现剥离与本机数据归位操作计划

> 2026-10-24 制定｜状态：旅客已确认，本地功能分支实施。实施顺序服从[P3.2 总路线](P3.2-代码清理与目录重组分步路线.md)；实施结果见[当前进度](../当前进度.md)。

## 1. 本步范围

目标是让当前运行入口只对应一套旅行助手实现，移除明确停用的旧图和旧 API，同时把两份本机原始虚构数据从仓库根目录移到 `data/source/`。本步不做整包重命名、历史文档归档、旧小样本清理、正式库重建或部署。

盘点发现：`api/routers.py` 只注册 `api/travel.py`，其对话入口只引用 `graph_chat/controlled.py`。旧 `api/graph_api/` 指向 `graph_chat/finally_graph.py`；旧 `api/system_mgt/` 依赖 `db/system_mgt/` 与 `db/dao.py`，但两组均未注册。旧 `graph_chat` 辅助模块再依赖 `tools/` 中的 SQLite 写工具和 Tavily 适配器。例外是 `tools/retriever_vector.py` 仍被一项政策测试引用；先用当前 `services/policy_catalog.py` 和公开政策表述覆盖该断言，再移除旧工具，不能删掉测试价值。

## 2. 确认后的具体操作

1. 重读三份核心文档、此计划和 G-16 结果，核对干净的 `main`、远端引用、8000／5433 状态；从已同步主线建立本地功能分支。记录当前已注册路由、导入关系、228 项自动化、两日期样本、前端脚本与依赖状态。正式库仅只读核对，不启动旧图。
2. 对候选文件做静态引用和测试引用清单。预计可剥离的范围是 `api/graph_api/`、`api/system_mgt/`、`db/system_mgt/`、`db/dao.py`，以及 `graph_chat/` 中除 `controlled.py`、`__init__.py` 外的旧图、旧 Gradio、旧 Tavily 和流程图文件；`tools/` 中的旧 SQLite 读写与游览写工具。还要单独检查 `utils/` 中只供旧接口使用的 JWT／文档／中间件文件和 `static/graph8.jpg`。这些只是**候选**：任一文件被当前运行链、迁移或必要测试引用，就先迁移用途或从本步保留。
3. 把仍依赖 `tools/retriever_vector.py` 的政策测试改为验证当前政策目录与服务端政策回答的规则 ID、版本和冲突边界；确认 `data/policies/fictional_platform.md` 仍是保留的参考材料。清理确证无用的旧模块及只服务于它们的包依赖；对 `tavily-python`、`langchain-community` 等依赖逐项核对实际引用后再改 `requirements.txt`，不臆测其他依赖无用。
4. 对根目录的 `travel_new.sqlite` 和 `travel2.sqlite` 分别记录大小与 SHA-256。先验证源文件、目标 `data/source/` 的解析绝对路径都位于本工作区，目标不存在；再逐个用同一个 PowerShell 环境移动到 Git 忽略的目标目录，移动后重新计算哈希和大小并核对。若目标已有文件或容量不足，停下报告，不覆盖、不删除源文件。更新 README 中原始数据源的可选再生成路径；当前运行与部署仍只依赖交付样本。
5. 对新旧路由与业务做差异核对：旧 `/api/graph/` 与旧用户管理不注册，当前登录、只读查询、九类待确认提案、逐笔确认及重复确认行为保持原样。跑完整自动化、两日期全航线、Python 编译、页面脚本语法、依赖和文档链接检查；对删除造成的旧测试变化列出理由及替代覆盖。正式 5433 数据库不执行写操作，不调用付费模型或联网搜索。
6. 把候选文件的最终“保留／迁移／删除”清单、原始 SQLite 移动前后哈希核对结果、测试及剩余限制写入《当前进度》；只在功能分支提交。本步完成后再给 P3.2b 的准确脚本与旧小样本清理计划。合并本机 `main` 与 GitHub 同步留待独立 G-17 计划和确认。

## 3. 停止与恢复条件

若旧模块仍被现行入口或迁移引用、删除后九类交易行为改变、测试缺少等价覆盖、路径越出工作区、SQLite 哈希不一致、目标已存在或正式数据库状态异常，停止相关操作，保留原文件并报告。Git 跟踪文件可从本步功能分支的起点恢复；本机原始 SQLite 只移动不删除，且两份均不加入 Git。
