## 顺序与边界

第一步优先解决当前登录后“我的行程”为空的展示缺口；在写入正式云库前后都生成服务器外加密备份。第二步补齐持续恢复能力，第三步处理长期在线的运维问题，第四步形成可直接展示的作品交付。若第一步发现时间、报价、库存或确认卡不一致，停止写入并先修复，不把不连贯的行程展示为完成。

四步都保留现有原订单、历史文档、五个数据／证书卷和已上线域名；不自动更新演示日期，不接真实支付或供应商。正常修复与回归通过后按已确认的发布规则拟定独立 Git 同步计划；新的费用、权限或业务范围变化先交旅客判断。
