# P2.7a：固定证据与受控推荐操作计划

> 编写日期：2026-10-19｜状态：用户已确认，功能分支已验收；结果见《当前进度》。

## 1. 本次目标与交付

把现有 `recommendation` 占位节点改成只读、可追溯的对话推荐流程。用固定的、明确标为测试材料的地点证据完成端到端验证；正式运行若未配置真实检索服务，必须提示无法核实，不能把测试材料当作实时推荐。推荐覆盖能力由数据库中的可达城市集合决定，不要求为 95 城市预生成景点产品。输出在现有 `/turns` 的回答与引用内呈现，不增加景点浏览页或游览交易。

## 2. 开工前检查和 Git 顺序

1. 收到本计划的明确确认后，再打开《产品需求》《软件架构》《当前进度》和 P2.7 路线，核对本机 `main`、`origin/main`、工作区变更、忽略文件和数据库状态。规划文件若尚未提交，先将其作为开工记录纳入分支提交；不把 `.env`、数据库文件、原始输出或密钥加入 Git。
2. 从已完成 G-14 的本机 `main` 创建 `<历史功能分支>`。本次仅在功能分支实现；不合并 `main`、不推送远端。若主线在开工前发生变化，先对照差异调整计划并告知用户。
3. 优先用内存/固定证据和隔离测试完成验证。需要真实 PostgreSQL 回归时，只使用已验证的独立 `travel-eval` 库，先检查容器、端口、备份和基线；不启动或修改正式演示库，也不写原 SQLite。清理测试记录后复核基线并停止隔离容器。

## 3. 具体实施步骤

### A. 城市和旅客上下文

- 在服务层新增只读的可达城市查询：由有效模拟航班、报价、机场信息生成城市集合；与日期平移后的演示窗口一致。若同名地点可对应多个城市或机场，要求用户明确；不可达城市只返回覆盖说明及有根据的可达替代城市。
- 从服务端认证身份取本人已确认航班、酒店订单，按目的地和日期挑选推荐上下文。查询须按 `traveler_id` 和会话归属限定；未指定目的地时优先用近期已确认行程，多候选则澄清。旅客指定出发地/日期时，不凭网络覆盖直接宣称当天有直飞、价格或库存。
- 补全推荐意图参数约束：城市、偏好、日期仅取自用户明确表达或本人可信行程，模型无权造出行程事实。景点预订请求仍路由到推荐说明，不生成交易动作。

### B. 固定证据与回答

- 定义小型只读 `RecommendationProvider` 接口，输入只含公开城市和偏好，输出受限证据记录。测试实现只保留少量有来源的固定样本用于回归；生产默认无联网提供方，返回“目前无法核实地点”的明确结果。
- 服务端校验来源字段：HTTP(S) 公网链接、标题、城市、地点名、支持理由的内容、检索 UTC 时刻；限制长度、条数并去重。拒绝非网页协议、无来源、城市不符或把网页文字当作指令的内容。证据不足时不让模型自由补地点。
- 在受控图的推荐节点拼装 2～3 个有依据的建议与逐项引用。理由只来自证据和本人行程的明确关系，不能将外部摘要用于政策或订单。可先用确定性回答模板；如使用 DeepSeek 润色，增加服务端事实/引用一致性检查，失败退回确定性答复。
- 优先只给城市层面的建议；“酒店附近”缺可信景点坐标时不提供距离或交通时间。保存最小引用元数据到已有 `chat_turns.references`，API 重放返回相同答复与来源，不需要新迁移。

### C. 质量核验与文档

- 新增必要的固定模型/服务测试：可达集合、行程优先、无行程、多目的地澄清、不可达替代、恶意摘要/虚假链接、证据不足、错误城市、跨账号、用户要求游览预订，以及推荐与九类交易交替的多轮流程。对跨账号和未确认写入用数据库记录前后值判断，不依赖模型口头声明。
- 跑现有完整自动化测试、两日期离线航线校验、编译、依赖检查；若使用隔离库，再核对迁移、会话重启/重放和清理后的基线。只为消除具体风险补额外测试。
- 更新 README 中过时的 P2.6c 分支状态，并说明“固定证据仅用于测试；正式联网推荐尚待 P2.7b”。更新《当前进度.md》记录改动、证据、失败及待办。检查 Git 差异与敏感内容后提交功能分支，交用户审阅；另拟后续 P2.7b 或修复计划。

## 4. 本次费用、依赖与停止条件

本次不调用 Tavily 或其他真实搜索；无需用户现在配置检索 API。建议固定模型和测试优先，真实 DeepSeek 只在固定结果通过后做至多 **12 次**、保守费用停机线 **0.5 元** 的定向复核；零自动重试，记录请求量、延迟及服务商用量估算，达到任一上限立即停止。现有 DeepSeek 密钥只读取本机忽略的 `.env`，不回显、不提交；若密钥不可用，固定测试可继续，真实模型复核留待配置后。

以下任一情况阻断阶段验收：无来源却给真实地点事实、不可达城市被说成可达、别人的行程混入推荐、网页内容影响交易权限、景点请求生成订单卡、来源链接与所述地点/城市不一致、缺少检索服务时仍把固定测试样本当成正式推荐。遇到阻断项先修复并复测，若需新增持久表或改变产品边界则暂停该变更、修订计划并请用户重新确认。

P2.7a 通过后只提出 P2.7b 的独立联网实施计划，不自动合并本机 `main` 或推送远端。
