# G-15a：公开内容整理与发布历史审计操作计划

> 编写日期：2026-10-20｜状态：用户已确认，已按本计划执行；结果见《当前进度》。本计划只在功能分支整理和审计，不合并本机 `main`、不推送 GitHub、不改写提交历史。

## 目标与已发现的取舍

P2.7e 已建议以人工地点目录、实时搜索关闭的模式进入主线发布准备。目标远端为 `https://github.com/kling-feel/Travel-Assistant.git`，本机 `main` 当前为 `9a505ec`，本地记录的 `origin/main` 为 `fbb02bb`；功能分支是 `feature/live-source-recommendations`。在 P2.7e 尚未提交的开工快照，功能分支比本机主线多 13 个提交，比远端多 70 个提交；每次开工须重新读取实际提交号和远端状态。

当前最新文件树仍有开发工具品牌字样：约 **36 个跟踪文件、96 行内容及 1 个文件名**。虽然新提交说明没有该字样，只清理最新文件仍不能消除历史快照：待推送的约 70 个本地提交树均含该字样。普通快进推送会把这些历史页面一并公开。用户此前要求公开内容避免该字样，同时已确认不随意改写历史；这两项在“普通快进发布全部本地提交”下无法同时满足。远端现有历史也可能保留旧内容，须如实界定可达成范围。

## 操作步骤

1. **开工复核**：重读《产品需求》《软件架构》《当前进度》、本计划和既有[发布规则](G-发布同步与公开内容规则.md)；确认功能分支干净、P2.7e 验收提交存在、远端 URL 正确。只读核对本机主线、功能分支、远端主线关系，并抓取远端最新引用；若远端出现新提交，重新计算差异后再继续整理。
2. **最新文件树整理**：在功能分支逐文件替换旧计划、进度、架构、README、示例命令等公开内容里的品牌字样，保留阶段、测试、风险和提交哈希等业务事实。把含该字样的单个文件名改为通用安全文档名，修复站内链接。禁止全仓盲目替换导致路径、历史说明或代码含义损坏；逐类核对差异。
3. **公开差异与功能验证**：对最新跟踪文件内容、文件路径和新增提交说明做不区分大小写的零匹配检查；检查 staged 文件不含 `.env`、密钥、数据库、备份和忽略账本。运行完整自动化测试、两演示日期航线校验、编译、依赖、旅客路由和旧路由检查；文档链接逐项核对。整理结果只提交功能分支，结果写入《当前进度》。
4. **待发布历史审计**：以实际 `origin/main..功能分支` 为范围，检查所有将新增到 GitHub 的提交说明、文件路径与每个提交树中的品牌字样，同时检查历史中是否出现有效密钥或原始旅客资料。审计只读，不改提交历史；形成“普通快进发布会公开什么”的清单及数量。若发现敏感资料，停止后续发布规划并先处理凭证与历史风险。
5. **发布策略提案**：根据审计结果，为用户分别说明保留完整本地历史并普通快进发布、或将尚未公开的本地成果整理为干净的发布提交等方案的影响。后者需要改变本机未发布历史的接续方式，必须先保存可恢复引用，再由用户单独确认；远端已有历史无法靠最新提交清除。另写 G-15b 的具体本机合并与 GitHub 同步计划，列出最终提交、测试、回滚和推送命令，请用户确认后才执行。

## 边界

本计划的确认只允许最新文件树整理、只读历史审计和功能分支提交。它**不授权**移动本机 `main`、压缩或改写提交、强制推送、普通推送、改动正式数据库或打开实时联网开关。历史取舍由审计结果和用户后续选择决定。
