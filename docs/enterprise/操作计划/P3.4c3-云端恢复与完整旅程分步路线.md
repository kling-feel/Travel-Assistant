# P3.4c3 云端恢复与完整旅程分步路线

> 2026-10-27 制定，P3.4c3a 已获旅客确认并验收，P3.4c3b／c 尚待分别制定与确认。承接 [P3.4c2f 验收](../P3.4c2f-云端应用与HTTPS验收记录.md)。这是阶段路线，**不授权三个子阶段一次性实施**；每步另给具体操作计划，获确认后再执行，结果持续写入《当前进度》。

## 当前事实与目标

- 云端 2026-10-27 虚构批次、两个授权账号及 HTTPS 短时验收已通过；模型成功 9 次、联网搜索成功 3 次，短时三容器运行无 OOM。验收后公网代理与应用已停止，仅数据库运行，五个数据／证书卷保留。
- 当前两份有效 PostgreSQL 备份均与数据库处于**同一台服务器**。服务器丢失时不能凭它们恢复；云端九类写入只完成了有限抽样，未对独立恢复环境做完整交易确认。阿里云控制台防火墙规则与展示地网络体验也尚待复核。
- 本阶段的目标是拿到**服务器外、已加密、可实际解密并从全新卷恢复**的备份，然后在独立数据上完成交易验收和展示日流程。不重置正在使用的 `travel-cloud` 数据卷，不把测试订单写入原云端批次。

## 分步推进

| 检查点 | 操作范围 | 通过后能说明什么 |
| --- | --- | --- |
| P3.4c3a [异地加密备份与新卷恢复](P3.4c3a-异地加密备份与新卷恢复.md) · [已验收](../P3.4c3a-异地加密备份与恢复验收记录.md) | 先核对原库与批次清单；产生有唯一名称的备份，验证格式和哈希；在服务器外加密留存；**用这份外部密文**在新 Compose 项目／新卷解密恢复并核对数据库、清单和私有应用启动守卫 | 当前批次有一份实际可用的服务器外恢复副本；原库不变。旅客确认私钥第二份副本已保存至密码管理器，但该副本尚未独立解密验收 |
| P3.4c3b 九类交易与多轮隔离验收 | 先为写入验收另建可丢弃的独立库，从已验收备份复制基线；覆盖机票预订／改签／取消、酒店预订／改期／取消、租车预订／改期／取消，以及拒绝、过期、重复确认、跨账号、重启和日志审计。少量 DeepSeek 真调用验证自然表达，其余用固定模型降低偶发性；原云端订单不参与写入 | 九类交易的页面/API/数据库状态有实际证据，确认前后边界与政策一致；失败项列清而不掩盖 |
| P3.4c3c 展示日流程与远端备份维护 | 写出并演练“开启 → 健康/证书/账号/模型搜索核对 → 演示 → 停止”；从真实展示网络检查页面、速度与防火墙；决定是否启用不同地域私有 OSS 桶的自动备份、至少七份日保留与恢复提醒 | 可按文档独立开关演示。若自动异地留存及定期恢复未落实，只报告手动备份能力，不宣称持续灾难恢复 |

P3.4c3b、c 的详细计划将在前一步结果出来后制定，旅客分别确认。若恢复副本无法解密、恢复摘要不符、账号越权、未确认改订单或资源 OOM，先停止隔离验收，保留原卷与证据，不继续公网展示。

## 费用与需旅客处理的内容

- 旅客已选择 **P3.4c3a 先将加密备份保存到自己的 Windows 电脑**，不购买新云服务；电脑是独立于香港服务器的第二地点。恢复私钥由旅客控制，并由旅客在自己的密码管理器留第二份副本。阿里云 OSS 的私有桶、地域、阻止公共访问、最小权限和实际费用放在 P3.4c3c 单独核对，不在本阶段开通或购买。阿里云说明 OSS 按容量、请求和公网下载等计费：[OSS 官方计费说明](https://help.aliyun.com/en/oss/billing-overview)。
- 官方 `age` 支持用公开接收密钥加密、持有私钥才能解密；实施前核对官方发布物与版本，不自制加密格式，也不把私钥发到云主机、聊天或 Git：[age 官方用法](https://github.com/FiloSottile/age/blob/main/README.md)。PostgreSQL 17 的自定义格式可由 `pg_restore` 列目录并恢复：[pg_dump](https://www.postgresql.org/docs/17/app-pgdump.html)、[pg_restore](https://www.postgresql.org/docs/17/app-pgrestore.html)。
- P3.4c3b 只使用现有已授权的模型与搜索密钥，不需要新的 API；若需真实展示地点访问观察，由旅客打开页面或提供不含账号／密码的现象。P3.4c3c 若决定长期使用 OSS，再由旅客在控制台开通并授予专用最小权限；不把账号主密钥或密码交给项目。
