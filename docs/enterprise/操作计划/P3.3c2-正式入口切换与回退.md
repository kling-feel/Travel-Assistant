# P3.3c2：本机 8000 正式入口切换与回退操作计划

> 2026-10-25 制定并获旅客确认，执行中。旅客已选择“先修复推荐再切换”。承接已完成的[P3.3c1 隔离验收](../P3.3c1-隔离页面全旅程验收记录.md)。本计划只把本机演示入口从旧 5433 批次切到已验收的 5436 新批次；不合并 `main`、不推送 GitHub、不部署云端、不删除旧库或任何数据卷。

## 目标和当前已核对事实

- 本机 `main`／GitHub 仍为 P3.2 发布线；P3.3a～c1 在本地功能分支，最近提交 `a044ac8`。P3.3c2 的推荐修复完成 248 项回归后将随同一次本地提交，切换时运行的代码以该复测版本为准；其余业务规则不在切换中临时修改。
- 旧批次 Compose 项目对应 5433，数据卷保留，P3.3b 记录的基准日为 2026-10-22；原始自定义格式备份及恢复演练已有证据。新批次项目 `travel-date-next` 对应 5436，基准日 2026-10-24、13 版迁移、115 机场、33,121 航班；P3.3c1 结束时仍无会话或动作，订单和供给摘要与构建时一致。
- 2026-10-25 制定计划时，本工作台未发现 8000、5433、5436 监听；三者的实时状态在执行日重新核对。工作台无法直接运行 Docker 命令，确需启停容器或容器内备份时，才请旅客在可运行 Docker 的普通 PowerShell 逐行执行，并核对返回。旧备份和新批次忽略凭证文件在本机存在，内容不发送到聊天。
- 新旧批次复用旅客 ID，但数据库密码、JWT 签名密钥及演示账号密码不同。新批次**不继承**旧会话、订单变更和登录状态；旧记录保留在旧卷，回退时可恢复查看。

## 0. 推荐质量先行门槛

P3.3c1 的“自然风景”查询暴露出明确原因：推荐排序先放有匹配主题资料的城市，再用没有匹配资料的可达城市补满三项，导致不贴合偏好的地点混入答案。旅客已选择在正式切换前修复：有偏好时只展示具备近期核查且主题匹配地点、同时在指定日有可售直达航班的城市；不足三座就显示实际数量，没有则说明资料不足并建议放宽偏好或调整日期，不凭其他主题补位。“自然”目录里的室内自然历史博物馆也不能充当“自然风景”地点。定向测试覆盖 0／1／2／3 个匹配城市、室内场馆排除、同城多个机场及来源仍可追溯；在 5438 隔离库用真实只读对话复核，再跑完整测试。**修复和复测未通过则不进入 8000 切换**，5436 候选库不用于此项写入验收。

## 1. 切换前停止门槛

1. 推荐质量门槛通过后，再读本计划、三份核心文档和 P3.3b／c1 验收记录；检查功能分支、提交、工作区，复跑完整测试、编译、依赖和页面脚本语法。若工作区有来源不明的改动，先审查，不带入切换。
2. 核对当前日期仍在新批次可售窗口（2026-10-25 至 2026-11-23）、8000 的实际监听与进程、5433／5436 的容器项目标签、命名卷挂载和端口。如果 8000 有未识别服务，先识别来源并安排停止窗口；**不能按端口号直接杀进程**。若日期过窗或供给已不适合展示，停止本切换并另拟新批次，不在 5436 上原地重置。
3. 明确演示停止窗口：停止在 8000 发起新对话和确认卡操作；检查旧库是否仍有待确认卡或正在处理的请求，记录状态但不代旅客确认或撤回。旅客确认本计划后即按此执行；只有实际条件与计划不符且会改变切换范围时，才先修订并请旅客判断。
4. 只读复核旧 5433 的项目、卷、演示日、17 类表计数、订单状态、会话／动作／审计和业务摘要；与 P3.3b 基线比较。只读复核新 5436 的标签、卷、基准日、13 版迁移、订单摘要 `79ff22e02d89e9f243db0ee2de089cfeef57a968db46c7627a48f9d23db06fce`、供给摘要 `0a2932c104826aa96a509dea648618ebca350e48fc3a7ed4166c23f1aa4812cc`，且切换前没有新会话／动作。任何不符先停止并查明。

## 2. 双边备份与恢复证明

5. 在 Git 忽略目录分别保存**切换当日**的旧 5433 与新 5436 自定义格式备份；先确认目标文件不存在，避免覆盖 P3.3b／c1 旧备份。核对容器身份和挂载后执行 `pg_dump -Fc`，检查非零大小、`PGDMP` 文件头、`pg_restore -l` 目录、SHA-256。备份文件、账号与连接串不进入 Git、聊天或截图。
6. 对当日旧库备份在**全新、隔离的恢复卷**做实际恢复演练，恢复库使用另一空闲本机端口（优先 5439，执行时确认）；只读比较演示日、迁移、订单状态、17 类表计数、订单与供给摘要、会话和检查点数量。恢复库若已有 schema 或卷，停止并重新识别，不在非空库上重复 `pg_restore`。新库备份至少做目录校验；若备份或恢复校验失败，切换停止，原卷保持不变。

## 3. 受控切换

7. 为 5436→8000 增加**专用、可核对的启动入口**：只从 Git 忽略的 `p33b-next.env` 读取新数据库密码、独立 JWT 密钥和演示账号配置，显式把 API 端口及同源地址设为 8000；DeepSeek 与阿里云字段仅从本机 `.env` 读取。启动前拒绝非 127.0.0.1、非 5436／8000、意外 `DATABASE_URL`、与旧签名密钥相同、缺少必要模型／检索配置或错误的数据库身份。日志只显示脱敏目标，不显示密钥。此入口不会修改 `.env`、`p33b-next.env` 或数据库；不复用只允许 5438／8017 的验收启动器。
8. 新 5436 容器健康并完成上述核对后，才停止已经识别的旧 8000 API；若 8000 本就空闲，记录“无需停止”。保留旧 5433 容器及卷作为立即回退目标，正常状态可停止容器，但**不运行 `down -v`、重置或导入**。
9. 用专用入口在 127.0.0.1:8000 启动新 API。先读取有效配置目标及 `/health`，再核对 `/app`、静态资源、演示基准日、迁移和数据库连接；任何目标身份、启动或页面错误，立即停止新 API，进入回退步骤。

## 4. 切换后验收与回退

10. 在隔离浏览器或明确清除该页面的旧标签页会话存储后测试登录：旧批次令牌应 401，旧密码应拒绝；从本机忽略文件读取新密码登录 `demo1`／`demo2`，旧会话 ID 不可读取。页面需清楚显示新批次日期；按账号只读核对当前行程、政策、上海→伦敦可售候选、经典地点和中国天气边界。做少量受控 DeepSeek／阿里云只读提问，模型最多 5 次尝试、搜索最多 3 次；计量与结果另存忽略目录，不生成或确认真实交易卡。若模型／搜索失败但基础只读接口正常，记录为功能降级并按计划门槛判断是否回退，不以模型自述代替数据库结果。
11. 新 API／数据库重启各一次后再次核对登录、行程、会话及端口；新批次会从此产生自己的访问或会话记录，旧库记录不迁移。确认无跨账号读取、旧令牌可用、错误金额／日期或不经确认写入等阻断项，再把 8000 入口视为完成切换。更新根 README 的日常启动／登录说明、三份核心文档、独立验收记录和《当前进度》；保留新旧卷与两份当日备份。
12. 若第 9～11 步触发阻断：停止新 8000 API，不清理 5436 卷；确认旧 5433 卷与配置仍是切换前身份，启动旧容器并用未修改的旧 `.env` 在 8000 恢复旧 API。核对旧账号、旧行程与旧会话，旧订单／供给摘要与切换前一致。若旧 API 仍无法恢复，保持 8000 关闭，记录故障与备份路径，不能把恢复演练库当作正式旧库替代。回退不把新批次产生的消息或订单合并到旧库。
13. 若最终通过或已完成回退，停止仅供恢复演练的临时容器，保留所有数据卷和备份，记录 8000 最终指向、5433／5436 状态、实际请求与费用、测试结果和 Git 差异。只提交当前本地功能分支；合并 `main` 并同步 GitHub 按后续 G-18 单独计划执行。

## 成功标准与已知限制

成功时，8000 确实连接 **5436 新批次**，旧批次仍可用卷及已演练备份恢复；旧令牌／旧密码不能进入新批次，新账号能看到正确的虚构供给和初始订单，正常对话／联网只读可用。推荐结果不得用不符合已明确偏好的地点填满数量；没有匹配资料时须明确说出。阿里云 GlobalBasic 的实际账单需另从控制台核对。

本计划的确认只授权**本机 8000 批次切换及必要的备份、恢复演练、烟测和回退**，不授权删除卷、覆盖旧库、云端公开访问、合并 `main` 或推送 GitHub。
