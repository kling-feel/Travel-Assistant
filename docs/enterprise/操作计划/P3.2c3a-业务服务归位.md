# P3.2c3a：业务服务归位操作计划

> 2026-10-24 制定｜状态：已获确认并执行。承接 [P3.2c3 分步路线](P3.2c3-业务服务与助手入口归位分步路线.md)，实施结果写入[当前进度](../当前进度.md)。

## 1. 本步目标与范围

把根目录 `services/` 的 28 个现行 Python 文件按原名迁入 `travel_assistant/services/`，更新所有现行调用方。服务层包含航班／酒店／租车查询和交易、政策与价格、会话、推荐、天气、受控对话辅助和检查点；本步只移动位置，不改其规则或对旅客的回答内容。

当前 `api/` 和 `graph_chat/` 暂保留根目录，使用新服务导入路径。根 `main.py`、数据库包、页面、迁移版本名、脚本文件位置和测试发现方式不变。迁移文件中对政策和报价服务的引用只能改导入路径，不改变已应用版本的身份或升级语义。

## 2. 确认后的执行顺序

1. 读取三份核心文档、本计划与仓库现状，确认 P3.2c2 提交、工作区和本机主线引用。记录 28 个服务文件、跨目录导入、`patch(...)` 等字符串目标、31 条注册路由、18 张数据表、13 个迁移版本与 230 项完整测试基线；核对 README 的公开脚本命令。
2. 原样移动 28 个文件到 `travel_assistant/services/`。先按明确的旧前缀改内部及外部导入，再改 API、助手、迁移、脚本、测试中指向服务模块的字符串补丁目标。逐文件比较移动前后内容：除导入路径以外不应有业务差异；不建立根目录兼容包装，不顺手修改模型提示词、报价、交易或推荐事实。
3. 在项目根与项目外工作目录只读导入当前启动、迁移、导入脚本和保留的隔离脚本模块；比较路由路径／方法、数据库元数据和迁移版本。通过内存测试客户端检查 `/app`、静态资源、登录保护及关键查询／待确认卡接口。只有这些检查通过后，才清除旧 `services/` 的缓存与空目录。
4. 运行服务／推荐／交易定向测试和完整自动化；核对两日期全航线样本、Python 编译、页面 JavaScript 语法、依赖、README 脚本入口及全部本地 Markdown 链接。凭证形态检查和 Git 差异检查须通过，确认交付数据、原始本机 SQLite 和忽略配置没有进入暂存区。
5. 更新 README、软件架构、脚本索引与《当前进度》，记录实际移动、导入数量和验证边界。只在当前本地功能分支提交；之后另拟 P3.2c3b 助手与 API 归位的详细计划，等待新确认。

## 3. 停止条件

- 任一服务导入失败、字符串补丁失效、迁移版本或表结构变化、API 路由减少、交易确认边界退化时，停止在本步修复；不得留下新旧两份服务实现。
- 如果服务文件存在其他隐式路径或运行时动态导入，先核实并更新为明确路径，不依赖当前工作目录；不能验证时保留原位置并说明原因。
- 本步不运行 PostgreSQL 迁移／导入／重置，不创建真实测试账号或订单，不调用 DeepSeek／阿里云接口，不合并本机 `main` 或推送 GitHub。
