# P2.7c：城市国家约束与地点证据修复操作计划

> 编写日期：2026-10-19｜状态：已执行，来源质量验收未通过；本计划不授权主线合并或 GitHub 推送。结果见《当前进度》。

## 1. 起点和目标

P2.7b 累计 24 次 `GlobalBasic` 搜索，接口本身可用，但真实样本出现三类来源误判：汇总页被当作具体地点、整座城市被当作景点、美国 Georgia 的 Rome 被当作意大利 Rome。定向过滤虽已阻止已知样本，尚无覆盖全部 95 个可达城市的国家依据，且同一地点的中英文名称可能重复。联网推荐继续默认关闭。详细证据、费用不确定性和测试结果见《当前进度》。

本阶段目标是让每条展示的推荐同时满足**具体地点、正确城市与国家、主题相符、来源可打开、去重可解释**。安全性优先于凑足推荐数量：没有足够证据就只给 1 个地点或明确降级。继续使用用户指定的阿里云 `GlobalBasic` 和原 FastAPI／LangGraph／服务层结构；不做游览预订、真实供应商交易、页面或数据库迁移。

## 2. 实施顺序

1. **开工与隔离**：重读《产品需求》《软件架构》《当前进度》和本计划；核对 P2.7b 功能分支、工作区、忽略文件、24 次搜索账本及本机/远端主线。保留 `ALIYUN_IQS_ENABLED=false`。只在现有功能分支继续；源库与正式 PostgreSQL 不写入。
2. **可信国家上下文**：从项目已有的机场时区读取所安装 `tzdata` 的公开 `zone.tab`，得到机场所属 ISO 国家代码；当前样本 70 个时区中 69 个可直接对应，`America/Montreal` 需有可审计的加拿大别名规则。生成或维护随仓库交付的城市/机场/国家映射和英文国家名，人工审查 115 机场、95 可达城市、同名城市及跨国机场情况。若某城存在多个国家或映射无法核实，就不联网推荐该城，并说明原因。映射内容是非个人公开地理数据，不改原 SQLite 或现有订单。
3. **把地区约束送到检索和验据**：服务端由可信机场映射确定目标国家；搜索请求只含城市、国家和有限主题词，不含旅客/订单信息。来源在标题、摘要、可验证域名或可用正文中必须有足够证据关联到该国和具体地点；缺失或冲突就丢弃。维持固定 HTTPS 端点、`summary=false`、单次搜索和短超时。是否开启 `mainText` 先用假响应比较额外质量收益及响应大小，确认无额外计费项后才用于真实请求。不得仅凭网页标题中的“官方”二字判定官方站点。
4. **地点与来源去重**：继续拒绝城市页、游记线路、榜单、机构与不安全链接。对英文冠词、标点及同一来源 URL 规范化去重；中英文名称若不能证明是不同地点，先只展示最可信的一项，避免同一博物馆在回答中出现两次。优先场馆/城市官方或公共机构页面；非官方来源可在支持地点事实时引用，但不得标成官方。无经核实坐标不报酒店距离；来源文本不进入政策或交易工具。
5. **固定测试与全城市真实复测**：增加 Rome Italy/Georgia、Paris France/Texas、London UK/Canada、城市页、列表页、中英同名、伪造官方、提示注入、恶意 URL 和网络异常的固定响应。逐一审查 95 个可达城市，对国家能确定的城市各做至少 1 次真实检索；有跨国同名且无法确认目的地的城市明确降级并计入未覆盖。另选高风险同名城市、跨语种页面及不同主题做复测。自动记录所有展示候选的地点、国家证据、主题、来源类型与降级原因；人工打开至少 60 条结果，覆盖至少 30 个城市和东亚、欧洲、中东、美洲等地区，优先检查所有可疑结果。来源内容只进 Git 忽略的评估账本；公开进度仅记录脱敏统计和典型问题。
6. **真实对话与数据库边界**：在隔离内存 API 做本人行程、跨账号、同请求重放、无来源降级、景点预订不建卡；再用 DeepSeek 做最多 30 次真实模型请求，包含至少 10 组多轮推荐/改意图/交易交错场景。模型不能把网页文字当指令，也不能凭来源生成订单、价格、距离或政策。若安全可行，再按既有隔离库基线做 PostgreSQL 重启核验；源 SQLite 和正式演示库不写入。
7. **收尾**：完整自动化、两日期全航线、编译、依赖和路由检查通过。更新 README、映射来源说明和《当前进度》；审查提交差异和公开内容后只提交功能分支，不合并或推送。P2.7c 通过后另提供 G-15 本机 `main` 合并与 GitHub 同步计划，等待用户确认。

## 3. 新增调用额度与费用说明

本计划建议 **P2.7c 新增最多 250 次 `GlobalBasic` 搜索、30 次 DeepSeek 请求**；P2.7b 已使用的 24 次搜索单独记账，不能把剩余 1 次挪到本阶段。250 次是预留上限，不是必须用满的目标：约 95 次全城市首轮、45 次风险城市/主题交叉、30 次对话联调、最多 80 次修复后复测。逐次在本机忽略账本中先记数再发请求；每 25 次检查接受率、误判与服务异常，质量没有改善就先修复或停止，不靠增加调用量凑结果。无自动重试，达到调用上限即停止。

阿里云 [Global 产品说明](https://help.aliyun.com/zh/document_detail/3062116.html)和[计费说明](https://help.aliyun.com/zh/document_detail/3061214.html)截至本计划修订时仍未公布 `GlobalBasic` 专属单价；不能保证人民币金额上限。为了准备较宽裕的测试经费，仅用已公开的 `GlobalAdvanced` **56 元/千次**作较高档的量级参照：250 次对应约 **14 元**，加上 DeepSeek 与误差余量，建议预留 **20～30 元**。这不是 `GlobalBasic` 的报价、费用承诺或自动停机线；最终按实际账单核对。若账号显示异常扣费、限流或欠费，立即停止并报告，不再扩张到其他引擎或增值参数。用户确认本修订计划才授权新增调用额度。

## 4. 验收与停止条件

- 抽样中**凡展示的地点**都能由打开的来源支持具体地点、目标城市/国家和给出的主题理由；不得出现同名城市跨国误配、城市/机构/榜单当景点、无依据距离/票价/时刻，或同一地点以中英名称重复。
- 95 个可达城市均完成国家/地区核查；能确定目的地国家的城市均至少真实检索一次，无法确定的城市如实降级并计入未覆盖。建议至少 **75/95 城市**有一条合格地点；不足时不宣称全城市推荐已达到演示要求，记录失败率并提出单独的检索源比较方案供用户决定，不暗中切换引擎。人工抽查至少 60 条结果、30 个城市，错国、榜单/城市页当地点、无据价格或距离、重复地点等高影响错误必须为 0。
- 任何来源误判导致错误城市或错误交易卡，立即停止该批真实测试、修复和复测；任一请求数达到新上限、429/额度或账号扣费异常也停止。无服务商单价时不能宣称金额上限已得到证明；如总量仍不足以达到验收，另提计划而不是自行扩大额度。
- API 密钥、原始对话、原 SQLite、正式库及忽略目录的原始检索片段不进入 Git；`main` 与 `origin/main` 在得到 G-15 确认前保持不变。测试结论和未解决风险只写入《当前进度》。
