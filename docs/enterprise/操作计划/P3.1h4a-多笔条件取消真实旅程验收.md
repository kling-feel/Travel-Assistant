# P3.1h4a：多笔条件取消真实旅程验收操作计划

> 制定日期：2026-10-23｜状态：用户已确认，验收通过；执行结果见《当前进度》和对应验收记录。只覆盖独立验收环境、必要的定向修复与功能分支提交；本机 `main` 合并和 GitHub 同步不在本计划内。

## 1. 目标与建议顺序

P3.1h3 已修复机票、酒店、租车的跨业务串线，并通过独立真实 API 旅程和旅客页面视觉复核。P3.1h2 仍未在真实页面完成“保留伦敦，取消其余行程”和按出发机场定向取消的多笔订单场景。本步先补这项交易风险较高的缺口；下一步再单独规划断线、切会话和宽窄屏矩阵。两步都通过后才更新 G-16 发布方案。

验收的核心不是助手能否说出“已生成卡”，而是它是否准确列出**保留、可取消、含糊、已过截止**的本人订单；每轮最多两张卡，确认前订单不变，逐张确认后只有目标订单改变。

## 2. 开工前核对与隔离

1. 重读《产品需求》《软件架构》《当前进度》、P3.1h3 验收记录及本计划；核对功能分支、工作区、提交和用户 8000 页面状态。只读核对正式 5433 库，不重启或修改它。
2. 复用保留数据卷的 `travel-p31h2` 独立 PostgreSQL（本机 5435），由用户在能运行 Docker 的普通 PowerShell 启动。先核对基准记录、现有测试账号和 Git 忽略目录中的备份；再保存本轮独立库新备份。只在新建的一次性旅客账号中安排多笔有效订单，不清理其他验收账号。
3. 独立 API／页面使用 8014，先检查端口空闲，并确认仅连接 5435。模型密钥、账号密码、原始对话、计费流水和备份只保存在 Git 忽略目录；公开文档只记录脱敏事实与汇总。

## 3. 操作与测试顺序

### A. 固定模型与服务端边界

- 在独立旅客账号准备至少两笔不同目的地的有效机票、一笔异地酒店和一笔租车；另设同机场多笔订单、跨城行程及已过取消截止订单。所有样本日期以本轮演示基准日为准，逐一核对政策版本和订单归属。
- 固定模型重放“保留伦敦，取消其他安排”“取消汉堡机场出发的机票”“取消我的所有酒店”“只取消刚才那一笔”。核对每轮保留／拟取消／无法办理清单；对象不唯一或跨城含糊时先追问，不借用模型猜测的订单 ID。
- 核对每轮最多两张独立待确认卡，未列入卡片的其余订单需说明并由旅客再次提出；同请求键重放不重复生成，另一账号无法读取或确认。报价、政策、订单版本、卡有效期和取消截止在确认时重新复核。
- 对一次性账号逐张执行一次确认、一次放弃和一次重复确认，逐次查询有效行程、订单历史、动作审计和实际订单状态。取消完成后普通对话不再提已取消订单；明确问取消历史才展示。

### B. 有上限的真实模型与页面旅程

- 使用现有独立计量思路建立本轮单独流水：最多 **30 次 DeepSeek 请求尝试**，保守估算模型费用达到 **¥8** 即停。此场景只验证订单取消，不主动调用阿里云搜索；联网默认配置保持原样，但若意外触发检索，应记录并停止排查。实际费用以服务商账单为准。
- 用真实模型连续重放上述条件取消话语；至少覆盖保留伦敦、多笔同类型订单和“汉堡出发”唯一／不唯一两种情况。失败先定位路由、订单定位、服务端守卫或最终文案；只做本范围内的定向修复并重测，不靠重复抽样把偶然成功写成通过。
- 旅客在 8014 本机页面检查待确认卡的对象、城市、当地时刻、费用、保留说明和状态；在一次性账号上按计划确认／放弃指定卡，并核对“我的行程”有效卡与历史取消卡区别。工作台若仍不能自动读取本机页面，就请旅客反馈实际观察，不绕过访问限制。

### C. 回归与收尾

- 新增针对发现缺陷的必要测试，运行完整自动化、Python 编译、页面脚本语法、依赖、两日期演示样本和差异检查；只为具体风险补测，不重复无关测试。
- 记录每个场景的通过／失败／未测、真实调用数与已知费用、订单前后状态和隔离环境影响。更新《当前进度》及验收记录；公开内容检查不得包含密钥、一次性账号、原始模型响应或用户要求排除的工具品牌字样。
- 关闭 8014 独立服务，由用户停止 5435 独立数据库容器并保留数据卷；只在当前功能分支提交本步成果。**不合并本机 `main`、不推送 GitHub、不触碰用户的 8000 服务。**

## 4. 通过标准与停止条件

通过需要真实模型与确定性服务都能准确识别取消范围；待确认卡只对应本人可取消订单；确认前零状态变更，确认后只改变逐张确认的目标；重复确认、越权、过截止和版本变化不会误取消；页面状态与数据库一致。若真实页面无法复核、独立库基线异常、预算边界触发或关键安全用例失败，暂停本步发布判断，记录缺口并先修复。

本步完成后单独制定 P3.1h4b 的断线恢复、切会话及宽窄屏交互验收计划。G-16 仍需在全部发布阻断项关闭后重写并单独确认。
