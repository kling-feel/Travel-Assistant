P3.4b 已有独立云端 Compose、Caddy 配置、固定依赖与基础镜像摘要、账号管理、限流、用量记录及隔离库备份恢复证据；258 项自动化测试通过。正式域名证书、香港线路、真实密钥和异地加密备份尚未验证，不能把本机结果当作公网验收。

## 二、购买前的费用与合规检查点（P3.4c1）

1. 旅客现有截图：香港 2 vCPU／4 GiB／50 GiB 套餐购买页为 **¥112／月**；2 vCPU／2 GiB／40 GiB 为 ¥56／月。根据[P3.4b2 本机容量验收](../P3.4b2-2GiB容量验收记录.md)，少量账号展示可优先考虑 **2 GiB 条件方案**：购买后必须在真实机器上复测导入、真实模型对话、重启和备份恢复，若不通过则停止展示并升级到 4 GiB。旅客明确本轮只考虑短期展示，**不以续费价作为本次购买门槛**。请在最终订单核对 **首购价、一个月购买周期、Ubuntu 镜像、磁盘、带宽／流量条款、税费、自动续费状态**。阿里云说明轻量应用服务器按套餐包年包月计费，实例到期后可能停机并最终释放，停机不等于免除已购买周期的费用：[计费规则](https://help.aliyun.com/zh/simple-application-server/product-overview/overview)。
2. 旅客选定 `tripfolio-lab.com` 作为候选；核对实际可注册状态、首年价格、实名认证要求、DNS 及证书联系邮箱。域名通常按年购买，须把首年现金支出单独列清；本轮不要求续费报价。香港服务器对应的公开服务手续由旅客按当前适用规则核实；[阿里云备案问答](https://help.aliyun.com/zh/icp-filing/basic-icp-service/support/for-the-record-process-faq)可作起点，不把地区标签直接等同于全部手续已经完成。
3. 确定服务器外的私有备份存储，优先同一账号下**不同地域**的私有 OSS 桶，或者等价的独立存储。核对存储量、请求次数、下载流量及加密密钥保管成本；[OSS 计费说明](https://help.aliyun.com/zh/oss/billing-overview)列出这些计费维度。备份应在上传前加密，恢复密钥与备份分开保存。服务器快照可辅助回滚，但单机最多三份且实例释放时会清除，不能充当异地备份：[快照限制](https://help.aliyun.com/zh/simple-application-server/user-guide/manage-snapshots)。
4. 制作一张**本次现金支出与首月运行费**清单：服务器一个月＋域名首年一次支付＋异地备份首月；DeepSeek 与联网搜索调用费单列，不设置金额自动停机线。用户的基础运行费目标为 ¥50～150／月，但域名年付会抬高第一次付款金额，必须单独明示。若实际首月费用高于预期，先给旅客选择调整套餐／域名／存储方案或明确接受本次金额，不直接购买。GlobalBasic 的真实单价仍需在账号账单或合同中核实，不能拿其他版本的价格代替。
5. **购买授权点**：把选中的具体商品、地域、系统镜像、月数、首购价、域名首年价、备份预估、自动续费状态和首次现金支出发给旅客核对；购买／支付只在旅客明确确认后进行。旅客在自己的阿里云账号中支付，不向聊天发送密码、支付资料或密钥。若以后决定继续运营，届时再核对续费价和预算。

## 三、服务器和程序部署（P3.4c2）

1. 推荐 Ubuntu 24.04 LTS x86_64；如果购买页更换系统镜像导致价格变化，先重新核算。创建 SSH 密钥登录和非 root 管理用户，限制 SSH 来源；启用基础系统安全更新。按照 [Docker 官方 Ubuntu 安装文档](https://docs.docker.com/engine/install/ubuntu/)安装 Engine 与 Compose 插件。安装后记录版本、空闲内存、磁盘和端口占用。
   若购买 2 GiB 套餐，先补并核对专用于正式部署的资源限额覆盖配置：应用 768 MiB、数据库 640 MiB、代理 128 MiB，保留正式 80／443 端口和真实证书；不能复制本机隔离试验的 8021／8022 端口与内部证书。构建、迁移、初始化及恢复分时运行，实时检查整机内存、交换空间、OOM 和磁盘；无法在真实主机安全完成时，改用预构建镜像或升至 4 GiB 后再开放展示。
2. 安全组只公开 80／443 和受限 SSH；不公开 PostgreSQL 5432、应用 8000 或 Docker 管理接口。核对 Docker 实际发布端口，因为 Docker 发布端口可能绕过主机 `ufw` 规则：[官方说明](https://docs.docker.com/engine/install/ubuntu/)。
3. 使用经过公开内容检查的固定仓库提交部署，创建新的 Git 忽略 `cloud.env`；不复制本机 `.env`、旧数据库或已有账号。填入域名、证书邮箱、独立数据库／JWT 随机值、授权的 DeepSeek 与阿里云搜索密钥，并核对固定基础镜像版本及安全更新。私有文件只让管理员读取；不要在日志、截图、聊天、Git 或镜像中输出密钥。
4. 新 Compose 项目和**新空卷**先做清单与空库检查，空库备份验证后显式执行 v001～v014 迁移和虚构批次导入；记录批次日期和供给摘要。初始化失败时暂停查因，不对非空卷重跑导入，不使用 `down -v`。先创建独立授权账号并停用初始账号，再启动应用和 Caddy。
5. 域名 DNS 指向实例后检查证书签发、HTTP 到 HTTPS 跳转、证书卷持久化与重启后的续签路径。Caddy 的自动 HTTPS 依赖域名 DNS、外部 80／443 和可写的持久数据目录：[官方条件](https://caddyserver.com/docs/automatic-https)。不能仅凭本机代理语法通过宣布公网 TLS 已完成。

## 四、公网验收、备份和回退（P3.4c3）

1. 从旅客实际展示地点打开页面，核对速度、中文布局、证书和手机窄屏；从外部检查只有计划公开的端口，`/docs`、`/health`、`/ready` 和数据库不能通过公网读取。匿名、错误账号、停用账号、已授权账号各走一次；两个授权账号互相读取本人订单／卡片应返回拒绝。
2. 抽样跑行程查询、最早航班、酒店、租车、政策、旅行推荐与联网来源核验，以及九类交易卡的关键状态。核对确认前订单不变、逐笔确认后只改本人订单、重复确认幂等。若真实 DeepSeek／GlobalBasic 密钥已由旅客配置，做**少量**真实调用并核对服务商账单；失败时清楚说明未核实，不把模拟结果称为实时事实。
3. 制作 `pg_dump -Fc`，验证备份目录、哈希，加密后上传到服务器外的私有存储；保留至少七份每日备份，并在演示结束与升级前额外备份。实际在一个全新隔离卷解密并恢复，核对批次日期、迁移、供给、订单、会话、动作及审计摘要。记录恢复耗时、成功证据、保留策略和谁持有解密密钥。正式异地备份未恢复成功前不将站点标为可恢复。
4. 验收完保留数据库与证书卷，按需要停止公开代理和应用；再次展示前检查套餐有效期、DNS、证书、容器健康、授权登录、模型／搜索余额和一条真实旅程。升级前先备份并记录当前镜像／提交，失败则停止新版本并恢复原镜像；如数据库迁移不可逆，用最近可验证备份在**新卷**恢复，绝不直接覆盖旧卷。
5. 将验收结果、实价、备份位置类别、恢复证据、问题和剩余风险写入《当前进度》。详细账号、主机 IP、密钥、备份路径、支付信息只留旅客私有记录。公开主线合并和 GitHub 推送按另一个 G 系列计划执行，不随本部署计划自动发生。
