## 顺序

1. 旅客在阿里云轻量应用服务器控制台为此实例自动创建**专用**密钥对，保存一次性下载的 `.pem` 私钥到自己电脑的私有目录；不在聊天、Git、截图或项目目录传播私钥。绑定目标实例并立即重启，使密钥生效。操作前先核对实例名称、香港地域和实例 ID；控制台一次只绑定一个密钥对，新绑定会替换原绑定。
2. 旅客只告诉助手本机 `.pem` 绝对路径；无需提供私钥内容、root 密码或 API Key。助手先只读检查本机密钥文件是否存在、权限是否合理、服务器 22 端口是否可达。
3. 使用阿里云 Workbench 可信控制台查看服务器 SSH 主机公钥指纹，与首次本机 SSH 连接显示的指纹核对。先以控制台密钥默认绑定的 `root` 用户登录。只读取系统版本、内存、磁盘、端口、防火墙和现有用户，不执行安装或改动。

   当前工作台的外网 SSH 探测未返回，旅客普通 PowerShell 的 22 端口 TCP 测试已返回 `True`。因此先在阿里云 Workbench 运行 `sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` 获取可信指纹，再在旅客普通 PowerShell 用专用私钥发起首次连接；显示的 ED25519 指纹必须一致才接受。若工作台网络仍不可达，后续服务器命令由旅客在本人普通 PowerShell 或 Workbench 中按逐步核对的指令执行，不通过跳过主机验证来绕过网络限制。
4. 只读检查通过后，创建专用非 root 管理用户并设置受控 sudo 与密钥登录；先验证第二条 SSH 会话可用，再限制 root 及密码远程登录。保持阿里云 Workbench 救援路径可用。对外 SSH 来源尽量限制为旅客当前公网地址；端口 80／443 待域名、配置、代理准备好后再开放，8000／5432 始终不开放。
5. 再按已确认 P3.4c 计划安装 Docker Engine／Compose、准备独立云配置与域名、执行空库备份和一次初始化；实际公网验收与异地恢复为后续检查点。本轮不会复制本机正式 `.env` 或旧业务数据库。

## 域名与解析并行核对

旅客已完成域名购买并在阿里云轻量服务器控制台添加一条 `www` A 记录。下一步确认最终只使用 `www.adzyforever.com`，还是使用裸域 `adzyforever.com`，或继续使用原候选 `tripfolio-lab.com`；这决定 `PUBLIC_HOST`、DNS、证书和页面链接。若选裸域，还须给 `@` 添加 A 记录；若选 `www`，不把根域也写进当前单域 Caddy 配置。实际对外 DNS 生效后，由项目已有 Caddy 自动申请 HTTPS 证书，无需在阿里云控制台另购付费证书。域名注册及信息模板由旅客本人在自己的账户管理，不向聊天发送身份资料或支付信息。

## 验收与失败处理

- 验收：SSH 主机指纹匹配；专用密钥可登录；非 root 管理用户可独立登录和运行授权命令；只读资源检查显示购买规格；没有应用、数据库或管理端口意外对外开放。
- 密钥下载失败、绑定到错误实例、指纹不符、无法登录或权限不对时，停止继续配置，使用阿里云控制台救援，不反复重置／覆盖密钥，不降低登录保护以绕过错误。
- Git：只更新公开操作指南与进度，不提交私钥、账号、IP、密钥指纹或带敏感信息的日志。功能分支成果以后按单独 G 计划审查、合并和同步 GitHub。
