# G-17：P3.2 本机主线合并与 GitHub 同步操作计划

> 2026-10-24 制定｜状态：等待旅客单独确认。本计划只用于发布已完成的 P3.2 目录与文档整理；实施结果写入[当前进度](../当前进度.md)。

## 1. 目标与已核对基线

把已验收的 P3.2a～P3.2d 从本地 `feature/p32a-legacy-cleanup` 快进合并到 `main`，随后同步到获授权的 `kling-feel/Travel-Assistant` 仓库 `main`。制定计划时，本机功能分支为 `b4c68d8c2e3fe00f5f9ac61642ba256f90996155`，本机 `main` 和保存的 `origin/main` 同为 `5d5e95d8fabb641f14520855fd859e3cc89c3d58`，工作区干净。待发布范围为 10 个功能分支提交、216 个变更路径，合计约 1,409 行新增、7,714 行删除；以真正执行前重新核对的数字为准。当前最新跟踪树的 257 个路径、内容和这 10 条提交说明中，不含旅客要求避开的开发工具品牌字样；`main..HEAD` 差异格式检查通过。

本次主要移除已停用旧实现和一次性脚本，将现行模块、页面资源与测试按职责归位，并新增文档导航。业务规则、交易确认边界、API 路径、数据库表和迁移版本不应变化。P3.2c4 的完整自动化基线为 **230 次测试执行**；P3.2d 只改文档，已核对 360 个现行本地文档链接、17 个 README 脚本路径及历史资料保留。正式演示数据库、8000 页面和付费模型／搜索均不在本次发布操作范围。

## 2. 确认后的执行步骤

1. 重读[产品需求](../产品需求.md)、[软件架构](../软件架构.md)、[当前进度](../当前进度.md)和[公开发布规则](G-发布同步与公开内容规则.md)。先把本计划、计划索引和事前进度记录作为一笔中性说明的本地功能分支提交；核对提交后工作区干净，不夹带别的文件。若计划或范围有变化，先更新计划并请旅客重新确认。
2. 核对远端 URL 仍为 `https://github.com/kling-feel/Travel-Assistant.git`，执行 `git fetch origin`，比较远端 `main`、本机 `main` 和目标功能分支。必须满足远端 `main` 与本机 `main` 一致、功能分支是其后代，且不存在待处理本地改动。远端若前进或分叉，停止发布，先报告差异并重新拟定整合方案；不做强制推送或历史改写。
3. 审查 `main..功能分支` 的完整文件与提交差异，确认没有 `.env`、密钥、原始 SQLite、备份、测试账号或费用流水进入 Git；对最新跟踪树的路径、内容和本次提交说明做品牌字样零匹配核对。执行凭证形态检查、`git diff --check`、文档链接、脚本路径、依赖与页面语法核对。若任何项失败，先在功能分支修复、复验并记录，不合并。
4. 在功能分支运行完整 **230 项**自动化测试，并复核现行启动／路由契约、两日期离线航线样本与数据库迁移版本清单。此阶段只读样本和代码，不运行数据库迁移、导入或重置，不触碰本机正式库。若测试基线因计划提交以外的变动改变，应解释原因并重新审查发布范围。
5. 确认前述门槛全部通过后，切到本机 `main`，用 `git merge --ff-only feature/p32a-legacy-cleanup` 快进合并。合并后再跑完整回归和静态／公开内容核对。将实际合并哈希、测试、远端目标与结果补入《当前进度》，作为单独的中性说明提交到本机 `main`；再次检查工作区和公开内容。若合并后检查失败，停止推送，先修复并复验，不隐瞒本机主线已前进的事实。
6. 仅执行普通 `git push origin main`，不推送功能分支或标签，不使用 `--force`。随后用远端读取核对 GitHub `main` 与本机 `main` 的提交哈希一致，并检查公开最新树及进度记录。推送失败时记录“本机已合并、远端未同步”，保留可恢复状态并定位原因；在同步完成前不开始下一次主线发布。

## 3. 发布范围与停止条件

- 本计划不更新演示日期，不清空订单／会话，不启停 Docker 容器，不调用 DeepSeek 或阿里云搜索。发布后若需正式演示库日期平移或云服务器部署，另拟计划并在执行前备份、核对订单影响。
- 最新公开文件树和新提交说明不出现旅客禁止的字样；旧 Git 历史不改写。若旧历史仍可在 GitHub 查到相关字样，应按既有公开规则说明历史边界，不以本次发布暗示旧记录已被删除。
- 任一快进关系、回归、凭证、文档链接或远端身份检查不通过时，停在安全检查点并给出事实、修复方案与新的确认点。
- 本文档及索引的写入只是事前计划，**不是合并或推送授权**；等旅客确认 G-17 后才执行第 1～6 步。
