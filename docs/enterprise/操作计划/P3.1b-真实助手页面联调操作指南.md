# P3.1b：真实助手页面联调操作指南

> 编写日期：2026-10-20｜状态：用户自行启动与测试的操作指南；尚未执行数据库重置、代码默认值变更、主线合并或推送。

## 1. 本次使用的服务

- **真实页面**：`http://127.0.0.1:8000/app`，由项目根目录的 `main.py` 启动，使用 PostgreSQL 和 `.env` 中的 DeepSeek 配置。
- **不要使用 8001**：它是 `tests/p31_preview_server.py` 的临时固定模型预览，只有两班汉堡至巴塞尔航班和一个酒店房型；模型不读取提问，不调用 DeepSeek 或阿里云。
- 阿里云 CleverSee `GlobalBasic` 本轮在本机运行配置中开启。检索仅在符合条件的经典地点推荐中尝试，每轮最多一次；回答仍以已人工核查的 95 座可达城市地点目录为事实来源。搜索匹配不到、超时或失败时回退目录，不能用回答文字直接证明检索成功。实际调用可能产生服务商费用。

## 2. 已核对的本机准备情况

功能分支 `feature/p31-traveler-ui` 工作区干净；`.venv` 和 `.env` 存在。`.env` 中 DeepSeek 提供方、模型、地址、密钥，阿里云密钥、数据库密码、JWT 密钥及两个演示账号密码均已设置；本指南不读取或展示任何密钥值。`POSTGRES_PORT=5433`，`ALIYUN_IQS_ENABLED` 尚未设置，代码缺省值为关闭。当前工作台找不到 Docker 命令，不代表用户自己打开的 PowerShell／CMD 中的 Docker Desktop 不可用。数据库容器和卷的实时状态须在用户自己的终端核对。

## 3. 用户操作：配置与启动

**步骤 1：关闭旧预览页。** 浏览器不要再使用 `http://127.0.0.1:8001/app`。打开 Docker Desktop，待引擎显示已运行。在文件管理器打开本项目根目录，点击地址栏、输入 `powershell` 并回车；新终端将从该目录启动。然后执行：

```powershell
docker --version
docker compose version
git branch --show-current
```

分支应显示 `feature/p31-traveler-ui`。若 Docker 命令在这个 PowerShell 也不可用，先在原来能执行 `docker --version` 的 CMD 中检查 Docker Desktop；不要因此重新安装数据库或删除卷。

**步骤 2：开启本次联网搜索。** 在上述项目目录运行 `notepad .env`，在文件末尾新增且仅保留一行：

```dotenv
ALIYUN_IQS_ENABLED=true
```

保存后关闭记事本。已有的 `ALIYUN_IQS_API_KEY` 和 DeepSeek 配置保持原样；不要把 `.env` 内容发到聊天或放进 Git。该开关会在下一次启动 API 时读取。此操作让**本机本次及后续按该 `.env` 启动的服务**默认尝试联网推荐；仓库代码里的无配置缺省值仍为关闭，永久产品默认值改动需在联调结果确认后更新代码、需求与发布计划。

可只检查开关和密钥是否存在，不输出密钥：

```powershell
.\.venv\Scripts\python.exe -c "from config import settings; print('search_enabled=', settings.ALIYUN_IQS_ENABLED, 'key_present=', bool(settings.ALIYUN_IQS_API_KEY))"
```

预期为 `search_enabled= True key_present= True`。若仍显示 `False`，检查 `.env` 是否有重复的开关行，以及当前终端是否设置了覆盖同名环境变量。

**步骤 3：启动现有数据库，不重置。**

```powershell
docker compose up -d --wait db
docker compose ps
```

预期 `db` 为 running/healthy。若提示 5433 端口冲突、密码或卷错误，停在此处并提供**不含密码**的错误信息。不要运行 `docker compose down -v`、导入脚本、`--reset-demo` 或 `init_local_env.py`。

**步骤 4：只读核对数据库。** 逐条执行：

```powershell
docker compose exec -T db psql -U travel_app -d travel_demo -Atc "SELECT count(*) FROM airports"
docker compose exec -T db psql -U travel_app -d travel_demo -Atc "SELECT count(*) FROM flights"
docker compose exec -T db psql -U travel_app -d travel_demo -Atc "SELECT count(*) FROM flight_offers"
docker compose exec -T db psql -U travel_app -d travel_demo -Atc "SELECT as_of FROM demo_state WHERE id=1"
```

已验收的完整样本应分别为 **115、33,121、15,374**；本次按“明天”演示，基准日应为 **2026-10-20**。若表不存在、计数不符或日期不同，先把这四项结果发来（不含账号密码），由我制定备份和日期整体平移方案；**不要直接重置已有订单与会话**。数据库正常且日期匹配后继续。

**步骤 5：在第二个 PowerShell 窗口启动真实 API。** 保持数据库窗口和 Docker Desktop 运行；用步骤 1 的文件管理器方法再打开一个项目根目录的 PowerShell，执行：

```powershell
.\.venv\Scripts\python.exe main.py
```

不要关闭这个窗口。浏览 `http://127.0.0.1:8000/health`，应看到 `{"status":"ok"}`；再打开 `http://127.0.0.1:8000/app`。健康检查只说明 API 进程在线，登录与对话成功才能分别证明数据库和模型可用。

**步骤 6：登录。** 页面账号填 `demo1`。密码为本机 `.env` 中 `DEMO_TRAVELER_1_PASSWORD` 的值，可在自己电脑上用记事本查看，不要复制到聊天、截图或公开仓库。`demo2` 对应第二名旅客及其单独密码。若登录失败，先确认访问的是 **8000**，而非旧的 **8001**。

## 4. 人工联调顺序

按顺序新建会话或在同一会话逐轮提问，记录回答是否与问题相关，不要只重复测试汉堡到巴塞尔：

1. “你好，你可以帮我做什么？”——应给一般对话答复，不应固定罗列两班航班。
2. “我现在有哪些已确认行程？”——应按登录旅客的订单回答。
3. “查询 2026-10-21 汉堡到巴塞尔下午的航班。”——应返回当前完整数据库中的候选，而非固定预览的 `SIM-1`／`SIM-2`。
4. “本平台机票取消规则是什么？”——应说明虚构平台政策及规则依据，不把它说成真实航司政策。
5. “推荐巴塞尔的经典地点。”——该城市有已核查目录，且本机搜索开关已开启，应尝试一次 `GlobalBasic`；若实时检索未核实新资料，仍可显示人工目录及回退提示。到阿里云控制台核对调用量，单凭回答内容无法确认是否成功发起付费搜索。
6. “把我的机票改签到第二班，并订第一家酒店，2026-10-21 入住一晚。”——若条件足够，应生成两张**独立待确认卡**；先核对对象、日期、金额及规则。没有逐笔确认前订单不能改变。你可以先点“拒绝”测试无写入；若点“确认”，这会持久改变本地虚构订单，之后须在“我的行程”和操作历史中核对。

页面不需要输入真实支付信息。若答复说已完成预订但没有确认卡及本人订单记录，记录该问题并停止该场景。若模型或搜索报错，请提供**脱敏后的**页面提示、提问、时间和 API 窗口错误类别，不要发送密钥、密码、完整 `.env` 或含令牌的网络请求。
