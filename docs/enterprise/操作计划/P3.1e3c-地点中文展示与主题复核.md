# P3.1e3c：地点中文展示与主题复核操作计划

> 编写日期：2026-10-21｜状态：用户已确认，功能分支已实施并验收；结果见《当前进度》。承接 P3.1e3b，处理缺陷 D14。本文件是事前计划，不授权重置正式数据库、合并本机 `main` 或推送 GitHub。

## 1. 依据、现状与目标

开工前已重读《产品需求》《软件架构》《当前进度》及 P3.1e 缺陷路线，核对干净的功能分支 `feature/p31-traveler-ui`、提交 `dd2e31b`。当前人工核查目录覆盖 95 座可达城市、190 个地点，每城 2 个。**190 条 `name` 均不是中文主名称，只有 60 条 `aliases` 含中文**；推荐器把 `name` 直接放进对话和结构化引用。主题也直接来自目录，上海豫园目前被标为 `nature`，旅客看到“自然主题”，与古典园林的人文属性不符。

本步目标：让中文旅客优先看到经过核查的中文地点名和合适的主题描述，同时保留原文名称、地点 ID、城市／国家、来源链接及核查时间。翻译与分类只影响只读推荐，不改机票、酒店、租车的模拟供给或交易规则。

## 2. 建议的数据方案

1. **不修改历史 v1/v2 目录**。现有加载器要求 v2 前 60 条与 v1 完全一致；直接改 `name`、别名或 `category` 会破坏该校验，也会模糊先前的核查记录。新增一个按稳定地点 ID 关联的版本化中文展示审查表，记录中文展示名、审查后的主题、名称证据、审查日期与审查备注；原文名称、原来源和地理归属继续取自 v2。
2. 加载器检查审查表与 v2 **一对一对应**，ID 无重复、无多余、无遗漏，中文名不是空字符串或仅机翻式占位；主题只能在已定义类别内。原文名称和所有别名继续用于联网匹配与同一地点去重，中文名只进入展示和旅客中文指代匹配，不能使新地点绕过来源校验。
3. 中文显示优先顺序：有依据的通用中文名／场馆官方中文名；常见中文别名可作为候选但需核对所指确为同一场馆；多义或不稳定译名应显示“核实的中文名（原名）”帮助识别。**如果没有可靠中文名称，不强行翻译**，保留原名并在审查清单注明原因；此类未决条目不计入“全部完成”。
4. 对主题建立简短人工判定标准：`nature` 用于以自然环境或植物为主要游览内容的地点；历史园林、宫殿、宗教建筑、博物馆分别核对其人文／建筑／历史侧重。每个地点只保留一个主主题，不凭名称里出现 `Garden`、`Museum` 等词机械归类。豫园列为必审反例，最终类别由来源内容核实后确定。
5. 中文展示名和审查主题进入推荐正文；结构化引用保留原文 `place`、来源 URL 与日期，并可增加兼容字段 `display_name`。旧客户端读取原字段不受影响。外部搜索结果仍只做目录匹配／新鲜度辅助，不能用搜索摘要直接替换人工目录事实。

## 3. 分批执行

### A. 基线与规则

1. 用户确认后核对工作区、真实服务与数据库状态；导出 190 条的 ID、城市、国家、外文名、现有中文别名、主题和来源类型审查清单。先在隔离环境记录上海、巴塞尔、伦敦及其他样本城市的原答复，作为对照。
2. 确定审查表字段、文本长度、唯一性和安全字符校验；列明中文名证据优先级（场馆／城市官方中文页、其他可信中文机构资料、可核对的现有中文别名）。DeepSeek 和阿里云检索可以帮助找候选，**不能单独作为定名或主题依据**。

### B. 190 条人工复核

1. 按现有目录顺序分三批约 60／65／65 条处理。先核对已有 60 条中文别名，再核查另外 130 条；逐条确认是同一城市、国家和具体场馆，防止同名地点、邻市地点与通用景点名称混淆。
2. 对每条记录打开原来源；原来源没有中文称呼时再找场馆／城市或可信机构的中文资料。保存简洁的审查结论和公开来源地址，不复制长篇网页内容，不保存个人信息。来源不可访问或译名冲突时标记未决并寻找替代来源，不靠模型补全。
3. 逐条复核主题与介绍是否一致。豫园、历史园林、建筑兼博物馆、城市公园等易混类别优先做交叉抽查；必要时调整展示主题与简短推荐理由，但不得加入未核实的新事实或票价、开放时间、路程。
4. 每批完成后运行目录结构校验、城市／国家与 ID 覆盖检查、中文名和主题差异审阅；发现一个地点显示错城市、错场馆或来源对不上，先停该批修复，不让不完整审查表成为正式读取源。

### C. 接入与回归

1. 加载器把 v2 的原始事实与审查表按 ID 合并，只有全量校验通过才启用中文展示；校验失败时保持安全降级并报告，而非由模型临时翻译。
2. 推荐正文以中文名为主、原名为辅助；中文指代、偏好筛选、联网目录匹配都指向相同地点 ID。检查“上海附近景点”“我想看历史／建筑”“豫园是什么类型”“伦敦经典地点”“切换城市”及原名／中文别名混用。
3. 回归 95 城市各 2 条的覆盖、来源域名与审查日期、目录过期降级、搜索超时与注入、跨账号与会话隔离；确认不产生游览订单卡，也不影响机酒车候选或确认流程。运行全套自动化、编译、依赖与页面检查。
4. 在隔离数据上用少量真实 DeepSeek 检查中文地点表达和跨轮理解，建议最多 20 次模型调用；如需要阿里云 `GlobalBasic` 寻找中文来源，最多 150 次公开地点查询，逐批记录次数及费用风险。专属检索单价未显示，实际以控制台账单为准；若有异常计费、来源污染或频繁无结果，暂停该检索路径并用公开原站点人工核对。

## 4. 验收、边界与交付

- 目标为 190/190 条都有核实过的中文主展示名、原文对照及审查主题；95/95 可达城市仍各有 2 个地点。任何无法可靠定名的条目列出 ID、原因和可行选择，不声称全量验收通过。
- 豫园不再被机械描述为“自然主题”；最终标签须与人工核对的场馆性质一致。正文与结构化引用指向同一个地点 ID，来源地址与日期仍可追溯。
- 不改 v1/v2 历史目录、原 SQLite、正式演示数据库、机酒车价格和交易政策；不新增游览预订。若确需数据库迁移或公开 API 的破坏性字段变更，先补充本计划并重新说明兼容方案。

验收后同步《产品需求》《软件架构》《当前进度》和目录审查记录，只在功能分支提交。公开差异不得带密钥、原始长网页或用户禁止的工具品牌字样。随后单独规划 P3.1e4：按用户真实对话做完整旅程、正式 PostgreSQL 重启与异常恢复验收；G-16 本机主线合并和 GitHub 同步仍须另行确认。
