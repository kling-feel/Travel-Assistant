# G-23 云端验收记录合并与 GitHub 同步计划

> 2026-10-28 制定并因 P3.4c3c1d 发现业务缺陷修订；**修订后的源码合并范围已经旅客确认**。原 P3.4c3c1c 最小方案不作为最终放行标准。本步骤只同步修复源码、回归测试和公开文档；云端镜像及服务操作依[P3.4c3c1e](P3.4c3c1e-机场地点修复与云端复验.md)另行执行，不上传数据库、备份、私钥或环境文件。

## 目标与范围

- 当前 `feature/p34c3c1b-release` 记录修复版发布与云防火墙核对；本机 `main` 和上次核对的 GitHub `main` 均为 `1118b95`。P3.4c3c1d 执行后再把真实业务验收记录和《当前进度》结果提交到同一功能分支。
- 本次把机场地点解析修复、对应回归测试、已审查的计划、验收记录、文档导航及核心文档状态并入 `main` 并同步 GitHub；公开提交说明、文件名与文档继续避免旅客要求排除的工具品牌字样。Git 忽略目录 `data/generated/`、环境文件、证书、备份及账号资料不进入提交。

## 操作顺序与停止点

1. 重读《产品需求》《软件架构》《当前进度》及 P3.4c3c1d 已完成的验收证据；核对功能分支改动文件、源码与测试差异、文档链接、空白差异、敏感信息形态、禁用字样和本机备份忽略规则。先如实记录第五轮酒店缺陷，不把部分验收写成通过。
2. 完整自动化回归通过后，在功能分支分别提交源码／测试与公开计划／阶段结果。通过 `git fetch` 与独立远端读取核对 GitHub `main`；若远端有新提交，先逐项审查并调整方案，不覆盖或强推。
3. 预期没有分叉时，以快进方式将本机 `main` 更新到功能分支；复核提交与文件清单，并在 `main` 重跑机场酒店、只读卡片边界及相关对话测试。原数据库和云端服务不在这一步启停。
4. 普通推送本机 `main` 到既有 GitHub 仓库，独立读取远端哈希与提交清单，确认一致后才将该主线源码用于 P3.4c3c1e 云端构建。最终云端验收记录若随后形成新的公开提交，沿用同样的检查、快进与普通推送流程，并把最终提交号写入《当前进度》。

## 风险与边界

- 不使用 `--force`，不改写既有历史，不删除历史计划与验收材料。若远端保护规则、权限或网络阻断普通推送，停止在本机已核对状态并报告具体原因，不绕过保护。
- GitHub 同步不决定云端是否在线；网站状态只按 P3.4c3c1d 的验收与旅客选择处理。云端运行中的私有配置与数据库不会因本步骤修改。
