# P3：页面、评估与交付分步路线

> 编写日期：2026-10-20｜状态：建议路线，待用户确认各独立阶段；本文件不授权实施。

## 起点与目标

P2.7 人工核实地点目录已发布到本机及 GitHub `main=99acbd1`，实时联网默认关闭。现有旅客 API 能登录、查询本人行程与产品、进行多轮对话、生成九类待确认交易卡并逐笔确认或拒绝。仓库还没有可操作的旅客页面，云部署说明和页面端到端验收也未完成。

P3 的目标是让求职作品能够从本机打开页面，真实演示“登录 → 对话／查询 → 查看卡片 → 逐笔确认或拒绝 → 核对本人订单”，再补齐部署和运行说明。所有航班、酒店、租车、金额与交易继续明确标为模拟；推荐只在对话中介绍有审查来源的可达城市经典地点，不加入游览产品或订单。

| 顺序 | 阶段 | 可交付结果 | 单独验收重点 |
| --- | --- | --- | --- |
| P3.1 | 旅客操作页面与本机闭环 | 同源轻量页面，覆盖登录、会话、对话、只读候选查询、行程、待确认卡、逐笔确认／拒绝及结果历史 | 两账号隔离、双卡独立处理、刷新后重新登录并恢复会话、错误和过期卡可见；本机浏览器完整演示 |
| G-16 | P3.1 主线发布 | 审查 P3.1 功能分支、合并本机 `main` 并普通推送 GitHub | 合并前后回归；远端与本机相同；公开内容和凭证检查通过 |
| P3.2 | 演示质量与运行交付 | 固定演示脚本、页面体验修正、成本／幻觉验收、Docker 本机启动与云服务器部署说明 | 新环境可按文档初始化并完成完整场景；故障恢复、备份与费用边界清楚 |
