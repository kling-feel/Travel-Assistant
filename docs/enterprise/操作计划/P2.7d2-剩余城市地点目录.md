# P2.7d2：剩余可达城市地点目录操作计划

> 编写日期：2026-10-20｜状态：用户已确认，功能分支已按本计划实施并验收；执行结果记于《当前进度》。本计划不授权主线合并、GitHub 推送或开启实时联网推荐。

## 1. 起点与目标

P2.7d1 已在功能分支建立首批 30 城市、60 地点的人工核实目录，并完成来源核查、隔离对话测试和数据库重启验证。可达城市总数为 95；剩余 65 城市尚无可信地点基线。P2.7 的整体目标是让旅客在对话中获得与可达城市、本人行程和偏好相符的经典地点介绍，地点事实可追溯，缺证据时明确降级，不提供游览预订或独立产品浏览。

本小步拟为剩余 65 城市各核实至少 2 个具体地点，新增至少 130 条，使目录覆盖 95/95 城市、至少 190 条地点。资料继续只保存公开地点名称、城市／国家、别名、主题、简短介绍、来源类别与页面、审查日期；不保存原始网页正文、价格、营业时间、坐标或旅客资料。

## 2. 分批实施

1. **开工复核**：重读《产品需求》《软件架构》《当前进度》和本计划；确认功能分支、工作区状态、已有目录、隔离测试库、忽略账本与默认关闭的实时搜索开关。先列出剩余 65 城市并与机场地理映射逐一比对，不用模型猜国家或城市。
2. **目录版本**：保留首批 `reviewed_places_v1.psv` 作为可回滚资料，建立覆盖全部 95 城市的新版本。新版本投入使用前，校验 30 个旧城市条目未丢失、每城至少 2 条、ID 不重复、域名和资料审查日期合规。切换读入版本须作为单独可审查的代码差异。
3. **三批人工核查**：按约 22、22、21 城市推进，每批先收集候选，再逐页打开来源并核对具体地点、所在城市／国家与主题。优先场馆官网、城市或公共机构；可核查百科可作补充并如实标类别。页面无法读取、与邻市混淆、混写多个场馆、仅为城市／榜单／酒店或信息冲突的候选均不入目录。对 Newark 与 New York、Victoria 与其他同名城市、Nagoya 周边地点、Washington, D.C. 等做额外交叉核对。每批完成即生成差异清单和失败原因，不合格条目不以编造资料凑数。
4. **对话与边界**：目录地点仍是唯一可进入回答的地点事实。实时搜索只能发现或核对目录候选；超时、无匹配、条目过期时回退或明确说明。对话仅介绍地点与理由；来源保留在 API 结构化字段，回答正文按既定偏好不强制附链接。无证据时不报票价、酒店距离、开放时间，不创建游览交易卡。航班、酒店和租车交易逻辑不改。
5. **验收**：每批检查城市、国家、域名、来源类别、重复、过期和注入边界；全量复核至少 130 条新来源。95 城市各至少 2 条合规地点；按文化／自然等主题与中英别名抽查对话，验证跨城、邻市、同名城市、跨账号、请求重放、政策与交易意图切换及断网降级。运行完整单元测试、两个演示日期的航线校验、依赖检查、路由检查；只有涉及持久化结构或会话路径的变化才重跑隔离 PostgreSQL 重启测试。再做一轮真实 DeepSeek 隔离 API 抽测并记录次数、tokens、估算及实际账单核对提示。
6. **收尾**：更新 README、来源核查记录和《当前进度》，核对公开差异、忽略文件与密钥，提交功能分支。若任一城市资料不足或关键对话场景失败，保持 P2.7 未完成并列出城市／原因。全部通过后单独提出整体 P2.7 验收、主线合并和 GitHub 同步方案；未经另行确认不执行。

## 3. 调用与费用边界

建议先以人工浏览可信来源建立 130 条资料，阿里云 GlobalBasic 作为候选发现工具而非事实来源。计划上限为 **180 次新增 GlobalBasic 搜索、30 次新增 DeepSeek 请求**；每次调用前预记独立忽略账本，每完成一批检查质量与费用。GlobalBasic 专属单价仍未显示，因此无法承诺人民币总额；发现异常计费、认证错误、限流或来源污染时停止相关调用并报告。DeepSeek 本小步预计不超过 **8 元**；以可见 token 用量估算并在接近上限时停机，实际费用以服务商账单为准。
