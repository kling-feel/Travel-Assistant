# P3.4c3c 云端正式发布与备份分步路线

> 2026-10-27 制定。G-21 已把隔离验收修复同步到本机与 GitHub `main`；云端正式镜像仍是修复前版本，公网应用和代理关闭。**本文是路线，不授权两个检查点一次性实施。**每个检查点另有计划，先向旅客说明、获确认后执行，结果写入《当前进度》。

## 当前依据与顺序

P3.4c3a 已证明一份保存在旅客 Windows 电脑的加密备份可在云端全新卷解密恢复；P3.4c3b 已在另一独立库验证九类交易和 11 轮修复场景。正式云端原库、账号、订单、证书卷均要保留。当前缺口是修复版正式镜像、修复后的真实模型抽样、展示网络和准确视口、控制台防火墙核对，以及持续自动异地备份。

| 检查点 | 范围 | 单独通过后可说明什么 |
| --- | --- | --- |
| [P3.4c3c1 修复版发布与短时展示验收](P3.4c3c1-修复版发布与短时展示验收.md) | 原库升级前另做服务器外加密备份；按已同步提交构建新镜像，保留旧镜像可回退；私有入口与少量真实 DeepSeek／阿里云检索复测；短时 HTTPS、授权账号、精确桌面／375／338 像素、来源、费用与资源检查；完成后关公网 | 当前正式镜像与主线代码一致，展示前开启、展示后关闭的人工流程通过；不宣称已有每日自动备份 |
| P3.4c3c2 不同地域 OSS 加密留存 | 先查旅客账号的地域可用性、按量单价、权限和预估账单；再单独获确认，配置私有桶／阻止公共访问、专用最小权限上传、客户端加密、至少七份日留存、失败提醒与新卷恢复抽查 | 连续备份、留存和恢复的实际证据齐备后，才可称具备自动异地恢复能力 |

先做 c1，使已修复的对话真正进入正式镜像；再做 c2，避免自动化脚本向尚未完成发布验收的原库写入或读取错误批次。c1 上线前仍需新增一份服务器外密文，所以 c2 的自动化不会成为发布前备份的替代品。两个检查点均不得自动平移演示日期、重建原库、删除卷或把模拟订单变成真实交易。

## OSS 预备判断与需旅客提供的内容

现有单份密文约 0.7 MB；七份约 5 MB，实际费用仍须按最终区域、存储时长、请求和下载量在旅客账号中核对。阿里云说明 OSS 按量计费包括容量、请求及公网下载，跨地域传输还有相应计费项；低用量阶段可先按量，不预购大容量资源包：[计费概览](https://help.aliyun.com/en/oss/billing-overview)、[资源包选择](https://help.aliyun.com/en/oss/purchase-resource-plans)、[流量计费](https://help.aliyun.com/en/oss/traffic-fees)。c2 优先比较香港以外的可用地域，不凭当前资料指定最终地区或价格。

桶应保持私有并开启阻止公共访问，上传主体只对专用桶与前缀授予必要权限；客户端加密后再上传，恢复私钥仍仅由旅客保存在本机和密码管理器。阿里云的[建桶说明](https://help.aliyun.com/en/oss/user-guide/create-a-bucket-4)和[权限说明](https://help.aliyun.com/en/oss/user-guide/permissions-and-access-control-overview)支持这些控制。轻量服务器是否能直接使用无长期密钥的实例角色，要在 c2 实际控制台核实；若不能，需在专用 RAM 身份的短权限与密钥轮换方案之间作安全选择，不把账号主密钥放在服务器。**现在无需购买 OSS、创建桶或发送 AccessKey。**

G-21 已同步当前代码；c1 或 c2 若新增通用脚本与公开文档，验收后再独立制定 G 计划，合并本机主线并同步 GitHub。服务器私有配置、备份、密文恢复私钥、账号文件与完整对话始终留在 Git 忽略位置。
