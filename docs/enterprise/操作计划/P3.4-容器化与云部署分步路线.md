## 当前事实与目标

本机演示入口已配置为 8000 经专用 Python 启动器连接 5436 新演示批次，数据库位于 Docker 命名卷，旧 5433 批次和备份保留。现行 `compose.yaml` 只定义 PostgreSQL；页面 API 在宿主机进程运行，启动器要求本机固定端口、批次摘要和 DeepSeek／阿里云配置。5436 容器曾意外退出，重启并核对后恢复，但原因未查明。规划时本工作台未检测到 8000 监听，实时运行状态须在实施前重新核对。因此现状已有演示启动路径，尚不能把“重启后能自动恢复”当作交付能力。

目标是在保持现有 FastAPI、LangGraph、PostgreSQL、模拟交易确认边界和简洁目录的前提下，得到可重复构建、可恢复、可观测的本机容器部署，再决定云端规格和开放范围。容器正常启动**不得**自动平移演示日期、导入或重置已有订单；新批次只能按显式备份、构建、验收和切换流程产生。云端仍是虚构平台和模拟交易，不接真实支付或供应商。

## 必须维持的边界

1. **数据**：旧批次和当前 5436 批次的卷、订单、会话及备份保留。隔离验收使用独立项目／卷；不得使用 `down -v`，不得在服务启动时执行导入、重置或日期平移。云端使用独立新批次，不直接复制本机旧卷或个人原始 SQLite。
2. **访问与密钥**：本机验收端口仅绑定 `127.0.0.1`。数据库不对公网开放。镜像及 Git 跟踪树不含 `.env`、本机密码、原始数据、备份和费用流水。云端凭证另配，不能复用本机 JWT 签名密钥和旅客密码。
3. **可用性**：数据库健康后再启动应用；应用须能报告自身存活与数据库就绪。重启策略只能覆盖容器退出和 Docker 引擎重启的部分情形，不能代替数据库备份、恢复演练或宿主机故障处理。容器异常退出原因仍应记录和排查，不把一次成功重启当作高可用证明。
4. **发布**：P3.4a 先在隔离环境完成，现有 8000 暂不切换；云端公网访问和主线推送各自另列门槛。公开文档、分支和提交说明沿用已确认的品牌与凭证审查规则；全部历史计划和进度保留。

## 需要旅客在 P3.4b 前判断的选择

建议首次云端演示使用**受控访问**：只给自己和面试官使用的链接，并保留登录、HTTPS 和费用上限；是否面向所有人公开、选哪家云厂商／地域以及可接受的月预算，待本机容器验收后结合当时官方规格与价格再决定。若目标是在中国大陆公开提供网站，还需在该阶段核实当时适用的备案及域名条件；此路线不预设具体厂商或价格。

本次仅制定计划，不构建镜像、不启停服务、不写数据库、不调用付费模型或搜索、不购买云资源、不合并或推送 Git。下一步执行 P3.4a 须旅客单独确认。
