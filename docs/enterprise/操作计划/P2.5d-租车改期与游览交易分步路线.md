# P2.5d：租车改期与游览交易分步路线

> 编写日期：2026-10-18｜状态：历史路线。P2.5d1 租车改期已完成；用户随后取消 d2～d4 游览产品与交易，**不得继续按本文实施游览部分**。现行范围见《产品需求》v0.8 与 [R-01 路线](R-01-后续阶段总路线.md)。

## 起点与目标

本机 `main` 已含 P2.5c 的八类逐笔确认动作及 v010 迁移，工作区在规划前干净；PostgreSQL 容器停止，现有演示数据和备份保留。旧图另有租车改期、游览项目搜索及预订/修改/取消，但旧游览 SQLite 表只有 10 条、5 个地点，没有价格、场次、旅客归属或订单，且旧“修改”会直接改共享推荐资料，不能作为新交易模型复用。

目标是复现这些**用户可见能力**：租车改期、可达城市的虚构游览产品搜索，以及本人游览订单的预订、修改、取消。全部写操作沿用结构化提案、本人逐笔确认、事务复核、结果重放和审计。真实地点的联网推荐继续只读，与虚构可预订游览产品分开；普通对话接入留给 P2.6。

## 已确认的业务规则

1. **租车改期**：仅调整本人已确认订单的取车和还车时间，车辆产品不变。原取车时刻前可确认改期；新取还车时间仍须在未来、顺序正确且落在产品可用窗口。沿用机场 IANA 时区和按实际经过时间每开始 24 小时计一日的算法。按新旧模拟总价补差或退差，不收额外改期费；旅客逐笔确认。
2. **游览供给**：覆盖目前有模拟航班可达的 95 个目的地城市；每城市 2 个明确标记为虚构的产品，每天上午/下午各一场，每场共享 12 个模拟名额。产品及场次随演示基准日确定性生成，约 30 天窗口；具体钟点和模拟单价范围在对应详细计划中审定。确认时复核名额，跨旅客并发不得超订。
3. **游览订单**：预订时选择产品、日期/场次和人数；每单 1～6 人，模拟总价为确定性每人单价乘人数。信息不足时后续助手应追问。本人修改只限**同一产品**的场次和人数；换产品需先取消旧订单再新订。修改按新旧总价补差或退差，不收额外修改费。
4. **游览退改截止**：修改和取消必须在当前订单场次开始前**超过 24 小时**确认；到开始前 24 小时的截止点及之后禁止。允许在开始前不足 24 小时新订，但确认卡明确提示其后不能修改或取消。允许期内取消模拟全退。按产品城市的 IANA 时区展示场次，截止判断使用实际时刻；待确认卡跨过截止点即失效。
5. **行程关联**：搜索与后续推荐优先结合本人已确认的航班/酒店城市和日期；可预订其他可达城市或不匹配日期，但必须提示不匹配，不静默阻止。真实地点推荐、开放时间和票价仍须联网来源；联网结果不能直接转成虚构交易产品。

## 建议分四步实施

| 步骤 | 独立交付 | 验收门槛 |
| --- | --- | --- |
| P2.5d1 租车改期 | 新动作、租车政策新版本及追加迁移；同车辆产品的时间调整、差额与本人确认 | 时区/DST、产品窗口、原取车截止、报价变化、跨账号、拒绝/过期/重放、并发卡与旧八类实库回归 |
| P2.5d2 游览产品与场次 | 按 95 城市确定性生成虚构产品、约 30 天上午/下午场及名额；只读搜索和政策草案 | 190 产品、每天 380 场、每场容量 12；重复生成不翻倍；两演示日期、分页/城市/日期查询与旧订单不变 |
| P2.5d3 游览预订 | 本人订单、`excursion_book` 卡及确认；场次名额原子复核和临近场次不可退改提示 | 确认前无订单、并发不超 12 席、人数/价格/日期、越权/过期/重放、重启恢复和行程读取 |
| P2.5d4 游览修改/取消及总回归 | `excursion_change`、`excursion_cancel`，严格 24 小时截止、模拟差额/全退、释放与转移名额 | 截止点两侧、时区、双卡竞争、同产品约束、全部 12 类动作真实 API 回归与旧脚本回归 |

四步只是分工建议，允许在每步详细计划中根据代码和实库证据调整；每步改动前先给用户完整操作计划并取得确认。功能分支验收、本机合并、远端推送分开规划与授权。P2.5d1 的独立事前计划见 [租车改期](P2.5d1-租车改期.md)。

## 共同工程边界

- 只追加迁移，不改写已在本机 PostgreSQL 应用的 v001～v010。改变现行政策时保留旧版本，旧待确认卡不得静默升级；迁移或演示重置前先只读盘点并核验 Git 忽略的备份。
- 产品 ID、价格、场次和容量由确定性代码与数据库给出，模型不能编造。客户端不能直接填旅客 ID、成交价或调用订单写服务。确认事务重查归属、版本、产品、时刻、金额及容量。
- 会写验收数据的脚本顺序运行，完成后清理临时旅客、订单、动作、结果和审计，复核两个演示账号与现有产品计数；正常服务或数据库重启不清空订单。
- 本阶段不接 DeepSeek、真实供应商、真实支付、联网推荐或页面；因此无需提供新的外部 API 密钥。P2.6 才把新版 LangGraph 接入这些受控查询/提案服务。
