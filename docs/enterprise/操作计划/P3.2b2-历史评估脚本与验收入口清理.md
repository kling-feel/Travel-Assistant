# P3.2b2：历史评估脚本与验收入口清理操作计划

> 2026-10-24 制定｜状态：旅客已确认，本地功能分支已实施；结果见[当前进度](../当前进度.md)。承接 [P3.2 总路线](P3.2-代码清理与目录重组分步路线.md)、[P3.2b1](P3.2b1-旧小样本与重置入口清理.md)。

## 1. 本步要解决的问题

P3.2b1 后，`scripts/` 尚有 51 个 Python 文件，其中 18 个 `evaluate_*.py` 是已结束阶段的一次性真实模型、搜索或对话评估入口。它们与旧计费辅助模块互相引用，容易被误认为当前运行或部署步骤。历史评估结论、费用与验收过程已写在文档中；旅客要求这些**计划、规划、进度和验收内容完整保留**。

本步只收敛脚本入口和测试依赖，不改变旅行助手的业务逻辑、API、数据库结构、样本数据、页面或九类逐笔确认规则。历史文档全文保留；已发布 Git 历史不改写。

## 2. 盘点后的处理边界

| 类别 | 拟处理方式 | 原因与前置条件 |
| --- | --- | --- |
| 现行数据与部署入口 | 保留 `build_network_fixture.py`、`build_recommendation_geography.py`、`import_network_data.py`、`init_local_env.py`、`migrate.py`、`verify_network_fixture.py`、`verify_network_data.py` | 仍服务于全航线样本、环境初始化、迁移或只读核验；不得改动样本哈希和迁移顺序 |
| 当前 README 所列核验脚本 | 本步保留全部现行 `verify_*` 命令，标注是否只读、是否需要隔离数据库 | 先保证操作指南可执行；其余历史 `verify_*` 的逐项精简留待后续单独计划 |
| 当前隔离付费验收入口 | 保留 `run_p31h3_metered.py` 及其模型、搜索次数与费用保护；保留 `tests/test_p31h3_meter.py` | 可供将来独立真实旅程验收；它不是日常启动命令，运行前仍需单独批准预算与隔离环境 |
| 现行只读审计 | 保留 `audit_p26d_secrets.py`、`audit_p31e5_schedule.py` | 分别用于公开内容凭证检查和正式排程只读检查；不得输出密钥 |
| 一次性评估 | 候选移除全部 18 个 `scripts/evaluate_*.py` | 当前服务和 README 不引用；先解除两项现行推荐测试对 `evaluate_p27c_sources.py` 的依赖，并核对所有跨脚本引用 |
| 旧评估专用辅助 | 候选移除 `audit_p27c_sources.py`、`p26d_metered_model.py`、`tests/test_p26d_metering.py` | 旧来源扫描和计费包装只服务已结束评估；必须先把仍有价值的“缺失用量停机、额度硬停止”断言转移到当前隔离验收入口 |
| 仍有历史核验引用的辅助 | 暂保留 `p26d_eval_guard.py` | `verify_p27d1_restart.py` 仍引用它；本步不为了减少文件数而连锁删掉该核验脚本 |
| 阶段专用预置和视觉准备 | `run_p31h4a_metered.py`、`run_p31h4b_metered.py`、`prepare_p31e4_visual.py` 先核对引用和可复用价值，再决定移除或保留 | 不把阶段名称当作唯一删除依据；不运行它们 |
| 其余历史核验与审计 | `verify_p27d1_restart.py`、`verify_p31e4_faults.py`、`verify_p31e4_journey.py`、`verify_p31e6_formal.py`、`audit_p31e4_flight_time.py` 暂保留 | 逐项比较覆盖和替代入口，留给 P3.2b3 或下一份独立计划；不在本轮扩大范围 |

两项当前测试 `tests/test_p27d1_catalog.py` 和 `tests/test_p27e_all_cities.py` 使用旧评估脚本的 `reachable_cities()`。实施时将这个**只读、从交付 SQLite 查询可达城市**的小函数迁到中性的当前核验模块，再改测试导入；不得用手写城市列表替代，以免推荐覆盖检查失真。

`tests/test_p26d_metering.py` 的旧价格拆分断言只对应旧评估模型；“缺失用量后停止后续付费请求”仍是安全边界。先对 `run_p31h3_metered.py` 增加等价测试，证实未知用量记账及后续请求拦截，再决定移除旧模块和旧测试。若现行逻辑不足，先修复并验证，不能直接降低保护。

## 3. 旅客确认后的执行顺序

1. 重读《产品需求》《软件架构》《当前进度》及本计划，核对本地功能分支和干净工作区；记录 229 项测试基线、交付样本与两份本机原始 SQLite 的大小和哈希。静态建立候选脚本的导入、测试、README、计划文档引用表。文档中的历史命令仅作为历史记录保留，不当作当前推荐命令。
2. 先迁移“可达城市”只读查询到当前核验模块，调整两项测试，定向运行推荐覆盖测试。再为当前隔离计费入口补“用量缺失即停机”和上限保护测试；定向通过前不删除旧评估或旧计费代码。
3. 按引用表移除无现行运行入口的一次性 `evaluate_*` 脚本及确证专用的旧辅助。阶段预置脚本若仍有独立可复用价值就保留并在索引中注明；若仅重复当前入口，则在引用和覆盖核对后移除。暂保留所有当前 README 核验命令和有未清依赖的历史核验脚本。
4. 新增 `scripts/README.md` 作为开发者命令索引：每个保留入口写明用途、是否只读、是否可能写隔离库、是否调用付费服务、必要前置条件；从根 README 链过去。标清当前常用命令与历史专项核验，避免复制旧文档命令误操作正式库。
5. 完整运行自动化并记录测试数变化；检查全航线两日期核验、Python 编译、页面脚本语法、依赖完整性、当前运行入口、当前 README 命令及 Markdown 本地链接。核对评估脚本删除后没有悬空 Python 导入。正式 5433 库最多只读核对，不执行导入、迁移、重置或订单操作；不启动付费评估，不调用模型和联网搜索。
6. 把逐项处理表、替代测试、命令索引、验证结果与保留待办写入《当前进度》。只在现有本地功能分支提交，提交前复核公开内容不含不应公开的内容；不合并 `main`，不推送 GitHub。之后再单独规划 P3.2b3／P3.2c，不把本步确认视为后续授权。

## 4. 验收和停止条件

- 当前启动、导入、迁移和 README 所列核验命令所需的 Python 模块均存在；全套自动化通过，并明确记录旧测试移除与替代测试新增的对应关系。
- `network_source.sqlite`、两份 `data/source/` 本机原始库的哈希不变；正式数据库的订单和演示基准日不因本轮变化。历史文档正文不删除，本地链接仍有效。
- 若候选脚本仍是运行入口、推荐覆盖或隔离计费保护所必需，先保留它并在索引中说明；若缺失用量不能可靠拦截后续付费请求，停止旧计费模块清理并先修复。
- 本轮不测试付费 API、不写正式数据库、不操作正在运行的 8000 页面。需要隔离库或额外真实调用时，先另出计划和费用／端口边界供旅客确认。
