# P3.4c2e 云端数据库初始化与授权账号操作计划

> 2026-10-27 制定并获旅客确认，现已执行；结果见[验收记录](../P3.4c2e-云端数据库初始化验收记录.md)。承接已验收的 [P3.4c2d 非公开镜像构建](P3.4c2d-云端私有配置与非公开镜像构建.md)。本阶段在香港主机建立**第一套云端虚构数据批次**，预置授权账号；网站、80／443、HTTPS 和真实模型／联网调用留给 P3.4c2f。

## 目标与现状

- 已有经过哈希核对的发布包、独立私有 `cloud.env` 和三张应用相关镜像。服务器实际可见内存约 1,613 MiB，未配置 swap；目前没有业务容器和数据卷。上轮镜像构建时 SSH 连接意外断开，原因尚未查明，因此不能凭客户端断线判断云端任务失败或直接重试。
- 只使用固定 Compose 项目 `travel-cloud` 的新卷。云端数据、账号和密钥与本机 `8000→5436` 演示环境完全分开。虚构数据在首次初始化时按执行当天的中国标准时间生成；批次建立后，普通重启不得自动平移日期或改写已有订单。
- 登录页公开后的访问范围仍是旅客已决定的“知道网址可打开登录页，只有预先授权账号可登录”。本阶段不会开放该登录页。

## 执行顺序与检查点

1. **复核与执行日**：重读《产品需求》《软件架构》《当前进度》及本计划，检查功能分支、云端发布提交和私有配置预检结果；经已核验的专用 SSH 密钥核对主机身份、Docker／Compose 版本、内存、磁盘和端口。核对服务器侧 `travel-cloud` 是否确无同名容器及数据卷。若已有卷或数据库，立即停止创建，先只读调查；不得套用“新空库”流程。若 `cloud.env` 中批次日仍为 2026-10-26，而执行日已是 2026-10-27 或更晚，在**建库前**只更新 `DEMO_BATCH_DATE` 为当日，保留其他凭证字段，重新运行不回显密钥的预检；若日期再跨天，以真正执行初始化的当天为准。
2. **使一次性任务可追踪**：先实现并离线检查一个受控的远程任务入口，用独立任务标识、互斥锁、私有日志和原子完成／失败标记记录启动、退出码与阶段。长时间初始化由系统服务管理，SSH 断开后仍可读取任务状态。正式触发前测试“断开客户端再查询状态”的无数据写入路径。日志不得包含环境文件、密码或 API Key。任何断连后，先核对任务状态、容器、数据库和批次清单，**不自动重新运行初始化**。
3. **建立空库并备份**：统一使用 `scripts/cloud_compose.py`，同时叠加正式 2 GiB 资源覆盖文件；只启动 `db`。核对容器项目标签、独立 `travel_pgdata` 挂载、健康状态，确认未发布数据库宿主端口，公开 schema 尚无业务表。随后运行已有 `empty-backup` 动作，检查 PostgreSQL 自定义格式、备份目录、文件大小和 SHA256，并确认备份卷与数据库卷分开；备份不放入 Git、镜像或聊天。若健康检查、空库或备份任一项失败，保留现场、停止导入。
4. **显式初始化一次**：通过上一步验证的任务入口运行现有 `init` 动作。它先检查空库、已验证的空库备份和不存在的批次清单，再执行 v001～v014 迁移及虚构航班／酒店／租车供给导入，最终写入批次清单。全过程只运行这一项高内存任务，监测 available 内存、磁盘、容器退出状态及内核 OOM；不并行启动应用、代理或账号任务。若初始化失败或 SSH 中断，先读取标记、任务退出码、数据库摘要及清单；即使清单缺失，只要库已非空，也不得在原卷上再次执行 `init`。需要重新建批次时，保留失败卷和证据，另立新项目／新卷及独立计划。
5. **只读核对导入结果**：用凭证脱敏的数据库摘要核对批次日、fixture SHA256、供给摘要、14 个迁移版本、115 座机场、33,121 条航班，以及酒店／租车供给和初始订单；比对批次清单中的日期、备份哈希与数据库摘要。检查初始化后仅有两名种子账号，尚无非种子账号，且会话／动作／用量记录为空。数量不符、数据时间不符合当前演示批次或出现意外业务记录时暂停账号操作。
6. **建立授权账号**：先创建旅客持有的管理展示账号，再创建独立的面试展示账号；两者使用不同随机密码，密码仅写入服务器 Git 忽略的私有 `cloud-accounts` 文件，目录 `0700`、文件 `0600`，不在终端、聊天、提交或镜像中打印。读取数据库状态和对应凭证文件后，执行 `disable-seeds` 停用 `demo1`／`demo2`。只读核对两个新账号有效、两个种子账号无效，订单仍无意外变更。若 SSH 中断，先核对账号是否已创建和凭证文件是否存在，不能盲目重复 `create` 或轮换密码。账号名称在执行前检查与现有记录无冲突；不需要旅客把密码发给我。
7. **留存恢复依据并收尾**：对已初始化且完成账号配置的云端库创建 `pg_dump -Fc`，检查 `pg_restore -l`、文件大小和 SHA256，保留在服务器私有备份位置，并记录数据卷／备份卷身份与批次摘要。本机离线核对可重复的摘要检查和任务状态检查；若需修代码，仅在当前功能分支提交经过测试的辅助脚本与文档。更新《当前进度》中的实际数量、任务状态、资源峰值、备份和遗留风险。云端正式数据及本机 `8000` 服务不因本步清理而删除或重置。

## 验收与停止条件

- 通过标准：目标确为新项目新卷；空库备份经过格式校验；初始化任务有可查询的成功退出状态，数据库摘要和批次清单一致；两名授权账号有效、种子账号停用；没有模型／搜索付费请求，没有应用或代理容器，也没有数据库、8000、80／443 新增公网监听；无 OOM，磁盘和内存仍可支撑下一阶段。服务器上的初始化后备份已验证格式与哈希。
- 若 `cloud.env` 日期不符、现有卷身份不明、镜像与发布提交不符、数据库不空、备份无效、内存／磁盘不足、任务状态无法确定、账号文件与数据库不一致，暂停并报告证据。不会使用 `down -v`、重置正式卷、把旧本机库复制到云端，或在非空库上重复初始化。
- 本阶段的服务器内备份是恢复准备，**不是异地可恢复验收**。服务器外加密备份和全新卷恢复将在后续 P3.4c3 独立验证；此前不宣称云端具备灾难恢复能力。

- P3.4c2f 再独立规划应用／代理启动、可信 HTTPS、根域与 `www` 跳转、授权登录及少量真实服务联调。公网开放前重新核对备份状态与服务器资源。
