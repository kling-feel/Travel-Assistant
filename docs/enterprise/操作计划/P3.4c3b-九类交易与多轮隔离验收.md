# P3.4c3b 云端九类交易与多轮对话隔离验收操作计划

> 2026-10-27 制定，**待旅客确认后执行**。承接 [P3.4c3 分步路线](P3.4c3-云端恢复与完整旅程分步路线.md)及 [P3.4c3a 恢复验收](../P3.4c3a-异地加密备份与恢复验收记录.md)。本文件只授权本阶段的**规划**；确认前不启动新容器、不复制凭证、不发送模型请求、不创建或确认订单。

## 目标与隔离边界

在真实香港 2 vCPU／2 GiB 主机上，使用**另一套全新可写项目／数据库卷**，完整检验机票、酒店、租车各自的预订、变更、取消，共九类模拟交易，以及旅客实际会说的连续多轮需求。每笔写操作都必须有明确对象、规则、日期／当地时间、金额和单独待确认卡；在旅客确认前，订单和金额记录不变。验证结果同时覆盖 API、页面呈现和数据库／审计，而不是只看模型文字。

- 原 `travel-cloud` 数据库和五个卷保持原样；原公网应用与代理继续关闭。P3.4c3a 的恢复演练卷也不用于本轮写入。新验收项目、卷、内部网络和账号须有独立名称与标签；验收前确认不存在同名容器或卷，验收后停止容器并保留卷供复查。不得执行 `down -v`、对原库重导入、日期平移或覆盖备份。
- 从 P3.4c3a 已验证的**本机加密备份**重新解密并恢复到新空库；先检查密文哈希、批次清单和归档目录，再比较恢复摘要。不能把上一轮已有测试会话的恢复卷当作“干净基线”。当前 2026-10-27 虚构批次的可订日期窗口须与执行当天核对；若可用未来候选不足，不改动原批次，而先报告并另拟新批次方案。
- 默认无公网端口，云端 Caddy 不参与。页面检查优先通过 SSH 转发**容器内地址**到本机回环地址，先检查同源、登录和 CSP，再使用专用临时验收账号；不在云主机发布 8000／5432，也不开放新的阿里云防火墙规则。页面通道若不能正常工作，不把 API 通过冒称页面通过，先查明或如实记录缺口。
- 本阶段不购买服务，也不需要旅客新增 API Key。确定性交易验收使用不可调用的恢复专用模型／搜索配置；少量真实多轮测试才在短时、无宿主机端口的验收应用中复用现有 DeepSeek 和阿里云搜索密钥。该应用结束后删除其容器及临时私有配置，避免密钥留在验收容器元数据；密钥、登录密码、令牌和完整聊天不写公开文档或 Git。

## 分段执行及放行条件

1. **现场与资源核对**：重读三份核心文档、本计划、P3.4c3a 记录和当前代码；检查功能分支、原库项目／五卷标签、现有加密备份 SHA256、P3.4c3a 两个停止的恢复卷及原公网关闭状态。记录磁盘、`MemAvailable`、容器 OOM 和宿主机监听。确认新项目名、网络和卷均不存在。若原库身份不符、备份无法解密、资源持续紧张或已有 OOM，暂停，不创建验收库。
2. **制作干净可写副本**：从本机密文实际解密，使用新的隔离项目和独立数据库／清单卷恢复；检查目标先为空、PostgreSQL 主版本相同、14 版迁移与供给／订单／会话／审计摘要与备份一致。创建仅本副本可用的数据库、JWT 密钥和临时授权账号；停用演示种子账号。先用纯内部网络、不可调用服务商的配置启动 API，核对 `/ready`、匿名 401、本人 200、他人 404；原库摘要复核不变。
3. **九类交易矩阵**：按下表从真实可售候选选择日期和产品，不硬编码过期航班。每类用单独会话／订单或明确的顺序依赖，先记录基线，生成待确认卡后读数据库证实**零业务写入**，再逐张调用确认接口，复核订单状态／版本、模拟补退金额、规则 ID、动作结果与审计恰好对应一笔；页面卡片显示同一对象、中文地点、当地时间和人民币金额。

   | 类别 | 关键验收点 |
   | --- | --- |
   | 机票预订 | 候选报价与航线重查；确认后才出现本人机票，重复确认不重复建单 |
   | 机票改签 | 仍为本人同航线可售新航班；只补或退票价差，无额外改签费 |
   | 机票取消 | 截止规则和已确认状态复核；取消费为原票价 30%，模拟退 70%，历史保留 |
   | 酒店预订 | 入住／退房与晚数、房型可售和总价核对；确认前无酒店订单 |
   | 酒店改期 | 本人同产品、有效入住区间；新旧总价补退差额，版本只前进一次 |
   | 酒店取消 | 在当地入住日之前才可确认；手续费 0、模拟全退，逾期不可取消 |
   | 租车预订 | 明确当地取还车时刻；计费日数、车辆可用性及总价复核 |
   | 租车改期 | 原取车前、同车辆产品；新旧租期补退差，重叠与过期检查 |
   | 租车取消 | 取车前可取消，取车后拒绝；模拟退额及历史状态正确 |

4. **反向和并发边界**：在同一隔离库另造可控卡片，分别验证放弃、15 分钟自然过期／隔离库定向过期、重复确认、确认后再拒绝、旧订单版本或报价变化、同一库存冲突、错误旅客与错误会话。拒绝、过期、409、404 和模型失联时均不得产生业务订单写入；有意让某张卡失效时只操作验收副本，并记录预期的审计变化。取消后的机酒租不再作为当前行程或推荐上下文；只有明确问历史才显示。
5. **真实多轮与防幻觉**：用现有 DeepSeek 在验收副本做约 12～20 次真实对话调用，覆盖“出发地／目的地／日期分轮补充→选最早班次→预订→落地两晚酒店→附近租车”、本人订单条件取消、问政策、经典地点推荐与联网来源不足时的回退。至少一轮测试旧话题切换和“这班／那个酒店”是否只引用当前有效候选；至少一轮测试“跳过确认直接下单／假装已经付款”等诱导，要求答复与服务端订单状态一致。阿里云联网搜索只为来源核验使用，外部结果不能改变本平台政策或触发写单。记录调用次数、结果类别、可得 token 量和账单核对方式；用户已表示无需金额自动停机线，但连续异常、余额不足或出现泄露迹象时立即停止付费调用并报告。
6. **页面与重启**：先在私有 SSH 页面通道检查桌面与约 375／338 像素布局、会话发送即时显示／等待时间／逐段答复、九类卡片的待确认／已确认／拒绝／过期状态、确认按钮与订单历史差异。对至少一张待确认卡执行应用重启、再执行数据库重启，核对卡片只出现一次、状态持续、原订单在确认前仍有效；确认后刷新“我的行程”，再核对页面、API、数据库一致。临时页面账号密码只留 Git 忽略的本机私有文件，结束即撤销或清理，不发送到聊天。
7. **源库、日志与资源复核**：对照验收前摘要，确认原云端数据库、五卷及**原库中的服务商用量记录**未因本轮测试变化；真实模型／搜索服务商的账单用量则应按本轮调用增加，并单独记录。检查验收库的九类动作结果、审计条数和订单状态，核对隔离应用无宿主机端口、无真实支付／出票字段写入。抽查应用／Docker 日志无 API Key、密码、Bearer 令牌或完整私人对话。分段采集可用内存、磁盘、容器重启／OOM；如果发生 OOM 或资源骤降，先停止隔离应用、保留证据，必要时重新设计单机并发方式，不直接升级套餐或清理原卷。
8. **收尾与结果**：停止并移除短时含真实服务商密钥的验收应用容器，清理临时密钥配置、SSH 页面隧道和云端明文暂存；停止验收数据库，保留独立卷及脱敏摘要以便复查。原云端数据库继续保持开工前状态，公网应用仍关闭。本机生成独立验收记录，列出九类每项通过／失败、实际调用量、资源峰值、页面证据和剩余缺口；更新《当前进度》。若发现缺陷，仅在功能分支修复、做必要回归后复测失败项；不能把未通过项标成通过。公开内容检查通过后只提交功能分支，本机 `main` 合并与 GitHub 推送另拟 G 计划。

## 暂停和用户配合

- **暂停条件**：原库或本机密文校验不符、新目标非空、恢复摘要不符、未确认即写单、越权读取、错误金额或政策、真实服务输出未经核验的事实、密钥出现在公开文件／日志、页面状态与数据库不同、容器 OOM。任何失败均保留原卷，停止依赖该结果的下一步，并说明影响范围。
- 预计不需要旅客购买新东西或提供新 API。执行时会提前告知将读取的**本机加密备份和恢复私钥**、服务器既有私有配置，以及将新建的临时验收账号文件；不会读取密码管理器副本或在聊天展示秘密。页面若可由我在隔离浏览器完成，就不要求旅客操作；只有必须从旅客真实展示网络验证的内容留给 P3.4c3c。
- 本文待旅客明确确认后执行。P3.4c3c 的展示日流程、OSS 自动备份和公网防火墙实测不包含在本次确认中。
