# P2.7b：真实联网来源与推荐验收操作计划

> 编写日期：2026-10-19｜状态：已按用户授权执行 24 次搜索并完成离线回归；真实来源评估发现阻断项，本阶段不通过、不合并主线。

## 1. 目标、范围和交付

把 P2.7a 的 `RecommendationProvider` 接到真实搜索，使旅客在对话中看到当前模拟航班可达城市的经典地点、可核对的推荐依据、可点击来源和检索时间。继续依据服务端认证身份读取本人已确认行程；推荐只读，景点预订、改期、取消仍不支持。航班、酒店、租车九类交易及逐笔确认规则不变。

按用户最终选择，使用阿里云 CleverSee 联网搜索的国际版 `GlobalBasic` 作为第一种可替换提供方，保留 DeepSeek 作为主模型。阿里云[产品说明](https://help.aliyun.com/zh/document_detail/3057228.html)介绍国际版覆盖国内及海外信源；[接口文档](https://help.aliyun.com/zh/document_detail/3062218.html)已列出 `GlobalBasic` 和网页标题、链接、摘录等字段。当前[公开计费页](https://help.aliyun.com/zh/document_detail/3061214.html)与用户控制台均未显示 `GlobalBasic` 单价，不能沿用 `GlobalAdvanced` 的价格估算。用户已明确要求继续真实联网测试，因此以调用次数控制本轮测试；金额只能事后按阿里云账单核对，不能声称实际金额不超过原估算。具体效果以真实样本核验，不把官方产品描述当作质量结论。

本阶段交付：联网适配器、配置示例与 README 操作说明、自动化与受限真实检索报告、来源人工抽查记录、更新后的《当前进度》。不做游览产品页、订单、数据库迁移或云部署。若实际检索无法可靠支持地点事实，就保留明确的证据不足回复并报告缺口，不为了凑齐 2～3 个地点而编造。

## 2. 用户准备与配置方法

这些步骤在用户确认本计划后、首次真实联网测试前执行；密钥不要发到聊天，也不要提交 Git。

1. 按[阿里云官方开通步骤](https://help.aliyun.com/zh/document_detail/3057186.html)，用自己的阿里云账号完成实名认证、开通 CleverSee 服务，并在控制台确认国际版可用、余额/试用额度和账单设置。开通服务可能涉及实名及后付费，用户自行阅读控制台协议并决定是否开通；项目不会代办。
2. 在 CleverSee 控制台的 API Key 页面为本项目创建专用密钥。仅使用 HTTP API Key，不需要创建云账号 AccessKey。不要在控制台测试时把个人行程或订单发给搜索服务。
3. 在项目根目录本机 Git 忽略的 `.env` 新增一行 `ALIYUN_IQS_API_KEY=<你自己的密钥>`；保留现有 DeepSeek 配置。若 `.env` 已存在，只新增这一项，不覆盖数据库、JWT 或模型配置。公开的 `.env.example` 只写变量名和占位符，不写真实密钥。
4. 保存后只回复“已配置”，不要粘贴密钥或截图中的完整密钥。执行时只检查“变量是否存在／能否认证”的布尔结果，不在终端、日志、异常或报告中输出密钥。若暂时不申请密钥，先完成不依赖联网的代码和固定响应测试；真实联网验收保留为未完成，不视为 P2.7b 通过。

开工前须重查配置名称、接口及计费，并在 Git 中确认 `.env` 仍被忽略。用户已完成本机配置并确认执行；执行中仅检查密钥存在性，未读取或输出密钥内容，已完成一次连通性检查。用户后续明确免除批量检索前核价要求；继续执行时不输出密钥或原始对话。

## 3. 开工检查与 Git 顺序

1. 收到明确确认后，重新打开《产品需求》《软件架构》《当前进度》和本计划，核对 P2.7a 的提交、工作区、`main` 与 `origin/main`、测试报告及可达城市基线。若需求、服务商计费或主线发生实质变化，先改本计划并请用户重新确认受影响部分。
2. 从 P2.7a 已验收的本地功能分支建 `feature/live-source-recommendations`，仅在新分支实施；以后新建分支、提交说明和标签采用项目功能名称，不使用开发工具品牌字样。任何未提交的文档改动先核对归属；不混入演示库、原 SQLite、`.env`、账本、原始网页或原始模型对话。功能提交前看差异、敏感字段和 staged 文件清单。本分支已创建，密钥仅做存在性检查，不回显。
3. 优先用纯内存/假 HTTP 响应验证适配器。若需要真实 PostgreSQL 回归，仅用经过基线核验的隔离 `travel-eval` 库，先确认容器、端口、备份与账号计数；测试后清理并复核。已核实 Docker CLI 和服务均为 29.8.2；受限命令环境无法执行用户目录中的 CLI，获准的命令环境可执行。实库测试仍须另核对 `DATABASE_URL`，不得启动、重置或写入正式演示库，也不写原 SQLite。
4. P2.7b 通过后只提交功能分支供审阅；本机 `main` 合并与 GitHub `main` 同步须写入同一份 G-15 事前计划并经确认。推送前另做公开文件的品牌字样清理和 Git 历史/远端差异审查；不推送本地功能分支或使用强制推送。

## 4. 实施步骤

### A. 搜索适配器与受控输入

- 在现有提供方接口下增加 CleverSee 适配器；必须配置密钥和显式启用开关才用于对话，未配置或未启用时沿用 P2.7a 明确降级。真实来源质量验收前默认关闭，避免自动产生未知费用。使用官方固定 HTTPS 搜索端点、`GlobalBasic` 引擎、最多 5～8 条结果、`summary=false` 以避免增强摘要附加计费；仅截取验证所需的网页摘要/正文，不保存原文。设置短超时、响应大小上限和明确错误分类。无自动重试，尤其不在 429／额度不足后重试。
- 搜索请求只含公开城市名及受限的主题词，例如历史／自然，不发送旅客姓名、账号、订单、酒店、行程日期、令牌、完整对话或系统提示。模型提供的城市仍须由旅客原话或本人可信行程核对；搜索商不能扩大 95 城市业务范围。
- 解析官方返回的 `pageItems` 标题、链接、摘要和可选正文；按请求数、引擎和控制台账单计量。检索仅产生只读证据，不接触交易提案、确认服务或政策规则表。测试以可注入 HTTP 客户端/假响应进行，避免正常回归消耗真实请求。

### B. 来源筛选与事实约束

- 在 P2.7a 的 URL、城市、摘录、时间和数量校验基础上，对标题、域名、地点名称和摘要做更严格的对应核对。来源标题像“官方”不能独自证明其为官方站点；只在可核实域名归属时标为官方。优先城市旅游局、景区或公共机构资料，搜索结果与地点/城市不对应时丢弃。
- 网页标题与摘要是外部数据：截断、去控制字符，拒绝指令式内容、伪造政策或订单、明显广告/低质聚合站；不得把网页文字塞进系统指令或写工具参数。链接只展示给用户，不由服务端任意抓取用户提供的 URL 或跟随重定向访问内网。
- 每个地点必须有直接支持“这个地点属于该城市以及推荐主题”的可核对来源；弱证据只说能核实的内容。推荐理由避免开放时间、门票价格、实时交通、距离、库存等未获证实事实。固定格式逐项展示来源 URL 和 UTC 检索时间，最多 3 项；只有 1 项可靠时只给 1 项。保存现有轮次中最小引用元数据，不长期保存网页原文。
- 查询“酒店附近”时，没有可信地点坐标仍明确不能判断距离；即使检索到坐标，也先按来源和地理归属核查，再由服务端计算直线近似值。若本阶段无法可靠取得坐标，就不加距离功能。

### C. 异常与成本护栏

- 对无密钥、401、429、超时、5xx、畸形结果、零结果、低可信/相互矛盾来源分别给清楚而保守的降级回复；不可达城市先由本地数据库判断，不为其检索地点。推荐失败不得改变现有会话归属、卡片或订单。
- 真实测试按小批次执行，先前已有 1 次 `GlobalBasic` 连通性检查，再做来源质量和边界样本。**CleverSee 累计最多 25 次搜索**；模型复核 **最多 12 次 DeepSeek 请求**，其新增费用停机线仍为 **0.5 元**。原拟搜索费用 2 元、合计 2.5 元上限在 `GlobalBasic` 价格不可见时无法实时核算；用户已明确要求在此情况下继续联网测试，故不再把无法核实的金额写成可执行停机条件。逐次保存脱敏计数、耗时和结果，禁止自动重试；若账号余额、扣费或限流出现异常立即停止。实际费用待控制台账单核对。本次授权只覆盖 P2.7b 已计划的来源验收，不延伸到日常无限量调用。

## 5. 验证顺序和通过条件

1. 假 HTTP 响应测试覆盖成功、字段缺失、超时、401/429/5xx、恶意摘要、伪造官方标题、畸形/内网 URL、重复地点、城市不符与费用计数；确认搜索请求不含任何旅客/订单信息。接口重放应保留同一引用结果，不重复搜索或建卡。
2. 用实际模拟航班数据检查 95 城市覆盖边界；至少抽样东亚、欧洲、中东和美洲不同可达城市，以及历史、文化、自然偏好和无行程/有本人行程。逐项人工打开来源，记录地点与城市/主题是否受该页面支持、链接是否可用、是否为官方；若来源无法支持具体理由则修正过滤或降级。不可达城市、跨账号、景点预订误分流和推荐后九类交易分别回归。
3. 完整自动化测试、两日期航线离线校验、编译、依赖检查与 API 路由检查通过。若隔离 PostgreSQL 可用，补真实会话重放/重启和账号隔离核验；测试记录清理后与基线比对并停止隔离库。若不可用，明确记录缺项和对 G-15 的影响。
4. 真实联网样本中，凡给出具体地点，都有可打开、内容支持地点/城市及所述理由的来源和检索时间；不得凭标题/摘要假定官方身份。无来源不得报地点事实，网页内容不得改变交易或政策权限，景点请求不得生成订单卡。出现上述任一高影响失败，P2.7b 不通过，先修复复测并在《当前进度》记录。

**执行结论（2026-10-19）**：单次接口连通及多地区来源检索可用；24/25 次请求后停止。人工抽查发现清单当地点、城市页当地点、美国 Georgia 的 Rome 混入意大利 Rome 等误判；已定向过滤并用真实 Rome 复测，但 95 城市国家上下文和跨语言同名去重仍未完成。自动化 80 项通过，P2.7b 保持未通过，联网开关默认关闭。详细来源和下一步见《当前进度》及 P2.7c 事前计划。
