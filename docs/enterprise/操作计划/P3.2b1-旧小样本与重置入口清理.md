# P3.2b1：旧小样本与重置入口清理操作计划

> 2026-10-24 制定｜状态：旅客已确认，本地功能分支实施；结果见[当前进度](../当前进度.md)。承接 [P3.2 总路线](P3.2-代码清理与目录重组分步路线.md) 和已完成的 [P3.2a](P3.2a-旧实现剥离与本机数据归位.md)。

## 1. 为什么先做这一步

当前本地功能分支已移除旧图及旧 SQLite 写工具，但 `scripts/` 仍有 55 个 Python 文件。仓库交付和运行使用 `data/fixtures/network_source.sqlite`（115 个机场、33,121 班航班），旧 `data/fixtures/demo_source.sqlite` 只有 24,576 字节，服务运行、现行导入及部署均不读取它。`build_demo_fixture.py → import_demo_data.py → seed_p1.py` 仍提供一条会把数据库恢复到汉堡—巴塞尔小样本的旧流程，README 还保留了该流程的操作说明，容易误用。

但 `scripts/migrate.py` 目前直接从 `migrate_p1.py` 导入 `main`，所以 `migrate_p1.py` **不能直接删除**。另外，旧小样本的两项测试保护了跨夏令时的下午航班和“存在待确认动作时拒绝重置”；这些断言应转移到现行全航线与重置入口后再移除旧测试。历史评估脚本与当前测试仍有交叉引用，留给 P3.2b2 单独审计。

## 2. 拟保留、替换与移除的对象

| 处理 | 对象 | 依据 |
| --- | --- | --- |
| 保留 | `data/fixtures/network_source.sqlite`、`data/source/` 两份本机原始 SQLite、`scripts/build_network_fixture.py`、`scripts/verify_network_fixture.py`、`scripts/import_network_data.py`、`scripts/verify_network_data.py` | 当前可复现数据链；原始库只供可选再生成，且 Git 忽略 |
| 保留 | `services/demo_pricing.py`、`scripts/migrate.py`、`migrations/` 全部已发布版本、现行业务测试 | 虽有早期命名，当前服务、迁移和价格核算仍依赖 |
| 先迁移用途 | 将 `migrate_p1.py` 中当前迁移入口实现收回 `scripts/migrate.py`；将旧两项测试有价值的跨时区排程与重置防护断言改为针对现行导入链 | 防止删除后启动或安全边界退化 |
| 候选移除 | `scripts/build_demo_fixture.py`、`scripts/import_demo_data.py`、`scripts/seed_p1.py`、迁移用途转移后的 `scripts/migrate_p1.py`、`data/fixtures/demo_source.sqlite`、仅验证旧链的 `tests/test_import_demo_data.py` 与 `tests/test_p1_seed.py` | 当前运行入口和交付样本均不使用；旧脚本可能误重置演示库 |
| 条件移除 | `requirements.txt` 中的 `pytz` | 静态引用再次确认仅旧导入器／旧测试使用，且现行 `zoneinfo` 测试能覆盖跨夏令时行为后才移除 |
| 本步不动 | 历史评估、计费与验收脚本，以及它们依赖的测试 | P3.2b2 逐项分组，避免误删仍被测试使用的辅助代码 |

以上是候选清单；实施时若发现其他当前引用，先补迁移或保留对应文件，不因文件名带旧阶段编号而直接删除。历史计划、验收文档和 Git 历史全文保留。

## 3. 确认后的执行顺序

1. 重读《产品需求》《软件架构》《当前进度》和本计划；确认 `feature/p32a-legacy-cleanup` 工作区状态、主线与远端引用，记录 228 项测试基线、现行迁移导入关系、小样本与全航线文件大小和 SHA-256。只读检查正式 5433 库的演示基准日，不运行迁移或导入。
2. 静态搜索所有旧小样本、三个旧脚本、`migrate_p1.py` 与 `pytz` 的代码、测试和 README 引用。先把正式迁移实现在 `scripts/migrate.py` 内保持同一顺序与版本判定；13 个已有迁移文件、迁移版本号和表结构不改。验证 `scripts/migrate.py` 可导入、列出的迁移数和版本与改动前一致。
3. 用现行全航线 `prepare_snapshot`／`verify_network_fixture` 补足两日期的汉堡当地起飞时间、候选间隔及报价稳定性检查。对现行 `import_network_data.py` 的重置前置条件建立可隔离测试：含非演示账号或待确认动作时拒绝，拒绝发生在删除任何记录之前；必要时只抽取小型守卫函数，不在测试里操作正式库。两项旧测试的有效断言被替代后，才移除旧测试、旧导入链与 24 KB 旧样本。
4. 从 README 删除旧小样本导入和再生成操作，明确唯一交付样本、可选 `data/source/` 原始库和正式重置必须先备份的命令；更新架构中的脚本职责与当前进度。历史阶段文档不改写正文，P3.2d 再统一整理导航和历史引用。复核 `pytz` 无现行引用后更新依赖声明。
5. 运行完整自动化，并逐项说明旧测试、替代测试及测试总数变化；运行两日期全航线核验、迁移入口只读导入/版本检查、Python 编译、页面脚本语法、依赖完整性、当前文档链接和 Git 差异检查。确认正式 5433 库及 8000 服务无变动，不调用付费模型或联网搜索。
6. 将保留／替换／移除清单、样本哈希、测试结果和未完成的 P3.2b2 内容写入《当前进度》。只在本地功能分支提交；不合并 `main`、不推送 GitHub。之后另出 P3.2b2 的历史评估脚本清理计划并等待单独确认。

## 4. 停止条件

若现行入口仍引用候选文件、迁移版本或次序发生变化、重置拒绝发生在任何删除之后、两日期排程或报价变化、测试缺少等价覆盖、全航线文件或本机原始库哈希变化，停止相关删除并保留文件。正式库只读检查失败也先报告，不用重建正式库解决。Git 跟踪文件可从本地功能分支起点恢复；本机原始 SQLite 本步不移动、不修改。
