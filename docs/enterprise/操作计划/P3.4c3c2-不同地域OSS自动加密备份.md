# P3.4c3c2 不同地域 OSS 自动加密备份

> 2026-10-29 事前计划，现按旅客确认执行。承接 [R-02 上线后完善路线](R-02-上线后完善路线.md)与 [P3.4c3c 分步路线](P3.4c3c-云端正式发布与备份分步路线.md)。OSS 试用和私有桶已经由旅客开通；上传、定时、提醒和恢复的实际结果分别写入[当前进度](../当前进度.md)。

## 一、现状与目标

正式网站 `https://adzyforever.com/app` 已在线。香港轻量服务器有独立授权展示账号及已确认的虚构机票、酒店、租车订单；原订单和五个正式数据／证书卷保留。当前已能手动生成服务器外加密备份、在本机解密核验，并曾在全新隔离卷完成恢复。恢复私钥由旅客在本机及密码管理器保存。缺口是**每天自动生成、加密并送到另一地域，能够发现漏备，并从自动备份实际恢复**。

目标是每日自动备份正式 PostgreSQL 数据及对应的演示批次清单，至少保留最近七份成功的每日备份；推荐保留 30 天，并在实施前用实际账单估算核对。备份只包含恢复所需的数据库与批次元数据，不包含模型／搜索密钥、SSH 私钥、登录环境文件或 TLS 私钥。订单和会话正文可能在数据库中，因此密文和恢复权限仍按敏感数据管理。

## 二、推荐配置与先决条件

| 项目 | 建议 | 核对点 |
| --- | --- | --- |
| 地域 | 新加坡 `ap-southeast-1`，与香港服务器分开；若控制台报价、地域可用性或连通性不合适，先报告再定其他香港以外地域 | 新加坡桶用公网 HTTPS Endpoint，不能误用香港内网 Endpoint；跨地域网络与下载账单以实际控制台为准 |
| 存储 | 单独新建标准存储桶，ACL 为私有，开启桶级“阻止公共访问” | 无匿名读取、公共读或公共读写；不绑定网站域名，不作静态网站 |
| 路径 | 专用前缀 `travel-assistant/backups/`，每次对象名带 UTC 时间与批次标识且不可重复 | 防止覆盖旧备份；桶内不混放网页资源 |
| 留存 | 先按最近修改时间 30 天删除此前缀对象；不启用版本控制或冷存储转换，避免本阶段的历史版本、最低存储时长与解冻复杂度 | 生命周期规则只作用于此备份前缀；至少能核对七份已成功的日备份；清理通常不是到点立即执行 |
| 加密 | 在服务器端用**恢复公钥**加密后上传；恢复私钥继续只在本机与密码管理器 | OSS 中只存在密文；服务器和 GitHub 都没有恢复私钥；上传前不得将明文写入应用公开目录 |
| 身份 | 先检查轻量服务器能否使用合适的临时身份；若不可用，专建 RAM 身份，仅允许对单桶指定前缀上传及必要核验读取 | 不使用阿里云主账号密钥，不复用模型／搜索密钥，不授予删除桶、公开桶或全桶管理权限；凭证仅在服务器权限受限的私有配置中 |
| 定时 | 服务器本地 `systemd` timer 每日低峰运行，加入互斥锁、超时和有限重试 | 服务器重启后仍启用；备份失败不影响现有网站；不触发数据库重建或日期平移 |

单份近期密文约 0.7 MB，按 30 份粗算仅约 21 MB；未来数据增长、请求次数、下载恢复、跨地域网络路径及 OSS 计费规则都可能改变费用。先在阿里云中国站核对**新加坡标准存储、请求、外网流出和跨地域传输**的实际单价与免费额度；按量付费，不预购大资源包。若页面无法给出可靠合计，先做一次有记录的小文件试传并查看账单，再决定持续运行。账单有延迟，不能把试传后即时的零费用当作免费证明。[阿里云计费说明](https://help.aliyun.com/zh/oss/billing/)；[地域与 Endpoint](https://help.aliyun.com/en/oss/user-guide/regions-and-endpoints)；[跨地域网络说明](https://help.aliyun.com/zh/oss/user-guide/access-and-network-overview)。

## 三、分步执行与检查点

### 1. 只读预检与费用判断

1. 重读《产品需求》《软件架构》《当前进度》及本计划；核对 Git 状态、正式网站健康、数据库批次、五个卷、展示账号三笔订单、可用内存／磁盘及最近已验证的本机密文。记录基线，不读取或输出私钥内容。
2. 查看阿里云中国站 OSS 是否已开通、新加坡地域是否可建桶、报价／免费额度及告警可用方式；核对香港服务器到新加坡 OSS 公网 HTTPS 的连通性。只做只读查询和极小试探，不对正式库写入。
3. 给出预估月用量、存储与请求账单口径及可用的告警渠道。若需要开通 OSS、创建桶或产生费用，先将实际选项和界面步骤告诉旅客，按本计划确认后执行。

### 2. 私有桶、权限与本地加密程序

1. 建立独立桶，核对地域、私有 ACL、阻止公共访问；先用匿名请求验证不能读取，再用受权身份验证只在指定前缀可操作。[阻止公共访问说明](https://help.aliyun.com/zh/oss/user-guide/block-public-access)；[前缀权限示例](https://help.aliyun.com/en/oss/user-guide/access-control-base-on-ram-policy)。
2. 单独建立最小权限上传身份。执行时先依据所选上传工具的真实 API 调用收窄权限；上传身份不应能下载明文、删除旧备份、改桶策略或列出其他项目。恢复使用另一套只读身份或由旅客控制台临时授权，不把下载权限长期放在应用容器中。若轻量实例支持无需长期密钥的方式，先验证其可行性再选用；不能仅按 ECS 文档假定支持。
3. 写一个独立的备份程序：检查正式项目与数据库身份、批次清单及健康状态；执行 `pg_dump -Fc`；生成不含凭证的摘要／文件哈希；用恢复公钥加密；以 HTTPS 上传唯一密文对象；再读取对象大小和元数据核验。成功后才清理本次临时文件。失败时保留诊断摘要及原有备份，绝不删正式卷或重置数据库。上传工具版本与校验和固定，日志不记录 AccessKey、完整连接串、订单正文或恢复私钥。[ossutil 安装与校验](https://help.aliyun.com/zh/oss/developer-reference/install-ossutil/)。
4. 先在隔离库和独立前缀做一次试备，故意模拟断网、权限不足、重复启动和中途失败；确认不会产生“上传成功”的假记录，也不会让应用停机。再对正式库做第一次手工触发的加密上传，事后只读比较正式数据摘要和订单数量。

### 3. 定时、留存与失败提醒

1. 配置每日一次的 `systemd` timer，设置互斥、超时、有限重试、服务器重启后补跑，并记录最近成功时间、对象标识、大小及哈希。备份任务不得执行订单写入，也不需要停止网站。
2. 配置只作用于专用前缀的 30 天生命周期删除规则。先确认规则没有覆盖其他对象；观察实际生效时间，不以“已创建规则”代替留存验收。[生命周期行为与延迟](https://help.aliyun.com/zh/oss/user-guide/overview-54/)。
3. 设失败提醒和“超过 26 小时没有成功备份”的漏备提醒，发送到旅客认可的邮箱或阿里云告警联系人；执行阶段核实具体告警服务的权限与费用。用一次人为失败验证旅客实际收到提醒，再恢复任务并验证成功通知或状态。若无法建立可送达提醒，阶段不能判为完成。

### 4. 跨地点取回与全新卷恢复

1. 从 OSS 使用独立的恢复权限把一份**自动产生**的密文下载到旅客本机；核对大小与哈希，用其保存的恢复私钥实际解密，检查 `pg_restore -l` 和批次清单。
2. 在与正式站点隔离的全新数据库／清单卷恢复，核对迁移版本、供给数量、展示账号行程及原订单摘要；私有验收应用用占位模型／搜索密钥，只读检查登录、页面和订单。不得以正在使用的正式卷作为恢复目标。
3. 停止隔离验收容器，保留可追溯的密文和验收摘要；删除本轮临时明文，复核正式网站、原五卷和订单未变。

## 四、需要旅客配合的最小事项

执行时由我先准备操作步骤、配置模板和权限策略供核对。旅客只需在阿里云控制台完成账户侧必需的 OSS 开通／私有桶或 RAM 授权操作，并把**桶名、地域、价格／额度和告警联系人状态**告诉我；如需 AccessKey，直接填入本机或服务器的 Git 忽略私有配置，**不要在聊天发送密钥**。现有恢复私钥继续由旅客保管，本阶段无需发来。当前先不要求购买资源包或修改防火墙；若实际检查要求新费用或开放端口，先单独说明原因和影响。

## 五、通过标准与失败处理

- 自动任务在服务器重启后仍按时运行；至少一次正式库自动备份在 OSS 中核对为密文，匿名访问被拒绝；上传主体无法修改桶策略或读取其他路径。
- 通过故障注入证明漏备或上传失败会提醒到旅客；连续运行后核对每日对象与留存规则，至少可取回最近七份成功的日备份。若实施当天不足七日，先以日程与首批运行证据验收“已启用”，七份齐全后再标记“留存目标通过”。
- 从 OSS 自动备份在本机解密，并在全新隔离卷实际恢复；批次、供给及订单摘要与备份时点一致。正式云库和在线网站保持原状。
- 记录实际 OSS 账单、资源变化、备份大小、运行耗时、告警与恢复证据；凭证、密文内容和私钥不进入 GitHub 或公开文档。

若任何预检、权限、上传、提醒或恢复验证失败，停用新增定时任务并保留现场与已存在的本机加密备份；不删除桶、对象、数据卷或原有备份。网站继续按已验收版本运行。修复后只补测失败环节与其直接影响范围。

## 六、Git 与发布边界

实施从当前干净 `main` 建立独立功能分支；只提交通用脚本、脱敏配置模板、操作说明、测试和验收文档，且公开路径、分支与提交说明不出现不需要的旧工具品牌字样。服务器凭证、桶中密文、本机恢复私钥、真实账号与环境文件一律保持 Git 忽略。先做静态检查、脚本自检及隔离恢复，再部署备份程序；本阶段不重建应用镜像、不迁移业务库、不自动改变现有订单或模型服务。验收后另拟 G 计划，核对实时远端、公开内容与差异，再经旅客确认普通快进本机 `main` 并同步 GitHub；不强推、不改写历史。
