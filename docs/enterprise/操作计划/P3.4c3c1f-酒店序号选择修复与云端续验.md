# P3.4c3c1f 酒店序号选择修复与云端续验计划

> 2026-10-28 制定并经旅客确认。承接已确认并部分执行的 P3.4c3c1e；本计划只新增“第一间”房型选择修复及其必要回归，随后继续原定完整云端验收。

## 已核实的问题

- 正式云端新镜像已正确查到伦敦希思罗机场附近 11 月 1 日入住、11 月 3 日退房的两间虚构房型，查询轮没有生成交易卡，原订单未变。
- 同一会话下一轮说“预订刚才找到的第一间……先给我待确认卡”时，助手答“有多个候选”，没有出卡。已立即停止后续付费对话，公网代理保持关闭。
- 只读本地复现与云端结果一致：候选选择规则识别“第一家”“第一个”“第一房型”，但酒店序号词表漏了“间”；因此未得到明确候选。模型建议的产品编号也不能越过服务端选择核验。

## 执行顺序

1. 从已同步的 `main` 建新的功能分支；只在酒店候选序号规则中补“间”，不放宽候选必须已展示、当前会话与当前范围、价格／日期复核、模型建议与旅客选择一致等边界。检查“第一间／第二间／第 1 间”以及超出序号、未展示产品、模型建议冲突仍正确处理。
2. 增加接口级回归：先在同一会话查询两间可售房型，再说“预订刚才找到的第一间”并给入住／退房日期，必须生成一张正确产品、日期、金额的**待确认**酒店卡；订单仍不变，其他账号不可读取此卡。把“先看看、暂时别订”及模糊多候选零卡保留为反例。
3. 运行完整自动化回归、依赖／编译／差异检查，并审查公开内容没有凭证、服务器私有路径或不希望出现的品牌字样。结果写入《当前进度》，公开源码和测试按另行确认的 G-24 普通快进、推送 GitHub。
4. 云端先核对原项目、五个数据卷、原订单摘要、当前镜像与服务器外加密备份。公网代理继续关闭；保留现有镜像为回退点，单路构建修订镜像并只更新私有应用，不迁移、不重导数据、不重置会话或初始订单。
5. 用新的请求键在同一验收账号的酒店会话重查两间房并申请“第一间”待确认卡，核对卡片产品／日期／金额、跨账号 404、未确认订单摘要不变。随后续跑酒店与租车、政策、历史、上下文、联网推荐等剩余真实轮次。每轮检查结果；遇到新的业务或隔离缺陷立即停测并保持公网关闭，记录准确原因。
6. 全部通过才打开 HTTPS，复核授权登录、桌面／窄屏、刷新、证书、80／443 公网入口与内部服务不映射、资源和日志。停用一次性验收账号并删除其私有凭证文件。网站按旅客已确认的偏好保持在线；后续另设步骤，为授权演示账号通过正常确认流程建立一套虚构行程。

## 失败处理与边界

- 所有交易卡只生成、不确认；云端原订单与已停用初始账号归属不变。若私有镜像或验收失败，关闭代理并回到保留镜像；不覆盖恢复原库。
- 已有加密备份留在本机和服务器端，恢复身份只存在旅客保管位置；不把密钥、账号、备份或环境文件写入 Git。云端真实模型／搜索用量按服务商实际计费。
- 本计划不要求新增防火墙规则、域名、服务器或 API 凭证。若需要新的服务、数据库结构或交易规则，另行制定计划并取得确认。
