# P3.4c3a 服务器外加密备份与全新卷恢复操作计划

> 2026-10-27 制定并获旅客确认，已按本计划完成手动验收；结果见[独立验收记录](../P3.4c3a-异地加密备份与恢复验收记录.md)。承接 [P3.4c3 分步路线](P3.4c3-云端恢复与完整旅程分步路线.md)。旅客选择**先将加密备份放在本人 Windows 电脑，后续再做 OSS**，恢复私钥的第二份副本保存在自己的密码管理器。

## 目标和边界

- 证明云端 2026-10-27 演示批次在香港服务器丢失时，旅客持有的一份加密备份可用于恢复。备份包含 PostgreSQL 完整数据库、自身 SHA256、批次清单、数据源和发布版本标识；不把 API Key、JWT 密钥、云端账号明文密码、SSH 私钥或证书私钥打包。恢复时可重建应用密钥并重新授权登录，既有浏览器令牌因此失效是预期行为。
- 原项目 `travel-cloud` 的数据库和五卷始终保留。恢复演练使用**新的 Compose 项目、新数据库卷、新批次清单卷、仅内部网络的应用**，不发布 80／443／8000／5432，不调用真实模型或联网搜索，不运行一次性 `init`，也不平移日期。
- 服务器实际可见内存约 1,613 MiB、无 swap；制作备份与恢复分时进行。恢复演练时原公网代理／应用保持关闭，先记录可用内存、磁盘、OOM 与卷身份。

## 执行顺序和逐级放行条件

1. **复核现场**：重读三份核心文档、本计划及 P3.4c2f 结果，核对功能分支、原库项目标签、五卷、批次日、迁移数、供给及订单／会话／审计摘要。检查现有两份同机备份的格式、哈希；确认目标本机目录被 Git 忽略、磁盘充足，拟用的新云端项目／卷不存在。原库身份或备份状态不符时暂停，不做覆盖性操作。
2. **确定密钥保管**：在旅客本机生成**专用备份密钥对**，只把公开接收密钥交给加密过程；私钥留在旅客控制的受限目录，不复制到服务器、不写脚本参数、日志、聊天或 Git。使用官方发布的 `age` 工具并核对版本／来源。给旅客提供本机私钥位置和密码管理器的保存步骤，由旅客亲自保存第二份副本；只请旅客确认“已保存”，不读取或索要密码管理器中的内容。若暂时只有本机一份，只能验收“服务器失效可恢复”，不能声称“本机和服务器同时失效也可恢复”。任何私钥输出、权限不符或来源无法核验时停止。
3. **取一致性备份**：在服务器的私有备份卷中新建带时间和随机后缀的文件名，拒绝覆盖已有文件。用 PostgreSQL 17 `pg_dump -Fc` 读取当前库，不停原数据库；运行 `pg_restore -l` 并核对归档头、文件大小与 SHA256。把批次清单、原发布提交及非敏感恢复元数据纳入独立清单，记录每项哈希；备份不包含运行配置和凭证。若 SSH 意外断开，先检查任务状态、文件大小与校验，不直接重跑造成第二份含糊快照。
4. **加密并移出服务器**：通过已经核验主机指纹的 SSH 通道，将备份包以二进制流传到旅客电脑，在本机以 `age` 公开接收密钥加密，直接写入 Git 忽略的私有目录；不在本机磁盘留下明文备份。传输或加密任一步失败，删除不完整的**新密文临时文件**，保留原库和已有备份。完成后比对传输前后的包校验值、密文大小与 SHA256，限制本机文件读取权限；公开文档只记录大小、哈希和位置类别。
5. **使用外部密文真实恢复**：先以旅客本机私钥实际解密这份密文，核对包内各项哈希和 `pg_restore -l`；再将该**外部密文解出的内容**经 SSH 送到全新隔离项目。新空数据库使用同主版本 PostgreSQL，先核对确无业务表，再运行 `pg_restore --exit-on-error --no-owner --no-privileges`；恢复演练不接触原卷，不在非空目标重试。恢复批次清单，并用独立私有配置、无公网端口的应用核对 `/ready` 与授权账号状态；必要的临时明文文件在校验后清理，不清理原云端备份或加密外部副本。
6. **对账与收尾**：逐项比较源库和恢复库的批次日、14 版迁移、供给摘要、账号有效／停用状态、三类订单、会话、轮次、待确认卡、动作结果、审计和服务商用量记录；计算实际备份、传输、恢复耗时。检查重建后的应用守卫与本人只读接口，核对两环境的卷、数据库连接和令牌不能串用。停止隔离应用及数据库，保留恢复卷和脱敏证据供下一步复查；原库仍保持此前状态。更新《当前进度》和独立验收记录，只把通过检查的公开脚本／文档提交功能分支。

## 验收、失败与回退

- **通过**：外部加密文件可由旅客持有的私钥解密；确实从它恢复到全新数据库卷和批次清单卷；业务／账号／会话／审计摘要一致，私有应用健康，原库及五卷未改、无 OOM。只有 `pg_restore -l` 或只有服务器内备份均不算通过。
- **暂停**：密钥丢失或出现在不该出现的位置、工具来源不可核验、备份校验／解密失败、目标非空、恢复报错、摘要不符、越权可读、明文或凭证误入公开文件、可用内存不足或 OOM。保留原卷与证据；要重试时换新隔离目标，不清理或覆盖未知卷。
- 本步骤是**一次手动异地恢复演练**；每日自动备份、七份日保留和从真正异地存储自动取回仍留待 P3.4c3c。若旅客没有独立保留恢复私钥，必须在结论中写明该单点风险。

## 旅客需判断的事项

- **已确定**本阶段备份落到旅客本机，不购买新存储；OSS 的地域、实际费用、私有桶与最小权限另在 P3.4c3c 规划，不索取主账号密钥。
- **已确定**恢复私钥第二份副本由旅客保存到自己的密码管理器。执行时只提供本机私钥文件位置及逐步操作说明；旅客不在聊天发送私钥或密码管理器内容。
- 全程不会启用公网网站、确认或取消任何原云端订单，也不会合并 `main` 或推送 GitHub。P3.4c3b 的九类交易验收会在本步骤通过后另给详细计划。
