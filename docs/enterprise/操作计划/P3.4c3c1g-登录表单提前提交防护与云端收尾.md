# P3.4c3c1g 登录表单提前提交防护与云端收尾计划

> 2026-10-28 制定并经旅客确认。承接 P3.4c3c1f 已完成的 12 轮私有业务验收；本计划新增一个在公网页面验收时发现的登录表单安全修复。

## 已核实的情况与即时处置

- 修复后的云端助手完成约定的 12 轮真实对话：机票、酒店、租车的明确预订各只生成一张待确认卡；“先别下单”、政策、历史与推荐均无卡。跨账号读取拒绝，原订单和行程摘要不变。伦敦地点检索记录显示搜索成功且与人工核查目录匹配。
- 公网页面自动化验收发现：浏览器在 `app.js` 尚未绑定登录事件时提前提交原生表单。当前 HTML 未指定提交方式，浏览器默认使用 GET，导致**一名临时验收账号的密码进入本网站的请求网址**，私有应用日志记录了 2 条相关请求。未观察到正式授权账号或模型／搜索密钥被传入网址。
- 已立即停用两名临时验收账号，删除服务器上两份临时密码文件；数据库核对仍有 1 个正式授权账号有效、4 笔原订单未变。公网代理已关闭；数据库和私有应用继续健康运行。泄露的是已停用的随机验收密码；不在文档、聊天或日志摘要复述该值。

## 执行顺序

1. 在独立功能分支修改登录表单：原生提交明确使用 `POST /app`，使脚本未加载时密码不进入 URL；登录按钮默认禁用，前端绑定处理函数后才启用。保留现有正常登录、会话恢复、错误提示和退出功能。
2. 加页面回归检查 HTML 表单默认行为及按钮启用时机，验证脚本加载前提交不会形成带密码的 GET URL；核对 JS 正常接管后仍通过 `/api/v1/login` 登录。运行完整自动化、前端语法、依赖和公开差异检查。
3. 按另行确认的 G-25 将修复、回归、计划和真实结果同步本机及 GitHub `main`，使用该主线在云端单路构建新镜像。旧镜像保留回退；只替换私有应用，不迁移、重导或覆盖数据库，公网仍关闭。核对新容器、原订单、授权登录和已停用账号不可用；检查新容器日志没有包含上述临时密码网址。
4. 先在私有入口核对正式授权演示账号登录、匿名拒绝、原行程与待确认卡的 API 边界，不再启用已停用账号。原卡归验收账号，正式账号若需页面卡片证据，只经正常对话产生一张新的待确认酒店卡，绝不点击确认或放弃；原订单不变。
5. 私有入口通过后短时重开公网代理，用**正式授权账号**在登录脚本就绪后提交，核对 HTTPS、页面刷新、行程、酒店待确认卡展示及 1440／375／338 像素布局；同时核对证书、HTTP／`www` 跳转、匿名本人接口 401、内部路由 404、仅 80／443 暴露且应用与数据库无宿主端口。任何失败立即关闭公网并记录；全部通过后复核资源、OOM、原订单及停用账号，网站按旅客选择保持在线。更新《当前进度》与独立验收记录；为正式授权账号补虚构行程仍为下一独立步骤。

## 边界与失败处理

- 临时账号密码已失效；既有原订单、会话、五个数据卷、本机加密备份保留。对于两条旧容器日志，仅核对记录数量与新容器无同类记录，不向公开文档或聊天复制敏感网址。新镜像更换原应用容器后再检查旧容器日志是否仍存在；如需额外日志清理，先核对精确目标和保留证据，再处理。
- 不购买新服务、不添加防火墙规则或开放内部端口。任何新的交易、认证或权限缺陷仍按停测规则关闭公网并另行规划。
