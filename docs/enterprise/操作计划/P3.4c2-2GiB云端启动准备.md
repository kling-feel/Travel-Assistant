# P3.4c2 2 GiB 云端启动准备操作计划

> 2026-10-26。属于旅客已确认的 P3.4c 分步计划。本步只处理仓库内的启动入口和说明；旅客自行购买域名与服务器并告知最终域名，本步不依赖报价。尚未登录云服务器或开放公网。

## 目标与范围

确保正式 2 GiB 部署的每条 Compose 命令一致叠加 `compose.cloud.2g.yaml`，不误用本机试验覆盖文件；保持数据库、应用无公开宿主端口，只有代理开放 80／443。给不熟悉 Docker 的旅客一组清楚、可复制的操作入口。保持现有云端账号预置、空库初始化和逐张订单确认规则。

## 执行顺序

1. 重读产品需求、软件架构、当前进度和 P3.4c 总计划；核对分支干净、云端 Compose、2 GiB 覆盖配置和现有操作指南。
2. 添加一个只负责组成并执行正式云端 Docker Compose 命令的简洁入口。默认使用 `compose.cloud.yaml` 与 `compose.cloud.2g.yaml`、指定项目名和私有 `cloud.env`。明确允许的日常命令；拒绝会删卷的命令。只打印无密钥的命令结构，不读取或输出私有配置内容。
3. 更新云端操作指南，以统一入口列出启动空库、一次性备份与初始化、账号管理、启动／停止、状态核对的**实际调用方法**。示例域名仅用于解释，不能当作正式域名；云端私有配置需旅客确定最终域名后生成。
4. 在当前工作台运行纯离线的命令构造、危险命令拒绝、配置文件解析和端口／资源上限检查。若当前工作台没有 Docker CLI，明确记录无法执行的 Compose 合成与真实主机验收，不请旅客为了本步重复执行容器命令。
5. 更新《当前进度》，仅在当前功能分支提交本步结果；不合并 `main`、不推送 GitHub、不启动或修改本机 8000／5436、不调用真实模型与搜索。

## 停止条件

若入口可能选择错误 Compose 项目、接受删除数据卷的命令、从本机 `.env` 读取密钥、覆盖现有私有配置、公开 8000／5432，停止本步并修复。正式域名、服务器和 SSH 尚未具备时，保持公网验收待办，不把离线检查写成正式部署成功。
