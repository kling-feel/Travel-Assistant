# P3.3c1：新批次隔离页面与全旅程验收操作计划

> 2026-10-24 制定｜2026-10-25 旅客确认并执行，结果见[验收记录](../P3.3c1-隔离页面全旅程验收记录.md)。承接已完成的[P3.3b 隔离批次构建与验证](../P3.3b-隔离演示批次验收记录.md)。本计划只在隔离页面和可写验收副本执行；**不切换 8000，不写旧 5433 或候选 5436，不合并主线或推送**。正式入口切换另拟 P3.3c2 并单独确认。

## 1. 为什么分成两步

P3.3b 已生成两套同日且业务摘要一致的新批次。`travel-date-next` 的 5436 卷是后续正式切换的干净候选；`travel-date-repeat` 的 5438 卷可承担会生成订单、会话和动作卡的验收。直接在 5436 做九类交易，会把验收记录带进展示入口，因此本步使用 **5438 数据库 + 8017 页面**。旧 5433 与候选 5436 只读核对、不写入。当前四个数据库容器均已停止，数据卷和本机备份仍在。

P3.3c1 的目标是证明真实旅客在新批次页面上能完成对话、查询和九类模拟交易，并在失败、刷新及重启后保持正确。通过后只形成**是否具备切换条件的验收结论**；不因本计划确认而自动启动正式切换。

## 2. 开工前核对和备份

1. 重读《产品需求》《软件架构》《当前进度》及 P3.3b 记录；核对功能分支、工作区、当天日期、8000／8017 和 5433／5436／5438 状态。若日期已使初始订单或未来 30 日窗口无法完成指定场景，先记录原因并重新拟定批次更新步骤，不静默平移任何库。
2. 在可运行 Docker 的普通 PowerShell 中，启动已有的 `travel-date-repeat` 验收库；为只读基线核对，也启动已有的 `travel-date-next` 候选库。核对两者实际项目标签、命名卷挂载和 5438／5436 端口与脱敏有效连接目标；**所有测试写入只指向 5438**。工作台若仍无 Docker，只在必须操作容器时给旅客逐条命令并核对返回；绝不要求发送 `.env`、密码、令牌或数据库文件。
3. 在任何测试写入之前，用自定义格式 `pg_dump` 为 5438 的已导入状态创建新的 Git 忽略备份；检查文件头、`pg_restore -l` 目录与大小。只读记录 5438 的演示日、13 版迁移、供给和初始订单摘要。同时只读确认 5436 保持 P3.3b 的干净摘要；若候选库出现非预期数据，停止验收。
4. 以 `data/generated/p33b-repeat.env` 中的独立数据库和 JWT 配置启动仅绑定本机 127.0.0.1 的 8017 API／页面。启动前由进程核对有效主机、端口、数据库名和 JWT 与旧批次不同；仅打印配置是否存在，不显示值。两个演示账号只在本机忽略文件中读取。

## 3. 执行顺序

### A. 固定模型、数据库和接口

- 先用固定模型及服务端证据测试九类动作：机票预订／改签／取消、酒店预订／改期／取消、租车预订／改期／取消。每类至少一条从查询、候选选择、待确认卡到旅客确认和数据库结果的完整路径；另测放弃、重复确认、卡过期／冲突、跨账号拒绝。每张卡核对对象、当地日期时刻、价格、费用／补退差、规则版本、审计和动作归属。确认前订单不变。
- 以两名旅客和不同会话验证：已取消订单只在明确问历史时出现；当前行程不含已取消项；混合请求最多两张卡，未完成项目清楚列出；一个业务缺条件不阻断另一业务只读查询。真实候选失效或价格变化时拒绝旧卡。
- 对可复现问题补定向自动化并修复，再重跑相关场景。任何 P0 级跨账号泄露、无确认写入、错误金额或候选与卡片不一致，都停止真实模型阶段。

### B. 真实页面、模型和联网

- 先检查本机原有 DeepSeek 与阿里云 `GlobalBasic` 密钥是否已配置，只读判断有无，不打印值。P3.3b 的批次启动器故意清空付费服务密钥；本步如需真实调用，增加**显式选择的本机凭证传递方式**，仅允许模型和搜索所需字段从本机 `.env` 进入 8017 子进程，数据库端口、数据库密码、JWT 和演示账号仍以 5438 的隔离配置为准。无显式选择时保持禁用付费调用。测试此配置优先级与泄露边界；若现有密钥不可用，再告诉旅客本机应配置的字段，不要求在聊天发送密钥。
- 用 8017 的真实登录页面执行四段多轮旅程：①最早可售航班、选班并预订，接落地酒店；②已有机票改签或取消及酒店联动；③租车预订、改期、取消；④自述所在地、可达城市旅行推荐、虚构政策和中国天气核验。搜索有凭证时按当前产品要求默认开启，只把已核查资料作为地点事实；境外天气仍说明无法核实。用数据库和结构化卡片判定结果，不把模型自述当成交易成功。
- 页面核对旅客消息立即出现、真实等待计时、核验后逐段答复、候选选择、金额与当地时区、确认／放弃按钮、有效行程和已取消历史。桌面与约 375／338 像素宽度都应可读可操作；键盘焦点、错误提示及系统减少动画一并检查。工作台若不能实际观察浏览器交互，只把需要人眼判断的少量项目交给旅客，不用截图替代服务端证据。
- 费用按本步新流水单独统计：DeepSeek 最多 **40 次请求尝试**，保守估算到 **¥8** 即停；用量缺失、定价无法核对或下一次可能越线时提前停机。阿里云搜索最多 **30 次请求**，逐次记录调用结果；由于 `GlobalBasic` 单价尚无可靠控制台证据，不承诺搜索金额上限，账单金额由旅客在控制台核对。请求上限是停止线，不是必须用满的目标。失败重试也计入次数，不打印密钥、原始请求头或用户凭证。

### C. 刷新、重启与安全边界

- 在 5438 验收库保留一张未过期卡及已确认订单，先重启 8017 API，再仅重启 5438 数据库；分别核对重新登录后的会话、消息、候选、卡片、订单和审计。卡自然过期后须显示过期，不能因刷新而变回可确认。
- 快速切换会话 A／B，处理中刷新页面、短暂断开连接并按相同请求键核对结果；不能串会话、重复消息、重复卡或重复订单。第二账号不得看到第一账号的会话、卡片和订单。旧批次令牌在新批次继续返回 401。
- 对外部检索文本做提示注入样例，验证其不能改变平台政策、发起交易或泄露内部配置。对缺失来源、模型超时、搜索失败和错误城市日期给出可理解的失败或降级答复；不声称已出票、已付款或取得真实库存。

## 4. 验收门槛、记录与收尾

- 九类交易的固定模型全链路全部正确；真实模型四段多轮旅程中每个写操作都只生成正确的待确认卡，由旅客明确点击后才改变 5438 订单。未授权写入、跨账号泄露、真实密钥外泄、错误金额或规则、把未经核实搜索结果当事实，允许数量均为 **0**。真实对话逐项记录通过／失败，不用平均分掩盖关键失败。
- 记录页面实际观察、API 与数据库前后状态、重启恢复、请求数和保守费用。发现问题先在功能分支定向修复及复测；无法修复的阻断项明列，不宣称通过。再运行完整自动化、编译、依赖、页面脚本语法、样本和公开内容检查。所有临时账号、聊天全文、备份与计量流水留在 Git 忽略目录。
- 最后只读重核 5436 的供给和初始订单摘要与 P3.3b 相同，旧 5433 的数据未改变。关闭 8017，停止仅本轮启动的 5438 验收容器，保留新旧卷和备份；更新独立验收记录和《当前进度》，只提交当前本地功能分支。

## 5. 后续单独决定

若 P3.3c1 通过，再拟 **P3.3c2 正式入口切换与回退计划**：写清 8000 当前进程与数据连接、用户停止操作窗口、旧库最新备份和恢复验证、新库候选 5436 复核、清除旧登录态、切换后只读烟测以及失败时恢复旧配置的命令。该步骤须旅客看到 P3.3c1 的实际结果后**另行确认**；P3.3c1 的确认不授权切换 8000、合并 `main` 或推送 GitHub。
