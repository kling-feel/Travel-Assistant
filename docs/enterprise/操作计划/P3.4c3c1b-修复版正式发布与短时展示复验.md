## 分段操作与放行条件

1. **只读开工核对**：重读三份核心文档和本计划；核对本机与实时 GitHub `main`、发布源、受限 SSH 身份。只读检查云端 `travel-cloud` 项目标签、卷名与挂载、数据库健康、应用／代理停止、原镜像 ID、迁移／批次／订单及供给摘要、私有配置权限、现有账号状态、证书到期、DNS、磁盘、可用内存及容器／内核 OOM。若项目身份、数据摘要、资源或现有云端状态与预期不符，停止并报告，不启动任何服务。
2. **新的服务器外备份与回退点**：给原库创建不覆盖旧文件的 `pg_dump -Fc` 及批次清单、脱敏摘要，检查 `pg_restore -l` 和 SHA256；通过专用 SSH 通道直接加密保存到旅客本机 Git 忽略目录，用旅客已保管的恢复身份在本机实际解密验证。按 2 GiB 内存预算分时在全新隔离卷做一次恢复核对；恢复项目不得暴露宿主机端口，完成后停止并保留卷。记录原应用镜像完整 ID、代码版本及 Compose 配置，为旧镜像保留回退标签。备份无法解密、恢复摘要不一致或无足够资源时停止。
3. **从审查提交构建正式镜像**：只从已同步 `main` 的跟踪文件制作发布包，核对文件清单与 SHA256；服务器使用新发布目录，不覆盖原私有 `cloud.env`、账号目录或证书卷。先运行不打印秘密值的配置预检和 Compose 配置差异检查，确认项目仍为 `travel-cloud`、原数据库／清单／证书卷未变、只有代理映射 80／443、应用及数据库无宿主机端口。按 `compose.cloud.yaml` 加 `compose.cloud.2g.yaml` 单路构建应用镜像，核对镜像内关键代码哈希、依赖、内存／磁盘／OOM；旧镜像保持可立即回切。构建或配置不符时不开应用。
4. **仅私有就绪验证**：代理保持关闭，只让新应用连接原健康数据库。通过容器内部或受限 SSH 回环通道验证 `/ready`、应用健康、配置与卷挂载、原业务订单和供给摘要不变；检查应用／数据库日志、镜像层和命令输出不含密钥或令牌。**本阶段不登录、不查本人行程或跨账号数据、不发对话、不建卡。**若就绪、数据或泄漏检查失败，停新应用并恢复旧镜像，公网继续关闭。
5. **短时公网基础入口复验**：私有就绪通过后才启动原域名代理。核对受信 HTTPS 证书、HTTP→HTTPS、`www`→根域、匿名可打开登录页、内部文档及健康接口对公网不可见；从独立网络检查 80／443 可达、8000／5432 不可达，并核对阿里云轻量服务器防火墙实际规则与 Docker 端口映射。浏览器仅检查登录页在桌面、375 和 338 像素的可读性及无横向遮挡。**本轮不测试登录、授权页面、行程、卡片、流式对话、DeepSeek 或阿里云联网推荐**；这些保留为未验收项。若控制台或独立网络只有旅客可访问，先给出最少检查步骤；缺少证据不宣称公网基础入口通过。
6. **重启、回退与展示日开关演练**：在已备份且状态稳定时分别重启应用和代理，核对 `/ready`、证书、匿名登录页及原订单摘要；数据库重启仅在连接恢复路径已验证且资源允许时进行。记录 2 GiB 主机内存、容器 OOM、磁盘和错误日志。实际演练“展示前核对并启动→确认基础入口→停代理和应用”。若新版本异常，先关代理和新应用，按记录的镜像 ID 回切；正常原库不以旧备份覆盖。若出现未授权订单写入，冻结入口和保全审计，另拟数据修复方案。
7. **收尾与结果**：不创建临时账号或服务商密钥副本；关闭 SSH 页面通道，保留审计、原数据库、五卷、证书、新旧镜像及服务器外加密备份。最后只读核对原业务订单／供给摘要、无公网监听、资源和日志。把每段结果、实际哈希、外部网络与视口证据及未验收项写入《当前进度》和独立验收记录；若新增可复用代码或公开文档，先留功能分支，再另拟 G 计划同步主线和 GitHub。
