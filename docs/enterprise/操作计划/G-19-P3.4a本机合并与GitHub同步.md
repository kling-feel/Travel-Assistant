# G-19：P3.4a 本机合并与 GitHub 同步操作计划

> 2026-10-25 制定并获旅客确认。承接[P3.4a 验收记录](../P3.4a-本机容器化验收记录.md)与[主线发布规则](G-发布同步与公开内容规则.md)。确认计划不代表已合并或推送。

## 目标、基线与范围

将已验收的本地 `feature/p34a-container-recovery` 快进合并到本机 `main`，并在门槛全部通过后，将 `main` 普通推送到旅客已授权管理的 `https://github.com/kling-feel/Travel-Assistant.git`。本次仅发布容器运行方案、守卫、测试、README 和验收文档；不切换当前 8000 演示入口，不迁移或导入 5436 数据库，不启停容器，不部署云端。

制定计划时工作区干净，功能分支为 `3c22eac`，本机 `main` 与本地保存的 `origin/main` 均为 `48dd8b3`；功能分支是本机 `main` 的后代，领先两笔提交、涉及 23 个文件。完整 **253 项自动化测试**与本机隔离容器的会话、确认卡、订单、重启及独立卷备份恢复已在 P3.4a 通过。当前 8000 经宿主机入口使用 5436；P3.4a 的隔离容器已停止，卷和备份保留。基础镜像仍使用可移动标签、传递依赖未单独锁定，云端发布前另在 P3.4b／c 处理。

制定本计划时，工作台访问 GitHub 443 失败，**尚未读取到实时远端 `main`**；本地 `origin/main` 仅是旧引用。执行时如果仍无法从可访问 GitHub 的环境获取远端哈希，就停在合并前，不把旧引用当作发布依据。

## 旅客确认后的执行顺序

1. **固定计划与起点**：重新阅读[产品需求](../产品需求.md)、[软件架构](../软件架构.md)、[当前进度](../当前进度.md)、本计划和 P3.4a 验收记录。仅把本计划、计划索引和事前进度记录提交当前功能分支，使用中性提交说明；核对工作区干净、分支提交链与 23 个已验收文件。若发生来源不明的改动，先停止并报告，不混入本次发布。
2. **获取实时远端基线**：确认 `origin` 仍是上述仓库。从能访问 GitHub 的环境读取远端 `main` 并 `git fetch origin`，核对读取结果、本机 `main` 和功能分支的完整哈希。只有远端 `main` 与本机 `main` 相同，且功能分支能快进时继续。远端已前进、仓库身份不同、无法访问或出现分叉，先停止并重新制定差异处理方案；不用强制推送、变基或历史改写。
3. **公开内容审查**：审查 `main..功能分支` 的每笔提交说明、全部新增／修改路径与最新跟踪文件树；检查公开内容中不出现旅客要求避开的工具品牌字样，且不包含 `.env`、令牌／密码、原始 SQLite、数据库备份、忽略目录或本机验收凭证。检查文档链接、构建上下文白名单、`git diff --check` 和凭证形态。任何命中都先在功能分支修复并重新验收，不带问题合并。
4. **合并前回归**：在功能分支运行完整自动化测试（当前基线 253 项）、Python 编译、页面脚本语法、依赖检查、Compose 配置校验及容器目标守卫测试。使用已有本机依赖和离线虚构样本；不调用付费模型或联网搜索，不读写业务数据库。若因环境无法完成某项，记录具体缺口并在合并前解决；不把 P3.4a 的历史通过结果替代本次执行检查。
5. **本机快进合并**：全部门槛通过后，执行 `git switch main`、`git merge --ff-only feature/p34a-container-recovery`。合并后再次核对提交哈希、工作区、完整测试与公开差异，并只读检查本机 8000 健康及 5436 身份。若合并后的检查失败，停在“本机已合并、远端未同步”，不推送。将实际合并哈希和状态写入《当前进度》，以中性说明提交到本机 `main`；这笔进度提交也须经过公开内容检查。
6. **普通推送与核对**：推送前再次实时读取远端 `main`，确认仍等于本次合并前共同基线；仅执行 `git push origin main`，不推送功能分支或标签，不使用 `--force`。推送后再次读取 GitHub `main` 的完整哈希，确认与本机 `main` 一致，检查仓库最新文件树与《当前进度》。若网络或权限导致推送失败，保留并报告“本机已合并、远端未同步”，在查明原因前不继续下一个主线合并。

## 停止点与执行边界

- 旅客已确认本计划；授权仅覆盖上述本机快进合并及指定仓库 `main` 的普通同步。各执行门槛仍须逐项满足。
- Git 发布不改变 8000 的进程、5436 和旧 5433 数据卷、P3.4a 隔离卷或备份；不运行迁移、导入、日期平移、`down -v`，也不购买云资源或公开服务。
- 工作台若仍无法访问 GitHub 或因自动审批额度无法执行 Git 写操作，先完成可独立进行的只读检查，再向旅客提供经过核对的最小 PowerShell 命令，由旅客决定是否代执行；不通过其他路径绕过审批。
- P3.4b 的云厂商、地域、预算、域名／HTTPS 和访问范围另拟计划并请旅客判断。G-19 完成只代表源码同步，不代表容器已经在云端运行或原 8000 已切换。

执行结果、实际哈希、测试和未解决风险同步到[当前进度](../当前进度.md)。
