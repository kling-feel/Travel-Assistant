# P3.2c1：项目路径与页面资源归位操作计划

> 2026-10-24 制定｜状态：旅客已确认，本地功能分支已实施；结果见[当前进度](../当前进度.md)。承接 [P3.2c 分步路线](P3.2c-应用目录归位分步路线.md)。

## 1. 本步要解决的问题

目前 `main.py` 以自身位置推断根目录 `static/`，两项地点服务以各自文件位置推断 `data/fixtures/`，配置也根据 `config/__init__.py` 推断根 `.env`。未来移动 Python 包时，这些推导会指向错误位置。本步先建立清楚的项目路径，并把页面资源放到应用包中；保留所有外部 URL 和用户操作。

本步只移动静态资源，不移动 `config/`、`db/`、`utils/`、`services/`、`graph_chat/`、`api/`、`migrations/`、`scripts/` 或 `tests/`。路径常量只服务现行文件位置，不提前改造全部业务导入。

## 2. 确认后的具体操作

1. 重读《产品需求》《软件架构》《当前进度》及本计划。核对当前分支、工作区、`static/` 四个文件的清单与哈希、`main.py` 的 URL、`config` 和地点服务的路径推导、README 与测试中的引用。先跑页面相关测试与完整自动化作为移动前基线；保留已有 230 项通过记录，但以本轮实测为准。
2. 创建 `travel_assistant/` 包和简短的项目路径模块，明确“仓库根目录”“页面资源目录”“交付数据目录”。路径应由包文件所在位置确定，不能依赖启动时的当前工作目录或假定 Windows 盘符。迁移 `config`、地点服务对 `.env` 和交付样本的定位到该模块；不读取、打印或修改 `.env` 内容，也不重建样本。
3. 将 `static/app.html`、`app.css`、`app.js`、`mark.svg` 原样移到 `travel_assistant/web/static/`。只改 `main.py` 的文件系统挂载位置，保留 `/app`、`/static/app.js`、`/static/app.css`、`/static/mark.svg` 与 CSP 等响应头；页面中的 URL 不改变。逐个比对移动前后的文件字节哈希，避免顺手修改样式或交互。
4. 更新当前 README、软件架构和必要的当前测试，使读者知道资源真实位置与外部 URL 的区别；历史计划和验收正文继续保存。若任何测试或脚本直接读取旧 `static/` 路径，先调整引用，再清除空目录，不添加长期保留的重复资源。
5. 用现有内存测试客户端访问 `/app` 和三项 `/static/*` 资源，并检查不存在的静态资源仍是 404；核对 `python main.py` 的启动导入、配置从仓库根 `.env` 读取、地点目录和地理样本从 `data/fixtures/` 读取。运行完整自动化、两日期全航线检查、Python 编译、页面 JavaScript 语法、依赖检查、31 个现有注册路由、README 脚本路径、全部本地 Markdown 链接和 Git 差异检查。无需启动 8000 页面或 PostgreSQL。
6. 将实际移动清单、哈希、测试和未完成事项写入《当前进度》；在现有本地功能分支提交本步。之后给出 P3.2c2 的独立详细计划，等待下一次确认。

## 3. 验收标准与风险处理

- 旅客在页面看到的路径、视觉、交互和订单状态不变；资源移动前后内容哈希相同。`main.py` 仍可从项目根启动，测试可从项目根运行。
- `.env` 仍在项目根；交付样本仍在 `data/fixtures/`；原始 SQLite 仍在 Git 忽略的 `data/source/`。迁移版本和数据库结构不变。
- 如果静态资源无法返回、配置指向新位置、推荐目录加载失败或自动化回归退化，先修复；无法在本步修复则不提交、不进入 c2，并说明证据边界。
- 本步不创建账号、动作卡或订单；不运行数据库迁移、导入／重置，不调用 DeepSeek 或阿里云检索；不合并本机 `main`，不推送 GitHub。
