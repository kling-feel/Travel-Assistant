## 起点与共同约束

本机 `main` 已完成全航线数据、虚构政策和航班/酒店/租车九类受控交易，最新实现为 P2.5d1 租车改期；新对话图、联网推荐和页面尚未完成。每个阶段开工前重读三份核心文档，检查 Git/数据库状态，另写具体操作计划并向用户详细解释，获确认后执行。合并本机 `main` 与远端推送另有独立计划。用户现无可用的旧模型/检索 API 凭证；有效密钥由用户在实际联调前按说明配置到 Git 忽略的本机 `.env`，不发送到聊天。

## 推荐的评估场景

1. “把明天下午的航班改签，并订一晚附近酒店”：给出两张独立卡；确认一张不能替另一张确认。
2. “下周去某可达城市，订最便宜的航班和取车租车”：候选来自数据库，价格来自确定性报价，旅客逐笔确认。
3. “取消我的航班/酒店/租车”：逐笔引用正确规则与模拟费用，拒绝与重复确认不重复变更。
4. “推荐我酒店附近的经典地点”：地点须在航班可达城市，结合已确认行程并标明来源；有可信坐标才显示近似直线距离。询问不可达城市时，说明范围并提供可达城市替代建议。
5. 反例：无班次、超出 30 天、过期价格、伪造政策、越权订单、网络中断、搜索结果提示注入、模型声称已订而未确认。
