# P3.1f2：条件取消与行程状态展示操作计划

> 制定日期：2026-10-22｜状态：用户已确认并在功能分支完成隔离验收；验收结果见《当前进度》。计划不授权数据库重建、主线合并或远端推送。

## 1. 用户已确认的体验规则

普通“我的行程／最近安排”、推荐、地点推断及当前任务上下文**不提已取消机票、酒店或租车**，连“另有若干笔已取消”的提示也不附加。用户明确问取消记录或历史订单时才单列历史；刚完成取消时仍需明确告知结果。数据库保留订单状态和审计。页面的“我的行程”可查看历史，但默认先展示有效行程，已取消卡片与已确认卡片须显著不同。

## 2. 实施前核对

1. 重读三份核心文档与 P3.1f1 验收结果，核对当前分支、工作区、正式服务和正式库状态；不接管用户的 8000 调试进程。
2. 在隔离库准备三类本人有效订单、三类已取消订单、过去已完成但仍为 `confirmed` 的订单、两笔同城／同机场订单及另一个账号的订单。记录卡片、订单和审计基线。
3. 对照现有 `/api/v1/me/itinerary`、`agent_reads`、推荐目的地和页面渲染，确定数据契约；保留完整订单只读 API（仍可返回本人全部状态的订单），在对话语义与页面展示层明确分类，不通过删除或隐藏数据库行解决展示问题。

## 3. 服务端操作

1. 将“当前有效行程”和“历史记录”设为两种明确查询语义。普通当前行程只返回仍有效且在进行中或未来的已确认机票／酒店／租车，不返回已取消订单、数量或引用。明确的“取消记录／历史订单”可按类型、时间查看历史；过去已完成但仍标记 `confirmed` 的订单显示为“已结束”，已取消订单显示为“已取消”，不能把两者都称作取消记录。对话中刚确认取消的反馈只说明本次目标和执行结果，不把历史订单混入下一次普通行程查询。
2. 推荐和地点推断只读取有效订单；已取消的伦敦机票不得让系统以为旅客仍将前往伦敦。自述所在地、拟预订目的地与已确认有效目的地分开。待确认取消卡尚未执行时，原订单仍为有效，但回复须标为“待确认取消”，不能提前说已取消。
3. 在本人订单只读筛选器中解析“汉堡机场出发的机票”“伦敦的酒店”“上海取车”等属性。只按数据库关联的航班机场、酒店城市和租车机场筛选 `confirmed` 订单；一笔命中可提出对应卡，多笔命中必须列出有区分力的日期／航班／酒店名称，不由模型猜选。未命中时说明实际可办理范围，不回退到旧候选或其他人的订单。
4. 对“除了去伦敦以外都取消”：先形成结构化保留集合与拟取消集合。目的地为伦敦的机票、伦敦酒店及伦敦取车订单属保留集合；其他已确认订单列入拟取消集合。若存在仅从伦敦出发、跨城酒店或其他关联难以判断的订单，先向旅客列明并问是否保留。逐笔校验取消规则、生成独立卡；遇到已过截止日期的订单须单独说明，不能因为一笔失败而把其余目标偷偷改掉。现有接口每轮最多准备 2 张动作卡；若符合条件的订单超过 2 笔，本轮至多生成 2 张，并清楚列出本轮卡片、尚未生成卡片的订单、已保留和不能取消的订单。剩余订单须由旅客下一轮明确要求继续办理，不自动取消或静默遗漏。每轮重新核对订单状态与版本，只处理旅客本人订单，确认一张卡只变更一笔。
5. 取消反馈与历史查询复核金额、当地截止时间、订单版本和状态；模型只负责理解筛选条件，不能把提案说成已取消，也不能自行决定退款额。

## 4. 行程页面操作

1. 将页面行程区域分为“有效行程”和“历史与已取消”。默认定位有效行程；历史可展开查看已取消及已结束的订单，不与即将出发项目交错排序。没有有效行程时明确显示“目前没有进行中或未来的已确认行程”，历史仍可展开。现有“操作记录”记录确认／拒绝等动作，不等于订单历史；两个区域须使用不同标题，不混用数据。
2. 已确认且有效：醒目的“即将出行／进行中”文字和实色状态徽标，突出时间地点。已取消：写明“已取消 · 不再出行”，使用中性色底、不同边框和图标，在历史区域显示，保留订单号供核查；**不能仅靠颜色**。已过期的已确认行程显示“已结束”，避免与待出发混淆。桌面和窄屏都维持清晰层次及足够对比度。
3. “待确认取消”只在动作卡区域呈现，不改变行程订单的已确认状态。动作卡的待确认、已确认、已拒绝、已过期分别有独立文字及样式；只有待确认卡出现确认／拒绝按钮。确认或拒绝后同时刷新动作、行程和操作记录，避免看到相互矛盾的状态。
4. 用现有 HTML、CSS、原生 JavaScript 风格完成，不引入额外大型前端框架。保留中文主信息、原代码次级核对、人民币样式及作品体验环境说明。

## 5. 验收矩阵

| 输入或操作 | 预期 |
| --- | --- |
| “我有什么行程／最近安排” | 只答有效本人订单；零条取消记录、取消计数或取消目的地。 |
| “我取消过什么酒店／查看历史订单” | 单独返回相应历史，并标明已取消、时间和订单标识。 |
| “取消汉堡机场出发的航班” | 唯一命中时给正确机票取消卡；多笔时列日期与班次供选择。 |
| “保留伦敦，取消其他安排” | 先列明保留与拟取消；每笔独立卡；伦敦相关订单保持原样；超过 2 笔时明确列出未生成卡片的剩余订单，下一轮须再次要求。 |
| 取消卡尚未确认／已拒绝／已确认 | 订单分别保持有效／保持有效／变已取消；页面和审计同步。 |
| 行程页桌面与窄屏 | 有效、已结束、已取消、待确认动作四类不会被误看成同一状态。 |
| 两账号、重复确认、过期和截止日 | 不读取或更改他人订单；不重复取消；服务端规则拒绝无效操作。 |
