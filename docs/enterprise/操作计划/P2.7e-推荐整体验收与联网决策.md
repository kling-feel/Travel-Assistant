# P2.7e：推荐整体验收与联网决策操作计划

> 编写日期：2026-10-20｜状态：用户已确认并在功能分支实施，人工目录模式整体验收通过；结果记于《当前进度》。本计划不包含本机 `main` 合并、GitHub 推送或默认开启实时联网。

## 目标与建议

P2.7d2 已在功能分支建立 95 座可达城市、190 个经逐页核查的地点，静态推荐和 25 组真实模型隔离对话通过。下一步建议做一次**整体发布前验收**：确认全部城市、过期与来源失效处理、行程关联、多轮对话、交易边界，并量化阿里云实时检索在已有目录之上的实际价值。若实时检索仍产生错地、无可读来源或不稳定结果，就保持默认关闭，以人工目录交付可靠的地点推荐；不为了“联网”字样牺牲结果质量。

## 操作步骤

1. **开工复核**：重读《产品需求》《软件架构》《当前进度》和本计划；核对功能分支、未提交修改、第二版目录、受控图路由、忽略文件及密钥配置。确认演示数据库、隔离数据库与 Docker 的当前状态，任何持久化测试只使用隔离库。
2. **离线全城验收**：从只读航线样本自动枚举 95 座可达城市，逐城检查 2 条地点、国家代码、中文／英文别名、来源域名和审查日期；测试旧版 60 条不变、11 座不可达城市不误入、错国家同名城市不串用、无匹配偏好或过期时降级。对已确认行程匹配、无行程、改问其他城市及多轮偏好切换做固定回归。
3. **实时搜索隔离评估**：维持正式开关关闭，只在隔离评估实例启用 `GlobalBasic`。按国内、亚洲其他地区、欧洲、美洲、非洲及大洋洲选取代表城市与风险主题；逐次预记账，最多 **60 次新增搜索**，人工复核返回页面是否可读、地点与城市／国家是否一致、与目录是否一致及是否带来新的可靠信息。搜索结果只作目录核对，不直接扩写地点事实或影响交易。遇到认证、限流、异常费用或来源污染即停该部分并记录。
4. **隔离对话评估**：最多 **15 次新增 DeepSeek 请求**，预算上限 **8 元**，覆盖跨城与同名城市、偏好切换、来源失效、无证据票价／距离／营业时间、虚构政策与真实航司政策分流、景点预订拒绝、航班／酒店／租车交易提案以及同请求重放与跨账号访问。逐轮检查引用城市、动作卡、订单写入、隐私与密钥边界；若出现错误，先固定复现和修复，再在剩余额度内定向复测。
5. **稳定性与部署前检查**：完整自动化测试、两个演示日期的全航线验证、编译和依赖检查、旅客路由与旧路由检查。涉及数据库持久化或会话路径的修改时，在独立 PostgreSQL 中复测重启恢复并清理临时记录；不动正式演示库。
6. **决策与收尾**：列出离线目录质量、联网命中率、误判率、失败回退、调用量及保守费用；明确建议默认开或关联网。只有全城地点准确、交易与隐私边界通过时，才建议 P2.7 整体通过。更新 README、来源记录和《当前进度》，仅提交功能分支。若仍有阻断项，保持 P2.7 未完成并提出定向修复。整体验收通过后，另写主线合并和 GitHub 同步操作计划供用户确认，再进入 P3 简单页面与部署。

## 费用与权限边界

`GlobalBasic` 的专属价格仍未显示，**60 次是请求上限，不是费用承诺**；最终金额以阿里云账单为准。DeepSeek 每次调用前预记独立忽略账本并用 token 用量保守估算，接近 8 元立即停止。公开提交不包含密钥、测试账本、旅客数据或开发工具品牌字样。此计划确认后只执行功能分支验收；本机 `main` 合并、GitHub 推送和默认联网开启均需分别得到后续明确确认。
