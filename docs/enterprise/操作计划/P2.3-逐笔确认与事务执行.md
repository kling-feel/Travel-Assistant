# P2.3：逐笔确认与事务执行操作计划

> 编写日期：2026-10-17｜性质：待用户确认的事前计划；实际结果只写《当前进度.md》

## 目标、起点与范围

在 G-03 合并本机 `main` 后，从干净主线建立 `<历史功能分支>`。让已登录旅客对**指定动作 ID**确认或拒绝：确认时在一个 PostgreSQL 事务中重新核对身份、会话、提案、订单、候选资源、模拟报价和规则，再执行一笔机票或酒店订单写入，同时保存结果与审计。覆盖航班改签、航班取消、酒店预订、酒店改期、酒店取消五种动作。

本步不接模型／LangGraph，也不制作页面；提案仍由 P2.2 内部服务创建。API 文档可用于验证已有动作的确认／拒绝，固定验收脚本会通过内部服务建立动作后再调用 API。旧 SQLite 写工具和通用文本 `y` 路由继续关闭。没有真实支付、退款、库存锁定或供应商调用，所有金额均为模拟核算。

## 对旅客的接口与状态约定

| 操作 | 建议接口 | 成功与重复请求 | 不应写订单的情况 |
| --- | --- | --- | --- |
| 确认 | `POST /api/v1/sessions/{session_id}/actions/{action_id}/confirm` | 首次确认返回动作 ID、执行结果及最新订单；对**同一已确认动作**重复确认返回同一持久化结果，不再次写订单 | 他人动作 404；拒绝、过期、已失效或内容变化 409 |
| 拒绝 | `POST /api/v1/sessions/{session_id}/actions/{action_id}/reject` | 首次拒绝保存状态；重复拒绝返回原状态，不写订单 | 他人动作 404；已确认或已过期动作 409 |
| 查看 | 复用 P2.2 动作详情、会话动作列表；增加本人操作历史读取 | 清楚显示待确认、已确认、已拒绝、已过期、已失效和模拟金额 | 不在响应中返回令牌、密钥或完整模型推理文本 |

请求体不接受旅客 ID、订单 ID、金额、规则或新航班等覆盖字段；这些只能来自已保存的提案。一个动作只对应一笔订单变更，两张动作卡须分别确认。若旅客修改要求，先拒绝旧动作，再由后续提案流程生成新动作。

## 事务与持久化设计

1. **v004 迁移**：增加 `action_results`（每个动作至多一条成功结果，保存订单 ID、执行后快照和模拟金额）及 `audit_events`（动作、旅客、会话、事件类型、结果摘要和时间）。为报价、订单版本或规则变化引起的终止增加 `invalidated` 状态，并迁移现有动作状态约束；保留 v003 已有数据，重复迁移安全。演示重置按外键顺序清理结果、审计和动作，不删除原始 SQLite 或 Docker 数据卷。
2. **提案审计**：后续创建动作时在同一事务写 `proposed` 审计；若升级前已有动作，v004 按动作 ID 幂等补齐必要的提议记录。审计只存必要标识和摘要，不存访问令牌或敏感请求全文。
3. **确认服务**：在事务中锁定动作行，按登录令牌确定旅客并核对会话与动作双重归属；检查会话仍可操作、动作 `pending` 且未过 15 分钟。已确认动作优先读取 `action_results` 返回原结果。另一个旅客即使猜中动作 ID 也不能读写。
4. **重算提案**：用 P2.2 的确定性校验重新读取本人订单版本与状态、候选航班／酒店可用性、报价金额与版本、演示规则内容与版本；和卡片保存的规范化参数、前后快照与费用逐项比较。任何变化将动作标为 `invalidated`、写审计、返回需要重新提案的冲突结果，不执行订单写入。过期动作标为 `expired` 并记录审计。
5. **一笔事务执行**：只有复核完全一致，才调用 P1 订单服务执行一个动作；把订单写入、动作 `confirmed`、`action_results` 和 `audit_events` 一起提交。航班改签还须把订单 `amount` 更新为已确认的新演示票价，按用户要求只核算新旧差额；航班取消保留原订单金额并展示 30% 模拟取消费与 70% 模拟应退。酒店预订只创建一次订单，取消只改状态、保留历史。
6. **并发和异常**：动作行锁、订单版本条件更新、结果唯一约束共同防止重复执行。数据库错误时回滚整笔事务，不出现“订单变了、动作仍待确认”或“审计成功但订单失败”；服务返回明确失败，保留可安全重试的状态。两个不同动作不能借一次确认同时执行。

## 验收门槛与失败处理

- 五种动作在本人明确确认后各完成一笔正确订单变更；每次结果可通过订单、动作结果和审计三处核对。
- 拒绝、过期、越权、报价／规则变化、订单版本冲突和数据库故障均不会产生未授权订单写入；重复确认不重复创建或修改订单。
- 机票改签只显示并保存新旧票价差额，取消按原票价计算 30% 模拟费用；结果始终标明无真实支付／退款。
- v004 与演示重置可重复运行，P0～P2.2 回归测试通过，PostgreSQL 并发与重启后结果读取通过，旧图交易路由仍关闭。

若迁移、并发或事务一致性检查失败，留在短期分支修复并重跑，不合并主线；不以重置数据库卷掩盖问题。若实际实现发现需改变状态语义、金额计算或事务边界，先更新本计划并重新向用户说明。
