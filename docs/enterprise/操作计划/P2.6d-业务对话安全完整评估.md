# P2.6d：业务、对话与安全完整评估操作计划

> 编写日期：2026-10-19｜状态：已执行，验收未通过；发现的对话问题转入待确认的 P2.6e 修复计划。取代未执行的 P2.6c2 小范围补测；执行结果统一写《当前进度.md》。

## 1. 目标与边界

在 `<历史功能分支>=e549fb7` 的基础上，对**已经实现**的旅客 API、DeepSeek 对话、虚构政策、航班／酒店／租车查询及九类待确认交易做一次接近真实使用方式的系统评估。目标是发现并复现业务错误、对话误解、幻觉、越权、敏感信息泄露和故障恢复缺陷，为后续修复提供可核对的证据。现有 P2.6c 有七类交易的真实模型成功证据，酒店取消、租车取消和真实多候选选择仍待验证；2026-10-16 的安全报告针对旧接口，须按当前注册路由重新核对。

本阶段测试当前能力，不把尚未实现的联网经典地点推荐、简单页面、真实供应商与支付算成已验收。测试发现的产品能力缺口列入下一阶段计划。测试数据仅为虚构旅客、虚构订单和人为编写的测试文本；不把真实旅客资料或实际 API 密钥放入模型提示词、报告与提交。

## 2. 费用与停机线

- 用户本轮已授权**新增 DeepSeek 实测最多 8 元人民币**；这不含 P2.6c 先前约 0.04 元的实际账单。费用是上限，不以花满为目标。最多 120 次新增真实请求，自动重试为 0，单次超时 25 秒；为防异常长输出，评估与正式模型适配均设置并验证 `max_tokens` 上限（初定 4096）。一次轮次可能只走确定性逻辑、不消耗模型调用，按实际请求计数。
- 每次保存提供方返回的输入缓存命中／未命中、输出及推理 token、耗时、响应状态和可解析性；不保存密钥、请求头或真实用户资料。费用账本按执行时 [DeepSeek 官方人民币价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)计算，同时用**全部输入按高峰未命中、输出按高峰价**做保守估算。每 10～15 次核对一次；预计费用达到 2 元、4 元时记录中途状态，无需再次请求批准即可继续到用户授权范围。保守估算达到 7.5 元、下一次请求可能越过 8 元、token 用量缺失、价格变化无法核实或达到 120 次时立即停机。账户实际扣费以 DeepSeek 控制台为准，API 用量估算不能替代账单硬限额。
- 不调用 GPT、联网检索或其他付费服务。当前 `.env` 已有 DeepSeek 密钥，只验证配置是否存在与域名匹配，不输出密钥。官方 API 文档表明 `max_tokens` 可限制单次生成量，JSON 模式可能返回空内容；这些均列入异常用例。[完成接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)、[JSON 输出说明](https://api-docs.deepseek.com/zh-cn/guides/json_mode/)。

## 3. 开工、安全隔离与可复现数据

1. 重读《产品需求》《软件架构》《当前进度》和本计划；核对当前分支、工作区、`main` 与远端引用。从当前功能分支创建 `<历史功能分支>`，计划文档单独提交。本机 `main`、远端和旧图不动。
2. 启动**独立的 PostgreSQL 评估容器及独立数据卷**，在不同本机端口从已验证备份恢复虚构演示数据；评估程序启动时断言数据库地址和 Docker 项目标识属于评估环境，拒绝连正式演示库。先只读核对 13 版迁移、机场/班次/产品与订单基线，再备份评估库。必要的日期整体平移只在评估库显式执行并记录基准日，不改变正式演示库或原 SQLite。
3. 构建带固定随机种子、场景 ID、预期结果和请求上限的评估器。实时报告与临时凭证保存在 Git 忽略的 `data/generated/`；只提交不含私密数据的测试代码和聚合结论。每批保留失败时的脱敏请求、模型结构化决策、服务端引用／卡片、正式库前后快照与判定原因；模型自述不作成功证据。测试中若出现清理失败，保留隔离评估现场供诊断，绝不重置正式库。

## 4. 测试矩阵与顺序

### A. 无付费调用：业务和接口确定性验收

- 列出当前实际注册路由；固定模型与数据库逐一验证九类交易从提案、旅客逐笔确认／拒绝到订单、模拟金额、规则版本、审计的全链路。覆盖未确认不写、重复确认、并发确认、旧版本／过期卡、产品不可用、报价变化、订单归属、双卡全有或全无、服务/数据库重启及网络重试。
- 覆盖全部 618 条航线的查询抽样与边界、同城多机场、多候选排序、无航班／无房／无车、相对日期、跨月/跨年、当地时区与夏令时、酒店取消截止日、租车取还车与计费、机票 30% 模拟取消费及补退差价。用服务端规则和数据库值作预期，不由模型生成金额。
- 安全核验按当前 FastAPI 路由进行：未登录、过期/伪造令牌、停用账号、跨账号会话／订单／动作／审计、伪造旅客 ID/金额/版本字段、意外请求字段、错误响应与日志泄露、Git 当前文件/历史中的凭证线索、CORS/Host/文档暴露、请求长度与并发资源限制。先确认旧管理和旧图路由是否注册，再判断旧安全报告中的发现是否仍可达；不把不可达旧代码误报为当前 API 漏洞。敏感值检查只输出命中位置与布尔结果，不打印内容。

真实模型的卡片在隔离评估库中可由测试旅客按 API **明确确认或拒绝**，以检查整条链路；确认动作由评估脚本按预期卡 ID 发起，模型不能代替旅客调用确认。不同场景使用独立旅客／会话或快照复位。对话测试同时检查答案是否误称已出票／已付款、是否把虚构政策说成真实航司政策、是否泄露其他账号订单或内部提示、是否把用户输入中的“忽略规则”当系统命令。包含无效 JSON、空响应、超时、429/服务中断的固定模型或故障注入；真实 API 不故意制造高并发或额度消耗。

## 5. 验收门槛、收尾与后续路线

- **阻断项为零**：未确认或跨账号写入、真实密钥/其他旅客资料泄露、错误金额、无来源事实冒充真实政策、测试库误连正式库。九类交易在固定模型全链路和真实模型基本表述下均有正确卡片；四段多轮旅程能完成预期操作；结构化输出异常时安全失败。对可评分的真实对话任务统计成功率，目标至少 90%，同时逐项披露样本量与失败项，不用平均值掩盖关键错误。
- 完成 58 项现有自动化测试及新增针对性测试、两日期样本、编译、`pip check`、路由检查和差异检查；核对正式演示库计数未变。隔离评估容器停止，数据卷和脱敏报告保留至用户审阅；`.env`、备份、评估状态均不进入 Git。仅提交功能分支，不合并本机 `main`、不推送远端。
- 测试结束后**根据真实缺陷**单独提出修复顺序和操作计划：先处理 P0/P1 并复测，再拟 G-14 本机合并；通过后沿已确认方向推进 P2.7 有来源的可达城市推荐，其后是简单页面和部署说明。每个实施阶段继续遵守“先打开三份核心文档、提交独立计划、向用户说明并获确认、实施结果写《当前进度》”的约定。若评估发现方向需要改变，先讨论并修订需求/架构，不直接扩张产品范围。

用户已确认本计划及本轮最多 8 元的真实 API 测试预算。最终完成 113 次真实请求，保守估算约 0.496 元，四段各六轮旅程已覆盖；发现政策分流、撤回待确认卡、候选短序号和口头确认问题，故不满足本计划验收门槛。细节见《当前进度.md》及 P2.6e 计划；本阶段结束，不继续消耗剩余额度。
