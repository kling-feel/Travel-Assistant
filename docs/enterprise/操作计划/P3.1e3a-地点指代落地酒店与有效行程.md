# P3.1e3a：地点指代、落地酒店与有效行程操作计划

> 编写日期：2026-10-21｜状态：用户已确认，功能分支已实施并验收；结果见《当前进度》。承接 P3.1e2b，处理 D07 的后续衔接、D11 和 D12；D13、D14 另列下一步。此文档不授权重置数据库、合并主线或推送 GitHub。

## 1. 依据与本步目标

开工前已重读《产品需求》《软件架构》《当前进度》及 P3.1e 缺陷清单，并核对 `feature/p31-traveler-ui` 的干净工作区和提交 `628aa6f`。目前旅客说“我在上海”或“伦敦落地后”时，对话任务未分别保存**本人自述所在地**与**航班目的地／到达机场**。“附近”可能被旧酒店、租车或推荐任务误读；酒店查询可继承候选航班机场，但还不能稳定说明落地日期和缺少的住宿夜数。“最近有什么行程”未命中当前有效行程分支，可能把已取消订单列在主回答。

本步目标是让助手基于**可追溯的本轮话语、当前任务及已核实的航班／订单**确定地点，或只问一个具体澄清问题。不能用设备定位、模型猜测或历史上已失效的地点。仍遵守逐笔确认：地点补全只能触发只读查询，不能替旅客自动预订酒店或景点。

## 2. 建议采用的产品规则

| 旅客表达 | 建议处理 | 边界 |
| --- | --- | --- |
| “我现在在上海，附近有什么酒店／景点” | 将上海记录为旅客**自述当前位置**；酒店查上海有效房型并追问入住／退房缺项；景点只介绍已核查的上海市内经典地点 | 不声称实时定位，也不把市内地点说成离旅客当前街道很近 |
| “我从上海到伦敦，找落地附近的酒店” | 以本轮选定的可售航班的**伦敦到达机场**为酒店搜索锚点；显示机场周边产品，说明机场和按坐标可核对的近似直线距离 | 航班只有多个候选时先问班次；缺住宿日期或夜数时只追问酒店部分 |
| “预订前面这班机票，顺便找落地酒店” | 若航班目标唯一且仍有效，先生成一张机票待确认卡；继续查询或追问酒店，提示航班当地到达日可作为入住日建议 | 不能自动确认航班，也不能把建议的酒店入住／退房日期直接用于酒店预订卡 |
| “我附近有什么景点”但最近对话同时有上海所在地与伦敦目的地 | 问“上海现在附近，还是伦敦落地后？”；旅客选择后只保留对应城市任务 | 不默选最近出现的城市，不把酒店城市当作当前人所在城市 |
| “最近／接下来有什么行程安排” | 先列未来或进行中的已确认机票、酒店、租车；已取消订单只在历史数量或另问历史时提及 | 没有有效安排时明确说明，不把过期或已取消订单称为将来行程 |

“附近酒店”可用现有机场／酒店坐标计算近似直线距离，并注明不是道路距离或通行时间；无坐标时只说“该机场所在城市的房型”。**经典地点目录目前只有城市归属和核查来源，没有可靠的旅客位置或景点坐标**，所以本步只能给城市级建议，不输出公里数、步行时间或“就在旁边”。用户若希望地点精确距离，需另立数据来源和核查计划。

## 3. 实施顺序

### A. 基线与状态设计

1. 用户确认后再次核对工作区、服务进程、正式演示库状态，并在隔离库复现“上海当前位置／伦敦落地／我附近”的歧义和“最近行程”错答；记录脱敏的意图、地点来源、候选与卡片状态。
2. 在会话检查点中区分 `current_city`（仅旅客明确自述）、`destination_city`／`arrival_airport`（已核实的当前航班任务）和酒店／租车独立查询条件。新明确声明覆盖旧自述；重启后仍可恢复，但不能把它称作实时定位。

### B. 地点解析与落地酒店

1. 在服务端识别“我在／目前在”“落地后／目的地”“附近酒店／景点”等关系，按本轮明确地点、当前已选航班、本人已确认且有效的行程逐级核对；多个合理锚点则定向追问。
2. 机票加酒店混合任务保留已实现的机票卡独立生成。对酒店先绑定经校验的到达机场与其**当地到达日期**；尚无明确住几晚／退房日时展示已知条件并追问，不偷用旧城市、旧日期或模型提供的推测值。
3. 查询酒店时按机场范围和实际产品坐标返回有据可查的近似直线距离；无可靠距离则只展示城市或机场相关性。查询结果带机场与日期上下文，后续“就这个酒店”仍按既有候选、日期、报价和逐笔确认规则复核。

### C. 推荐与有效行程

1. “我附近有什么景点”使用明确自述城市或旅客刚选择的目的地，沿用 95 城市人工核查目录及现有联网默认开关；只给城市级地点介绍和可核查来源，不创建游览订单。
2. 将“最近有什么行程安排”“接下来要出发吗”等自然问法归到有效行程查询；按当前真实时刻筛选未来／进行中已确认订单，已取消和已过期订单不混入主列表。单问“所有订单／历史订单”仍可显示历史状态。

### D. 回归与真实联调

1. 隔离库回放：上海自述位置后问附近酒店／景点；查询上海至伦敦多机场航班后问落地酒店；选定一班并要求机票预订加酒店查询；上海与伦敦均可能时一次澄清；换城市、新会话、另一账号和重启后的地点隔离。
2. 核对航班机场、当地到达日、酒店日期／距离来源、景点城市、订单状态和引用。多个航班、无坐标、无房、无目录来源、已取消航班、模型给错城市时不得生成误导性事实或错误卡；确认前订单不变。
3. 运行全套自动化测试、Python／页面语法、依赖与文档链接检查。少量真实 DeepSeek 在隔离库重放关键多轮，建议最多 12 次模型调用；阿里云搜索若参与，只用公开城市词并最多 6 次调用，记录成功／降级与用量，账单以供应商为准。不能把搜索摘要当作地点距离或交易依据。

## 4. 停止条件与交付边界

出现跨账号地点或订单泄露、错机场／错日期卡、未经确认订单写入、把已取消订单当有效行程，立即停止相应联调，定位并修复后重验。正式演示库只读核查，不重置、不使用真实账号生成或确认业务卡；不修改原 SQLite、航线样本、价格与政策规则。若发现需要新的持久化字段或迁移，先补充本计划并说明对现有会话的兼容方式。
