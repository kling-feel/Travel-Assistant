# P3.1g3：境外天气官方数据核验操作计划

> 制定日期：2026-10-23｜状态：用户随后撤回境外天气接入方向，本计划已作废，**不得按下文实施**。下文仅保留规划过程记录；当前优先级改为对话即时反馈与流式呈现。

## 1. 决策依据与目标

当前中国五座可达城市的天气路径使用阿里云 `GlobalBasic` 发现国家气象中心页面，再直接核对官方正文；境外城市返回“仅支持中国可达城市的天气核验”。`services/trip_discovery.py` 也只为中国目的地读取天气。P3.1g3 的目标是让已确认的境外城市、当地日期和有来源的预报在满足证据门槛时进入对话与组合推荐；资料不足时如实说明，不能由搜索摘要或模型补天气。

首选官方数据为世界气象组织的 [世界天气信息服务下载说明](https://worldweather.wmo.int/en/dataguide.html)所提供的逐城 JSON。该服务汇集成员国气象部门的城市预报，公开下载说明要求标明来源、准确再现数据；其[字段规范](https://worldweather.wmo.int/en/json/WWIS_json_schema_v2.json)包含城市 ID／名称／坐标、预报签发时间及其时区、逐日日期、天气和高低温。现有阿里云搜索只用于发现或核对候选城市来源，不直接提供最终预报值。天气内容仍须从预先审查并限定的官方主机和城市 ID 重新读取。

**已知风险**：来源是官方也可能不新鲜。2026-10-23 检索可见的[伦敦官方 JSON 样本](https://worldweather.wmo.int/en/json/32_en.json)签发时间为 2026-10-15，已无目标日预报；[新加坡](https://worldweather.wmo.int/en/json/234_en.json)和[纽约](https://worldweather.wmo.int/en/json/278_en.json)的可见样本较新。这些读取可能经过网页缓存，实施时须重新向官方端点核验，不能预设伦敦明天一定有天气。英国气象局公开网页的[网站条款](https://www.metoffice.gov.uk/policies/tandc)限制未经授权的自动抓取，因此本计划不把抓取其网页作为补救途径；若 WMO 对伦敦仍无有效数据，明确降级并在结果中报告。

## 2. 开工、来源核对与停止点

1. 重读《产品需求》《软件架构》《当前进度》、P3.1g 总计划、本计划及公开发布规则；确认功能分支与工作区。只读核对 8000 是否可达及版本，不重启用户服务。核对 `.env` 的配置项是否存在即可，不显示密钥值。
2. 用官方逐城清单和受审机场地理资料，对所有演示可达境外城市尝试建立**静态、可审计**的城市→国家→WMO 城市 ID 映射；仅唯一城市／国家匹配且坐标合理者纳入。重名、近郊站点或城市无法确认时不自动匹配，也不接收模型或旅客提供的任意 ID。记录可映射／不可映射数量、无有效预报的城市和核对日期。阿里云搜索可辅助人工发现候选，不代替这个映射。
3. 在改答复前先做小样本：伦敦（已见过期）、新加坡和纽约（不同 `issueDate` 时区），再抽查至少 3 座其他可达境外城市。直接检查官方 JSON 的城市、成员国、日期、签发时间、天气、高低温和来源说明。若来源结构变化、使用条件不允许或样本普遍无法复核，则停止天气接入，只提交来源评估和明确下一步选择，不把未验证预报上线。

## 3. 代码实施顺序

1. 在天气服务保留现有中国官方页面路径，增加独立的境外 WMO 适配器。只允许固定 HTTPS 官方主机、数字城市 ID 构成的路径；禁用跨站重定向，限制响应大小、超时和请求次数，不把任意搜索结果 URL 传入请求。请求只带公开城市／日期，不含账号、订单、对话、令牌或密钥。
2. 对每条境外预报逐项核验：静态映射的城市 ID、名称、国家／成员国与坐标一致；目标日按**目的地 IANA 时区**解析“明天／后天”，且只落在官方 `forecastDay`；`issueDate` 按其 `forecast.timeZone` 解释，不把目标日或检索时间冒充签发时间；签发时间不在未来且距查询不超过审查阈值（拟 36 小时）；天气词和摄氏温度完整且数值合理。任何缺失、错城、过期或时区歧义均不给数值答复。
3. 中文回答区分“某城市某日预报”和“签发于／获取于”，标明世界天气信息服务及供稿气象部门；结构化引用保留官方城市页、签发时间、获取时间、目的地当地日期。必要时翻译已知天气代码／词条，不能扩写成原始资料没有的雨量、体感、出行安全结论。预报是动态信息，提示可能更新。
4. 让普通天气问答、同会话自述所在地后的“明天天气”、以及可出行目的地组合推荐复用同一适配器与校验结果；组合推荐只有在该目的地当日预报核验通过时才讨论天气，否则只根据已核查地点和模拟航班给建议。天气只读，不影响机票、酒店、租车的交易判断、提案和确认。
5. 保留原有中国路径与现有阿里云默认开启行为。遇到搜索失败、WMO 超时、配额或证据不足时，答复说明原因与可查的城市／日期边界，不无限重试、不把另一城市或另一日期的预报代入。

## 4. 验收矩阵

| 场景 | 必须满足 |
| --- | --- |
| 境外城市与当地“明天” | 自述所在地仅限本人本会话；目标日按该城市 IANA 时区计算，跨 UTC 日期和夏令时不串日 |
| WMO 资料新鲜、字段完整 | 与静态城市 ID／国家匹配，目标日与签发时区核对，天气及摄氏高低温准确显示，引用与来源说明完整 |
| 伦敦资料过期、目标日缺失 | 明确无法核实，不给旧预报、不改用搜索摘要或模型猜测；记录实际覆盖缺口 |
| 同名异国、错城市、错国家、异常坐标 | 拒绝错误映射，必要时追问城市／国家；外部页面文字不能改变既有交易规则 |
| 签发时间缺失、未来或过期；温度异常 | 不给数值天气，说明无法核实；不把获取时间伪装为签发时间 |
| 中国天气原路径和组合推荐 | 中国现有官方核验回归通过；境外组合推荐只在证据通过时加入天气，失败时继续给有据的地点和模拟航班 |
| 隔离与故障 | 跨账号／跨会话不借用自述位置；搜索与官方来源超时、安全失败；天气调用不生成动作卡或订单 |

先用固定响应建立失败回归，再实施适配器；运行相关测试及完整测试、Python 编译、依赖与差异检查。实际联网联调在隔离环境执行，计划上限 **20 次阿里云搜索尝试、30 次官方 JSON 请求、0 次 DeepSeek 模型请求**；统计调用次数，阿里云单价未知时不推算确定费用。即使预算允许，错城、旧日期、假签发时间、无证据天气或未经确认写订单均阻断验收。只在页面文件确有修改时重复桌面和窄屏视觉验收。
