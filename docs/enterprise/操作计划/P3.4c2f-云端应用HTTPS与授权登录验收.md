# P3.4c2f 云端应用、HTTPS 与授权登录验收操作计划

> 2026-10-27 制定，旅客确认后已执行；结果见[独立验收记录](../P3.4c2f-云端应用与HTTPS验收记录.md)。承接已完成的 [P3.4c2e 云端数据库与账号初始化](P3.4c2e-云端数据库初始化与授权账号.md)。本步只做有明确收尾的首次公网联调；服务器外加密备份、全新卷恢复和完整九类业务验收另按 P3.4c3 规划。

## 目标和当前基线

- 香港主机 `travel-cloud` 项目目前只有健康的数据库容器；演示批次日期 2026-10-27，批次清单与 14 版迁移、虚构供给一致。`portfolio_owner`、`interviewer` 两个授权账号有效，`demo1`／`demo2` 已停用。初始化后备份已经验证格式与 SHA256，但仍与数据库同机。
- 用户指定的主站为 `https://adzyforever.com/app`，`www` 应跳转到根域。任何人可打开登录页，只有预置账号能读取本人数据；虚构供给、示例报价和模拟交易必须持续清楚展示。
- 实际主机可见内存约 1,613 MiB、无 swap。云端 Compose 给数据库 640 MiB、应用 768 MiB、代理 128 MiB 的上限；这些上限合计接近主机可用总量，所以要按“数据库 → 内部应用 → 公网代理”的顺序逐级测量，不能仅凭容器启动成功判断容量足够。

## 执行步骤与逐级放行条件

1. **复核现场与回退依据**：重读《产品需求》《软件架构》《当前进度》及本计划，核对当前功能分支、云端发布提交／镜像身份、DNS 解析、数据库项目标签与三卷挂载、批次日期和授权账号状态。检查初始化后备份仍存在、可列目录且哈希吻合；在打开公网前另作一份不覆盖旧文件的当前库备份。核对云端私有配置权限和字段，不打印密钥，也不运行会展开完整环境变量的配置命令。记录执行前的内存、磁盘、OOM、容器和监听端口；确认没有其他进程占用 80／443。只核对本机 `8000` 状态，不启动、停止或重置本机演示库。
2. **仅启动内部应用**：使用同一 `travel-cloud` 项目、两份正式 Compose 文件及原 `cloud.env`，先单独启动 `app`，保留 `proxy` 关闭；不能使用会同时启动代理的 `app-up` 入口完成此检查点。确认应用和数据库都没有宿主机发布端口，应用镜像仍对应已验收的发布代码，且启动守卫认可批次清单、两名授权账号和已停用的种子账号。通过容器内 HTTP 检查 `/health`、`/ready`、`/app` 与静态资源；对未授权请求、无效账号、有效账号的 `/me` 和本人行程分别核对返回。测试密码只从服务器私有文件读取并在进程标准输入中使用，不放在命令参数、日志、聊天或截图中。
3. **内部安全与容量门槛**：用两名授权账号做最小范围的会话／订单归属检查，验证跨账号读取被拒；停用账号不能登录，错误登录不会泄露账号是否存在，重复失败触发限流。只做只读查询和一张可放弃的模拟待确认卡，确认前订单数不变；该卡不做真实订单确认。检查应用及数据库健康、可用内存、磁盘、容器重启次数与 OOM，确认 2 GiB 主机在两容器并存时稳定。若启动失败、守卫拒绝、密钥误出日志、跨账号访问成功或资源不足，停止应用并保留数据库与备份，不进入公网步骤；先报告证据和修复／升级选择。
4. **核对公网前提**：从服务器侧和独立外部解析器检查根域及 `www` 都指向已购实例；核对阿里云轻量服务器防火墙及主机实际监听，只允许计划中的 SSH、HTTP 80、HTTPS 443 入站，不发布应用 8000、PostgreSQL 5432 或 Docker 管理接口。若阿里云控制台需要人工更改防火墙或 DNS，我会先给出具体界面步骤和需要的规则，用户操作后再复核；不猜测规则已经生效。[阿里云轻量服务器防火墙说明](https://help.aliyun.com/zh/simple-application-server/user-guide/manage-the-firewall-of-a-server)列出规则核对入口。[Caddy 官方文档](https://caddyserver.com/docs/automatic-https)说明公网证书及 HTTP 跳转依赖可用域名和外部 80／443；证书会在后台申请，因此容器健康并不等于证书已签发。
5. **启动代理并验收 HTTPS**：上述门槛通过后才启动 `proxy`，保持 Caddy 证书卷持久化。由外部网络核对根域受信证书的域名、有效期与证书链；核对 `http://` 自动跳至 `https://`，`https://www` 跳至根域，`/app`、静态资源与安全响应头正常。公网 `/docs`、`/redoc`、`/openapi.json`、`/health`、`/ready` 不应暴露内部信息；匿名请求不能读取本人行程、会话或卡片。检查外部 8000／5432 不可访问，代理日志不含密钥、账号密码或令牌。若证书申请失败，先查 DNS、80／443 和 Caddy 错误；停止公网代理或维持维护状态，不降低为明文 HTTP、不绕过证书校验、不反复重启触发签发重试。
6. **页面与真实服务小范围联调**：在可信 HTTPS 下核对桌面和窄屏中文布局、登录／退出、已取消订单的视觉区分、虚构供给说明、用户消息即时显示、等待计时和答复逐段输出。用两个授权账号核对会话隔离及刷新恢复。执行少量真实 DeepSeek 对话和阿里云 GlobalBasic 检索，覆盖行程、政策、航班候选和有来源的地点推荐；核对服务端证据、模型不直接确认订单、失败时不捏造实时信息。记录服务调用次数和用量类别，不设置金额自动停机线；实际费用以供应商账单为准。若模型标识、密钥、余额或搜索权限失效，清楚报告并停下对应测试，不把降级答复写作真实服务通过，也不请用户把密钥贴进聊天。完整九类交易和更长对话留给 P3.4c3。
7. **重启、收尾与记录**：备份与证书卷存在的前提下分别重启应用／代理，复核 HTTPS、授权登录、批次清单和会话读取；数据库重启前先确认有可验证备份，重启后做同样的只读检查。记录可用内存、OOM、容器状态、证书与端口证据，以及用户实际展示网络的加载体验。按照用户“展示前开启、平时关闭”的选择，验收结束后停止代理与应用，保留数据库、订单、备份和证书卷；是否连数据库一起停止，以之后的展示日操作指南为准，不执行删卷命令。将结果写入《当前进度》和独立验收记录；仅在功能分支提交公开代码／文档，主线合并和 GitHub 推送另给 G 系列方案确认。

## 验收标准与失败处理

- **本步通过**：应用启动守卫通过，2 GiB 主机无 OOM；登录页可由公网 HTTPS 打开，两个有效账号各自只能访问本人数据，种子账号和匿名者不能进入；根域证书受信、`www` 与 HTTP 跳转正确；公网内部路由及 8000／5432 不可访问；至少一条真实模型对话与一条真实搜索有明确成功证据，模拟订单仍遵循逐笔确认；重启后数据与证书仍可读取。
- **暂停公网**：任何账号越权、未确认写订单、敏感内容出现在公开页面或日志、证书不受信、端口意外开放、资源不足／OOM，均先关闭代理并保留证据与数据卷，修复后重新验收该门槛。模型／搜索自身失联时，只能把相应能力标为未通过，不能声称已完成真实联调。
- 本步只是可短时展示的上线联调。服务器内备份不能代替异地备份；P3.4c3 完成加密异地备份、全新卷恢复及完整业务验收前，不标记为可持续运行或灾难可恢复。不会自动修改演示批次日期、删除云端卷或影响本机 `8000→5436` 数据。

## 需要旅客配合的情形

现有服务器、域名、专用 SSH 密钥、私有授权账号文件及两项已获授权的服务密钥可用于开始；预计不需要新采购或重新发送密钥。如果 DNS／轻量服务器防火墙只能由账号持有人在控制台调整，或需要旅客从面试实际网络判断页面速度，我会给出明确操作步骤和需回传的非敏感结果。账号密码、私钥、API Key 和证书联系邮箱仍不在聊天中传递。
