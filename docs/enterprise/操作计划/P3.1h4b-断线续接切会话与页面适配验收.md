# P3.1h4b：断线续接、切换会话与页面适配验收操作计划

> 制定日期：2026-10-23｜状态：已按用户确认完成；结果见[独立验收记录](../验收记录/P3.1h4b-断线续接与页面适配验收记录.md)。此计划只授权在独立验收环境做恢复和页面检查、必要的定向修复及功能分支提交；不授权合并本机 `main` 或推送 GitHub。

## 1. 目标与本轮边界

P3.1h3 已走通真实模型的机票、酒店、租车待确认卡；P3.1h4a 已完成多笔条件取消的真实模型、逐张确认与放弃。P3.1h2 尚缺的发布证据是：**处理中的消息遇到连接中断、刷新或服务重启后如何恢复；快速切换会话时内容会不会串线；真实登录页面在桌面和窄屏是否仍能清楚、安全地操作。**

本轮以同一独立页面检查这些问题。已有交易规则、数据范围和视觉设计保持原目标；只修本轮实际复现的缺陷。境外天气、游览预订和正式库重建不进入本轮。

## 2. 开工前的检查与隔离

1. 重读《产品需求》《软件架构》《当前进度》、P3.1h3／h4a 验收记录和本计划；核对功能分支、工作区、8000 页面与正式 5433 数据库现状。只读核对正式环境，不停止用户进程。
2. 复用已保留的 `travel-p31h2` 独立数据卷。由旅客在能运行 Docker 的 PowerShell 启动独立 5435 容器；先核对 8014／5435 端口空闲、数据基准和 P3.1h4a 的订单前后结果。对隔离库新建本轮备份，再用新的一次性旅客与会话做可写测试；不重置或清理既有验收账号。
3. 独立 API 与页面仍用 8014，并明确绑定 5435。临时账号、备份、原始聊天、请求键、截图和调用流水只留在 Git 忽略目录。页面若无法由工作台自动查看，请旅客按后文项目在本机实际观察，不绕过访问限制。

## 3. 分层执行顺序

### A. 固定模型和接口恢复边界

- 构造一段处理中对话、一次已完成但响应丢失的对话，以及含待确认卡的已完成对话。分别模拟请求中断、页面刷新、相同请求键重试和 API 重启。核对同一请求键最终只有一条旅客消息、一条结果及原有动作卡；不同文本不能复用旧请求键；失败要有可恢复或明确失败状态，不能宣称订单成功。
- 保留一笔已确认订单和一张待确认卡，重启独立 API，再由旅客重启**仅** 5435 独立数据库。重新登录后核对会话列表、消息、图检查点、候选引用、卡片、订单与操作结果均一致；卡过期或报价变化时按现有规则拒绝，不靠旧页面状态放行。
- 同一账号建立会话 A／B：A 的回复尚未完成就切到 B，随后切回 A。A 的流式片段、引用、卡片与等待计时不得显示在 B；两个会话各自的请求键和任务条件保持独立。再用第二账号验证不能读取第一账号会话或卡。
- 为上述失败模式补必要的自动化测试。只针对可复现缺陷做定向修复和复测，确认前不产生订单写入，重复确认不重复执行。

### B. 真实页面与交互

- 用旅客登录后的实际 8014 页面完成桌面约 1280 像素、窄屏约 375 和 338 像素三种宽度的观察。重点看登录、会话列表、聊天输入、旅客消息立即出现、真实等待状态与经过时间、核验后逐段答复、来源／候选、待确认卡、有效行程与已取消历史；检查长中文机场名、金额、当地时刻、错误提示和按钮是否溢出、遮挡或难以点击。
- 在页面做一次处理中刷新、一次中途切换 A／B、一轮短暂断线后重连。观察旧答复不插入新会话，刷新后保留最终答复和卡片；失败时能识别失败并安全重试。网络或模型响应时长不可控时，以固定模型的延迟回合和可重复的故障注入为准，再用少量真实 DeepSeek 回合核对实际页面体验。
- 旅客用键盘依次聚焦输入框、发送按钮、会话、卡片“确认／放弃”和历史展开；开启系统“减少动画”时仍能读懂等待与最终状态。确认按钮应清楚标明目标、金额和规则；不在页面测试中误确认正式订单。

### C. 模型计量、回归与收尾

- 本轮主要测试连接与页面，不主动调用阿里云搜索。真实 DeepSeek 只用于必要的恢复后问答和页面体感复核，设置单独流水：最多 **10 次模型请求尝试**，保守估算到 **¥8** 即停；未知用量或超时保守计入。服务商实际费用仍以账单为准。
- 运行完整自动化、Python 编译、页面脚本语法、依赖、两日期演示样本和差异检查；记录每项通过、失败或未测及具体环境。页面由旅客观察的项目与自动化证据分别写清，不把静态截图等同于登录后交互验收。
- 更新《当前进度》与独立验收记录，检查公开文件不含密钥、临时账号、原始模型响应或用户要求排除的字样。关闭 8014，请旅客停止独立 5435 容器并保留数据卷；只在当前功能分支提交成果。正式 5433、用户 8000、本机 `main` 和 GitHub 均不改。

## 4. 通过标准与停止条件

通过需要：中断、刷新和服务／数据库重启后不重复消息、卡或订单；切会话与切账号不串内容；页面宽窄屏的关键内容可读可操作；待确认、已确认、已取消和失败状态明确；旅客实际页面观察与数据库一致。若连接故障导致不确定的写入状态、错误会话出现卡片、跨账号内容泄露或卡片可被错误确认，即停止发布判断，先记录并修复。独立库无法安全启动或真实页面无法核对时，相应项标为未测，不声称 P3.1 整体验收通过。

本步结束后才重写 G-16 发布计划，重新核对公开内容、远端分支和正式库状态；本机主线合并与 GitHub 同步仍须旅客**单独确认**。
