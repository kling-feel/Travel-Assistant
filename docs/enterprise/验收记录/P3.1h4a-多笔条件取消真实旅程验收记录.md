# P3.1h4a：多笔条件取消真实旅程验收记录

> 2026-10-23｜状态：固定模型、真实模型、自动回归与旅客页面逐张操作通过；独立环境已停止

## 隔离与基准

- 复用独立的 `travel-p31h2` PostgreSQL 项目（5435）和 8014 页面。开工基准为演示日期 2026-10-23、4 名旅客、3 笔机票订单、3 笔酒店订单、0 笔租车订单。正式 5433 数据库及用户的 8000 页面未用于本轮验收。
- 写入一次性验收订单前创建独立备份 `data/generated/p31h4a-before-test.dump`，大小 770,596 字节，文件头为 `PGDMP`；备份及一次性账号留在 Git 忽略目录。
- 在新建的隔离账号中构造伦敦需保留订单、汉堡出发机票、巴塞尔酒店与租车、同机场重复机票、跨城航班和过取消截止酒店。只对这些一次性账号执行测试动作。

## 发现与修复

- 初次真实模型联调中，批量取消仍绕经模型路由，一次模型超时使请求返回 503。批量取消现由受控服务端先从本人订单数据库确定范围，再生成待确认卡；这类明确指令无须模型响应。超时计入尝试次数，并保守预留估算费用。
- “保留伦敦”遇到跨城航班时，不猜测该订单去留、不生成任何取消卡；答复列出其余受影响订单及原本可取消项，告知旅客先澄清。名单过长时要求缩小范围。
- “只取消刚才那一笔”面对多张待确认取消卡时，明确要求指出订单或逐张操作，不擅自选择。明确问“查看取消历史”能读取历史记录，不误当新取消动作。
- 取消清单的租车取车时刻使用中文当地时间；汉堡出发机场在卡片中显示为“汉堡机场”。

## 验证证据

- 固定模型的独立 PostgreSQL 旅程覆盖唯一机场取消、多笔酒店取消、保留伦敦但最多两卡、剩余租车需再提、跨城歧义零卡、已过截止酒店零卡、相同请求键重放、跨账号确认拒绝、逐张确认与放弃、重复确认幂等、有效行程与取消历史。只有被确认的目标订单状态改变。
- 真实 DeepSeek 连续重放唯一机场、所有酒店、保留伦敦、同请求重放、模糊指代、同机场两单与跨城行程。修复后的联调均返回预期范围和卡片；在页面人工操作前，真实验收账号的订单均保持已确认，跨账号确认返回 404。
- 本轮计量流水累计 **5 次模型尝试：4 次成功、1 次超时**，成功响应输入 3,708／输出 1,290 tokens。按保守单价及超时预留 ¥0.5 估算累计 **¥0.517736**；阿里云搜索 **0 次**。实际计费以供应商账单为准，未触及 30 次或 ¥8 上限。
- 完整自动化 **227 项通过**；Python 编译、页面 JavaScript 语法、依赖检查、两日期航线样本和差异检查通过。两日期样本各含 115 座机场、33,121 班航班、618 条计划航线及 15,374 班可售航班。

## 页面与收尾

- 旅客在 8014 页面使用一次性账号查看“保留伦敦”会话，反馈两张取消卡、保留及未生成卡的说明均与预期一致；逐张**确认**汉堡出发机票 `h4a-live-flight-8152` 的取消，**放弃**巴塞尔酒店 `h4a-live-hotel-basel` 的取消。刷新后反馈页面有效行程和取消历史符合预期。工作台浏览器读取本机页面曾被自动审批拒绝，本轮没有绕过该限制。
