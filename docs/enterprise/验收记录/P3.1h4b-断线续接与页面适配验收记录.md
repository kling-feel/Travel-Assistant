## 恢复与隔离证据

- 独立 PostgreSQL 的固定模型验收覆盖：相同请求键重放只保留一组旅客／助手消息和原卡片；相同键改写文本返回冲突；处理租约过期后以原键安全重试；API 重启后恢复会话和卡片；跨账号读取会话或动作卡返回 404；重复确认不会重复执行订单动作。
- 页面延迟回合中，旅客完成会话 A→B→A 切换与处理中刷新。数据库只读核对：A 的两轮新问题各保存一次，B 没有写入 A 的消息或卡片。旅客确认 B 未出现 A 的内容；刷新后原有登录丢失问题已按下文修复并复验。
- 旅客提供的桌面截图中三栏可读、没有明显遮挡。旧取消卡显示“已过期”；服务端确认返回 409，对应机票仍为已确认。过期是 15 分钟有效期规则的正常结果，不能作为待确认卡可操作性的证据；已另建未过期卡供后续页面复核。
- 旅客确认切到 B 时没有 A 的内容，新卡在桌面和设备工具栏窄屏下的对象、当地时刻、金额及按钮可读。旅客还指出刷新后回到登录页；因此不能把先前的数据库恢复等同于页面刷新恢复。

## 发现与定向修复

- 切换会话时清除上一会话留下的全局处理提示，避免等待文字短暂出现在新会话。
- 截图中的“确认前订单是否会改变”得到模糊的业务引导。受控答复现直接说明：待确认卡只是提案；逐张确认且服务端核验通过才会修改模拟订单；放弃或过期不会改变订单。新增回归检查，且不会为这类解释问题生成动作卡。
- 页面原先只把登录令牌留在运行内存，刷新后丢失。现仅在当前浏览器标签页保存短期令牌与所选会话，重新加载时先请求 `/me` 验证，401 或主动退出即清除；不保存密码。旅客实际 F5 后保持登录并回到同一会话，消息和卡片各只出现一次。
- 旅客随后在固定延迟答复过程中按 F5，回到 A 后只见原提问与一条答复，B 无该内容。独立 API 核对 A 共 8 条消息、B 共 2 条，最近回合 `completed`，测试订单仍为已确认。
