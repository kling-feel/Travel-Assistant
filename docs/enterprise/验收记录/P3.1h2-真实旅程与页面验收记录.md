## 缺陷与初步定位

1. **跨业务候选污染（阻断）**：租车预订句中有明确的“车”，模型仍输出 `flight_book`；对话图保留的航班候选继续流入交易提案。现有服务端检查拦住了错误下单，却给了旅客错误的航班澄清。须让本轮明确业务类型约束模型建议，并只从同类、仍有效的候选选择。
2. **自然取还时刻丢失（高）**：首轮“10 点取车、18 点还车”没有完整承接，导致重复追问。须检查时刻提取、日期和时刻在不同轮次合并，以及当地时区复核；不能由模型自行补时刻。
3. **落地酒店条件重复追问（高）**：唯一待确认航班和“两晚”已有足够信息时，仍要求重选航班或确认退房日期。须从已核对的航班到达日推得入住日，并按用户明确晚数推退房日；真正冲突时再问。
4. **答复重复（低）**：酒店取消成功生成卡后，相同政策与“订单未改变”文字重复出现，影响清晰度；应在最终呈现层去重。

## 验收缺口与决定

- 本轮真实页面调用未形成逐请求 token、计费和搜索次数的可靠本地流水，无法独立证明精确费用或预定的 30 次模型／15 次搜索上限。已经停止新增真实模型调用；金额以供应商控制台账单为准。下次付费验收前须加本地计数及硬停机检查。
- 本轮没有逐项执行搜索故障注入、页面切会话断线矩阵、真实页面多笔条件取消以及宽屏复测，均标为未测，不能由自动化结果代替。
- **G-16 本机主线合并和 GitHub 同步暂缓。**先按单独修复计划解决跨业务路由与多轮条件，再用相同话术重新验收。正式 8000 页面运行的提交仍未核实，不以 8014 结果代表 8000。
