# P3.4b 云端准备隔离验收记录

> 2026-10-26；本机功能分支 `feature/p34b-cloud-readiness`。本记录不含账号、密码、API 密钥、数据库内容或支付资料。

## 验收范围

新建独立 Compose 项目 `travel-p34b-acceptance`，应用仅发布在 `127.0.0.1:8020`，数据库无宿主机公开端口，使用独立卷 `travel-p34b-acceptance_travel_pgdata`。本机正式入口 `8000→5436` 未切换；隔离环境的 DeepSeek 和阿里云搜索配置为不可调用真实服务的测试值，真实付费请求为零。

## 已观察到的结果

| 项目 | 证据和结果 |
| --- | --- |
| 构建与配置 | 云端镜像在 Linux 容器中构建，`pip check` 通过，以非 root 用户运行；镜像内没有 `.env`、生成凭证或原始 SQLite。Caddy 配置验证通过，固定的 Python、PostgreSQL、Caddy 基础镜像摘要记录在私有配置生成器内。 |
| 空库初始化 | 空库先备份，再运行 v001～v014 共 14 版迁移；导入 2026-10-26 虚构批次，含 115 个机场、33,121 条航班、15,374 条报价和 618 条可售航线。容器为 UTC 时也按北京时间核对批次日期。 |
| 账号与访问 | 先创建两个独立授权账号，再停用 `demo1`、`demo2`；匿名、停用账号及跨账号会话／卡片读取被拒绝。连续错误登录触发 429。云模式自动 API 文档关闭。 |
| 交易确认 | 通过实际 HTTP API 建立巴塞尔酒店新订待确认卡；确认前订单未写入，确认后只写入本人订单，重复确认返回相同结果。九类交易的业务规则另由完整自动化回归覆盖，不能把这一笔抽样当成九类真实云端联调。 |
| 用量与降级 | 管理员用量报表可运行，隔离环境显示真实模型／搜索调用数为 0；余额不足等降级路径通过自动化测试。正式服务商账单与真实错误响应需在公网阶段核对。 |
| 备份和恢复 | 含验收订单的 `pg_dump -Fc` 为 690,455 字节，SHA256 `8DE2EBCDDB44357257A1B964049728C6774543EE2A4D98EC281D510679C42A44`。全新 `travel-p34b-restore_travel_pgdata` 空卷恢复一次；日期、迁移、供给、订单、会话、动作、审计等 10 组摘要与原卷一致。 |
| 重启和收尾 | 分别重启应用和数据库后，授权登录、会话及本人已确认订单仍可读取。验收与恢复项目容器已停止，数据卷和 Git 忽略目录中的备份保留；原 8000 `/health` 为 200。 |
| 代码回归 | 完整 258 项自动化测试、Python 编译、页面脚本语法、凭证形态及公开字样检查通过；提交差异无空白错误。 |
