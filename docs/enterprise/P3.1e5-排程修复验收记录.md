# P3.1e5 航班排程修复验收记录

> 2026-10-22｜功能分支、独立 PostgreSQL 与本机页面；正式演示库未重建。本记录不表示真实航司时刻、价格或可售库存已核实。

## 根因与规则

只读检查源 SQLite 后确认，`SIM-3831` 上海至伦敦的源计划间隔仅约 2 小时 10 分，旧导入仅整体平移时间，导致错误到达日。旧样本中距离至少 5,000 公里的 10,594 条计划班次，有 10,049 条不足 5 小时。修复用机场坐标的大圆距离、5% 路程余量、每小时 820 公里和 35 分钟准备时间，向上取整到 5 分钟并限制在 45 分钟至 24 小时。规则 ID `fictional-flight-time-v1`。出发时间、航班 ID、可售窗口和报价不变；源实际到达相对计划到达的偏差保留。原始 SQLite 未修改。

## 隔离数据库结果

使用独立 Docker Compose 项目和端口 5434，先备份空库并以 `pg_restore -l` 核验，再将演示基准日设为 2026-10-22 重建。13 版迁移、115 个机场、33,121 条航班、15,374 条报价和 618 条可售航线通过。只读审计逐条比对全部航班和报价；10,594 条长途计划班次中不足 5 小时的数量降为 **0**。15,374 条可售航班中，落地日起查不到连续两晚机场周边酒店供给的数量为 **0**；最晚落地日在基准日后第 31 日。价格保留：上海至伦敦 `SIM-3831` ¥6,585；伦敦盖特威克机场周边房型示例每晚 ¥165 和 ¥210。

`SIM-3831` 在该隔离库的上海当地起飞为 **2026-10-27 01:18 +08:00**，伦敦当地到达为 **2026-10-27 05:43 +00:00**；实际 UTC 间隔约 **12 小时 25 分**。两晚酒店可查询 2026-10-27 入住、2026-10-29 退房，总额分别 ¥330 和 ¥420。窗口末端房型查询亦通过。新的房型生成规则为 `reachable-products-v2`，旧价格种子保留；至少一种房型的退房日扩至基准日后第 34 日，租车窗口不变。

## 连续旅程和页面

在独立真实 PostgreSQL 中用固定模型重放“查最早上海至伦敦航班 → 预订该班并找落地酒店 → 查两晚房型 → 生成酒店卡 → 拒绝酒店卡 → 查询租车并生成卡 → 重启数据库 → 确认租车卡”。机票确认只新增所选机票，酒店拒绝不新增订单；另一账号读取会话或动作返回 404，重复确认返回同一结果；重启后会话、订单和待确认卡可恢复。政策与有来源的地点建议也通过。页面以 338×640 窄屏和 1280×720 桌面分别核对卡片、时间与酒店日期；窄屏通过实际按钮拒绝酒店、确认机票，随后本人行程与结果一致。

本步对话路由、模型提示及联网资料规则未变，因此使用固定模型做确定性回放，没有新发起 DeepSeek 或阿里云付费请求。完整 **173 项**自动化测试通过；Python 编译、页面 JavaScript 语法、`pip check` 和差异空白检查通过。两项旧测试因固定样本日期与运行当天不一致而失败，已让测试中的对话和确认校验使用同一固定日期，目标复测和全量重跑通过；产品逻辑没有因此放宽。
