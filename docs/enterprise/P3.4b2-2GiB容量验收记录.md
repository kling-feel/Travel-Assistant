# P3.4b2：2 GiB 套餐本机容量验收记录

> 2026-10-26；执行目标为判断截图所示香港 2 vCPU／2 GiB／40 GiB、¥56／月套餐能否作为少量账号作品展示的候选。所有写入都发生在全新隔离数据卷；没有购买服务器、调用真实 DeepSeek／搜索、切换 8000 或操作正式数据库。

## 资源约束与证据边界

新建 `travel-p34b-2g` 项目，API 只映射 `127.0.0.1:8021`，本地测试代理只映射 `127.0.0.1:8022`，数据库无宿主机端口。API、数据库、代理分别限 **768／640／128 MiB**，合计 1,536 MiB，给假设的 2 GiB 主机操作系统及 Docker 预留约 512 MiB；CPU 分别限制为 1／0.75／0.1 核。初始化和账号管理在 API 启动前运行，恢复检验在源项目停止后运行。代理使用仅供本机的内部证书，不是正式域名证书。

限额实际写入 Docker 容器配置，并非仅在文档中估算。内存数字来自 120 次 `docker stats` 采样；Linux CLI 显示的内存使用量会扣除部分缓存，不能直接视为整台主机占用：[Docker 指标说明](https://docs.docker.com/reference/cli/docker/container/stats/)。Docker Desktop 运行在本机，未把其 Linux 虚拟机、宿主机内核、系统更新或真实香港网络纳入 2 GiB 总内存硬限制。结论仍须在实际 2 GiB 云主机验证。

## 实测结果

| 检查 | 结果 |
| --- | --- |
| 独立目标 | 项目及卷首次创建；项目标签、卷、无公开数据库端口和 640 MiB 数据库上限均已核对；迁移前 public 表数为 0。原 8000 健康检查为 `ok`。 |
| 初始化 | 先生成并验证空库备份，再在 768 MiB 初始化容器和 640 MiB 数据库中完成 14 版迁移、2026-10-26 虚构批次导入：115 机场、33,121 航班、15,374 报价、618 条可售航线；无 OOM。 |
| 授权与业务 | 创建两名独立授权账号并停用初始账号；航班、酒店、租车和行程只读查询有结果；跨账号读取被拒绝；酒店卡在确认前不写订单，确认后仅本人可见且重复确认幂等。 |
| 并发 | 延长抽样执行 **600 次只读 HTTP 请求**：单路 100 次中位 9.63 ms、最慢 12.56 ms；双路 200 次中位 12.66 ms、最慢 24.97 ms；三路 300 次中位 19.39 ms、最慢 83.71 ms。它们是本机数据库／API 延迟，**不含真实 DeepSeek 或联网搜索等待**。 |
| 内存 | 120 次采样；API＋数据库＋代理同时运行的总内存峰值 **208.97 MiB**、中位 **166.74 MiB**。各容器采样峰值为 API 137.10、数据库 60.04、代理 14.12 MiB；初始化容器单独采样峰值 118.70 MiB。三常驻容器的 OOM 标记均为 false，未见异常退出。一次性管理容器退出时，首版采样器遇到容器列表竞态；修正后补采，早期部分窗口没有完整样本，不能据此推断精确峰值。 |
| 重启 | 分别重启隔离 API 与数据库，授权登录、原会话和已确认酒店订单仍存在。 |
| 备份恢复 | 在应用运行时生成 690,562 字节 `pg_dump -Fc`，SHA256 `11844E6F7FB3A5CEEDE93DFC23EED0F78314EEC469CBD10F9C95D1B618725507`；目录可读。新项目 `travel-p34b-2g-restore` 的独立 640 MiB 数据库在恢复前表数为 0，恢复一次成功；使用 768 MiB 检查容器对照源／恢复的 **10 组完整摘要相等**，包括批次、迁移、供给、订单、会话、动作、审计与检查点。 |
| 从头构建 | 使用固定 Python 基础镜像、`requirements.lock`、`--no-cache --resource memory=1536m` 从头完成应用镜像构建；新镜像约 **423 MiB**，在 768 MiB 运行限额下 `pip check` 通过。构建容器有 1,536 MiB 限额，但 Docker 构建器和操作系统的额外内存不在此限额之内，不能据此保证在真实 2 GiB 主机原地构建成功。 |
| 费用与隔离 | 模型／搜索密钥为不可用的测试值，真实付费请求均为 0；测试账号、环境文件、备份、指标和报告保存在 Git 忽略目录。两个测试项目容器在收尾时停止，数据卷保留；原 8000 页面与现有库未改变。 |

## 结论与购前建议

**2 GiB 套餐可以作为单人或少量账号求职展示的优先候选，不能判定为“不支持部署”。** 实测核心业务、短时并发、重启、备份恢复及受限镜像构建都通过，容器资源离 1,536 MiB 预算尚有余量。选择截图中的 ¥56 套餐，可将基础月预算更多留给域名与异地备份；正常续费价、磁盘／流量条款仍需核对。

正式购买后先在该真实机器上完成 2 GiB 主机级复测：记录 `free`、交换空间、`docker stats`、OOM 日志、磁盘余量，跑一次真实模型对话及服务商搜索、一次供给导入、双账号使用、重启和备份恢复。若构建或任一关键操作因内存失败，优先考虑预构建镜像或升级到 4 GiB；若真实展示会有更多并发旅客，也选 4 GiB。上述复测通过后再开放面试访问。阿里云首月与正常续费账单仍须以账户购买页为准。
